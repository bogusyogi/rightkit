# Changelog

## 0.5.0

- **Platform defaults.** Windows: E40 on DirectML with graph pre-warm and an opt-in parity verdict cache (load about 2 s warm against 42-51 s cold). macOS: the Core ML fp16 package with per-length compute units and pre-warm. Both are chosen from the model directory; the details are in the bullets below.
- **Pre-warm (E40 and Core ML).** New `EmbedderConfig::with_prewarm(bool)` (public field `prewarm`, default `true`; **Breaking (0.x minor)** for struct literals). After admission every graph (E40) or function (Core ML) is built or loaded and has one dummy text run through it during `load`, and stays resident, so no query pays a graph build, compilation or shader build; `false` restores build-on-first-use. The time is in `LoadTimings::prewarm` (new `LoadTimings::prewarm_per_length`: per-function times, Core ML only). This supersedes the E40 bullets below that say graphs are released after admission. Ignored for CPU and Q4.
- **Core ML per-length compute units.** New public `CoreMlUnits`, `CoreMlComputeUnit` (`All`, `CpuAndNe`, `CpuAndGpu`, `CpuOnly`), `CoreMlUnitsParseError` and `NEURAL_ENGINE_MAX_TOKENS`. `CoreMlUnits::per_length_default()` is the default map, from the Mac matrix of RightKit issue #81: `cpu_and_ne` for the 32, 64 and 128 token functions (p50 about 2.3-3.0 ms) and `cpu_and_gpu` for 256 (about 5.1 ms) and 512 (about 9.8-18.7 ms). Each function loads on its own `MLModelConfiguration.computeUnits`; one `MLModel` per function and unit is kept resident. New `EmbedderConfig::with_coreml_units(impl Into<CoreMlUnits>)` (public field `coreml_units: Option<CoreMlUnits>`, **Breaking (0.x minor)** for struct literals) forces one unit for every length (`CoreMlComputeUnit::All` / `CpuAndNe` / `CpuAndGpu` / `CpuOnly`) or a custom map; `CoreMlUnits` parses `default`, a bare unit name, or `256=cpu_only,32=all` pairs over the default. New `Embedder::coreml_units()`. A map that is `cpu_only` everywhere is served as `"cpu"` with no probe, parity check or pre-warm. `Cpu` is unchanged. The first `cpu_and_gpu` call per length was measured at up to 51 s cold, which pre-warm moves into `load`. The compiled `.mlmodelc` (one per package-hash and OS key, in the caller's cache dir) is independent of the units, so changing the map never recompiles.
- Runtime budget: `Cargo.toml` now declares resources for `src/e40.rs` and `src/coreml.rs` (the `COMPILE` static is a data-free lock, with a `static_note`). `tests/runtime_budget_declaration.rs` pins the shape.
- **Load timings and parity verdict cache (E40).** New `Embedder::load_timings() -> Option<&LoadTimings>`: tokenizer load, token-table read, probe, every graph build (`SessionCreate`, per provider and length), the parity check (total, CPU reference, accelerator) and `total`. New opt-in `EmbedderConfig::with_parity_cache_dir(dir)` (public field `parity_cache_dir`, **Breaking (0.x minor)** for struct literals): the parity verdict is stored as one JSON file per model directory, keyed on the bundle files' names, sizes and mtimes, the ONNX Runtime library (path, size, mtime, sibling `DirectML.dll`, ORT build string) and the provider name (ORT exposes no cheap adapter identity; a stored verdict is trusted for 7 days because the driver is not in the key). A stored pass builds no CPU session; a stored failure still serves CPU; a missing, corrupt or non-matching file re-runs the check and rewrites it. No default location. New feature `bench-internals` (not default, not stable API): `Embedder::bench_query_tokens`, `bench_embed_query_split`. Written, unverified: not compiled or run.
- **E40 backend (Windows DirectML, CPU elsewhere).** A model directory holding `embed_tokens.f16.npy` and `model_32.onnx` (the layout of `scripts/embed-export/eg2-directml`) is loaded as the EmbeddingGemma 2 E40 bundle, chosen from the directory only. Five fixed-length fp16 graphs (32, 64, 128, 256, 512), batch 1; each text runs through the smallest graph that holds it, with the fp16 embedding row looked up on the host from the `.npy` table (unscaled) and an int64 mask; the graph returns the normalised 768-d vector (fp32 tail). Graphs are built on first use. Texts are truncated to 512 tokens. Sentinel scrubbing applies.
- Admission: `Auto` on Windows probes, then runs the existing vector parity check against the same graphs on the CPU provider. For E40 the check uses five prompts (about 20, 50, 90, 190 and 500+ tokens) so every graph is exercised; the graphs are released after admission and rebuilt on first use. `provider_used()` is `"directml"` or `"cpu"`; a graph that cannot be built on the requested provider is an error, never a silent CPU session. Explicit `DirectMl` fails with `AcceleratorParity` or a runtime error; `CoreMl` is refused for an E40 bundle.
- `Auto` not admitted: serves the E40 graphs on CPU, or, with the new `EmbedderConfig::with_fallback_model_dir(q4_dir)`, the Q4 bundle on CPU (its own `model_id()` and `pipeline_id()`, reason in `fallback_reason()`). **Breaking (0.x minor):** `EmbedderConfig` has a new public field `fallback_model_dir`.
- New `EMBEDDINGGEMMA2_E40_MODEL_ID` (`embeddinggemma2-e40-dml`) and `EMBEDDINGGEMMA2_COREML_MODEL_ID` (`embeddinggemma2-coreml`, now served by the Core ML backend below). `pipeline_id()` of an E40 bundle hashes the eight bundle files and uses its own model id, so it differs from the Q4 ids and consumers reindex.
- `rightkit-onnx` is now used with its `half` feature.
- **Core ML backend (macOS 15+).** A model directory holding `EmbeddingGemma2Text.mlpackage` and `embeddings.bf16` (the `embeddinggemma2-coreml` store entry: `FluidInference/embeddinggemma-2-coreml` at 3f978ddf) is loaded as the EmbeddingGemma 2 Core ML bundle, chosen from the directory only. ONNX Runtime cannot load an `.mlpackage`, so `src/coreml.rs` talks to Core ML directly through `objc2-core-ml` (macOS-only dependencies `objc2`, `objc2-core-ml`, `objc2-foundation`, same versions and features as `rightkit-asr`'s bridge, pulled by `inference` on macOS only). The package is a multi-function ML Program; functions `embed_32`, `embed_64`, `embed_128`, `embed_256`, `embed_512` (batch 1) are used (`embed_48` and `pack_256` are not). Each text runs through the smallest function that holds it (first 512 tokens kept). Inputs: `inputs_embeds` float16 `[1, L, 512]` (row of `embeddings.bf16`, bf16 widened by a 16-bit shift, times `embed_scale` = sqrt(512) from `config.json`, rounded to float16; pad rows scaled the same) and `attention_mask` float16 `[1, L]` (1 on tokens, 0 on right padding). Output `embedding` float32 `[1, 768]`, pooled, projected and L2-normalised in the graph. No ONNX Runtime is initialised for this bundle, so `EmbedderConfig::runtime_path` need not exist.
- Core ML compile and load: the package is compiled once with `MLModel.compileModelAtURL` into `<model_dir>/.coreml-compiled/embeddinggemma2-text-<key>.mlmodelc` (override: `EmbedderConfig::with_coreml_cache_dir`), where `<key>` hashes the three package files and the macOS version; an existing compile is reused and the install is atomic. Each function is loaded on first use with `MLModelConfiguration.functionName`; macOS older than 15 is refused with a clear `EmbedError::Runtime`. Core ML errors surface as `EmbedError::Runtime` with a `Core ML:` prefix. The first load compiles the Neural Engine program for all functions (the card says several minutes, once; Core ML caches it), so the first `Auto` load is slow.
- Core ML providers: `Auto` = all compute units (`provider_used()` `"coreml"`) after a probe and the existing vector parity check against the same package on `cpuOnly` (five prompts, every function exercised; functions are released after admission and loaded again on first use); explicit `CoreMl` is the same with no fallback (`AcceleratorParity` on a miss); `Cpu` = the package on `cpuOnly` (`"cpu"`); `DirectMl` is refused. With `EmbedderConfig::with_fallback_model_dir(q4_dir)`, `Auto` serves the Q4 bundle on CPU when the package cannot load (macOS older than 15, compile error), the probe fails or parity fails; without it a failed probe or parity check serves the package on `cpuOnly` and a load failure is an error. `pipeline_id()` hashes six files (the three package files, `embeddings.bf16`, `tokenizer.json`, `config.json`) with the Core ML model id. A Core ML bundle on a non-macOS host is refused with `InvalidConfig`.
- New: `EmbedderConfig::with_coreml_cache_dir` and public field `coreml_cache_dir` (**Breaking (0.x minor)** for struct literals, like `fallback_model_dir`).
- Tests: unit tests (no model, any platform) for the unit map, its override parsing and the budget declaration; unit tests (macOS) for bucket choice, bf16 widening and scaling, input padding, cache key, config checks and strided output reads. `tests/coreml_real_model_e2e.rs` (ignored by default; `RIGHTKIT_EMBED_GEMMA2_COREML_DIR`) checks admission, parity >= 0.995 against `cpuOnly` for every function length, ranking and explicit `CoreMl`.
- Written, unverified: nothing was compiled or run for this change; the per-length units, pre-warm and `LoadTimings` for Core ML were written on Windows and compile only on macOS. In particular the fp16 E40 graphs on the ONNX Runtime CPU provider (the parity reference) are unmeasured through this crate. The Core ML backend (objc2 calls, `setFunctionName`, compile and cache, parity of all compute units against `cpuOnly`) has never been built or run; the 12 Oct Mac measurement used Python coremltools, not this code.

## 0.4.0

- Republished on the renamed dependencies: `rightkit-onnx` (was `rightkit-ort`). The 0.3.2 on crates.io was packaged before the renames and still named the old crates.
- **Breaking (0.x minor):** `ExecutionProvider` converts from `rightkit_onnx::ExecutionProvider`.
- **An accelerator is used only if it reproduces the CPU provider's vectors at load.** DirectML
  (ONNX Runtime 1.24.4) returns wrong EmbeddingGemma 2 Q4 vectors (cosine to CPU 0.58-0.72) that are
  finite, non-zero and faster than CPU, which the probe and any speed check accept. Whenever the
  session was built on anything other than CPU, `Embedder::load` now builds a CPU session for the same
  model, embeds a short query, a medium document and a long document (each alone, then as one batch)
  through both, and requires cosine at least `ACCELERATOR_PARITY_MIN_COSINE` (0.995) on every pair at
  native dimension, with finite non-zero output. Under `Auto` a failed check falls back to CPU with
  `fallback_reason` like `directml -> cpu: vector parity failed: cosine 0.579 at ~20 tokens, floor
  0.995`. Under explicit `DirectMl` / `CoreMl` it fails the load with the new
  `EmbedError::AcceleratorParity { provider, lowest_cosine, floor, detail }`. The CPU session is
  dropped when the check passes; load costs one extra CPU session build and four ONNX calls per
  session. `Cpu` is unchanged. The check cannot be turned off and the probe is unchanged.
- New public items: `ACCELERATOR_PARITY_MIN_COSINE`, `AcceleratorParity`,
  `Embedder::accelerator_parity()`, `EmbedError::AcceleratorParity`. Adding an `EmbedError` variant
  breaks exhaustive matches on it. `pipeline_id()` is unchanged by this (providers are not inputs).
- Consequence: `Auto` on Windows currently resolves to CPU for EmbeddingGemma 2 Q4 on the hardware
  measured, and an explicit `DirectMl` errors. CoreML is unmeasured.
- Written, unverified: nothing was compiled or run for this change.

## 0.3.2

- Internal: model-digest and pipeline-fingerprint SHA-256 now go through `rightkit_fs::digest`
  (`digest` feature only); the direct `sha2` 0.10 dependency is gone. Fingerprints are unchanged.
- `VectorStore::open` / `in_memory` open the connection through `rightkit-db`'s bootstrap
  (`DbOptions::open_writer`, `open_in_memory`): WAL with verified fallback, 5 s busy timeout,
  owner-only database file. Bootstrap failures that are not SQLite errors surface as
  `VectorError::Sqlite` with `SQLITE_CANTOPEN` and the original message. `from_connection` is
  unchanged for callers that bring their own connection.
