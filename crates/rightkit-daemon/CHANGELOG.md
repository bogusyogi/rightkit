# Changelog

## Unreleased

- New `client` feature (off by default; no new dependencies): a blocking device client in `rightkit_daemon::client`. `Client::new(ClientConfig)` trusts only the root certificates the caller supplies (`root_pem` / `root_der`; no system roots, `Error::NoRoots` without one). `Client::enrol(code, key, label)` returns a `DeviceSession` that signs every request; `DeviceSession::send` (generic signed request), `update_job`, and the resumable upload calls `upload_init` / `upload_status` / `upload_chunk` / `upload_complete` / `upload_reader` / `upload_bytes` / `upload` (resume skips the chunks `upload.status` reports and re-acknowledges a committed upload). `DeviceKey` wraps an Ed25519 key built from caller-stored PKCS#8 bytes or a seed. Every daemon refusal is `Error::Refused(Refusal { status, code: ErrorCode, body })`; TLS failures are `Error::Tls`. One connection per request over std sockets and rustls, no runtime.
- Shared with the server so client and daemon cannot drift: `signing::sign_request` / `signing::verify_request` (the daemon's signature check now calls `verify_request`), `signing::chunk_digest`, `signing::object_hasher` / `object_digest` and `signing::parse_digest_key` (the upload routes now call them). Behaviour of the server is unchanged.
- New `testing` feature (implies `client`; adds optional `rcgen` and `tempfile`, both already dev-dependencies): `testing::TestCertificate::generate()` makes a self-signed `localhost`/`127.0.0.1` certificate at run time, and `testing::TestDaemon::start()` runs a daemon with `serve_blocking` on `127.0.0.1:0`, exposing `addr`, `root_pem`, a single-use all-scope `enrolment_code`, `daemon`, `stop_handle()`, and stop-on-drop. `tests/client.rs` runs it in CI through a self dev-dependency that enables `testing`.
- No version bump: the crate is `publish = false` and this extends the open Unreleased entry, as `serve_blocking` did.

- New `serve_blocking(daemon, std_listener, tls, ready, stop)` and `StopHandle`: a blocking entry point that owns a dedicated tokio runtime (2 workers, blocking pool capped at 32), so consumers need no tokio dependency. `ready` is a `std::sync::mpsc::Sender<SocketAddr>` signalled after `LISTENING`; `StopHandle::stop()` (clonable, any thread, no polling) triggers the same bounded drain as `serve`, then the runtime shuts down with a 5 s timeout. Calling from inside a tokio runtime, a runtime build failure or a panic returns `Err`. `serve` is unchanged (it now shares an internal `serve_with`). No Cargo.toml change.

- A device-authenticated request writes `state.json` at most once: `authenticate` marks the replay nonce dirty instead of writing it, and the request's own change (the job patch and its idempotency record, for `job.update`) is written with it before the answer. A submission drops from two writes (two fsync pairs) to one. The file format, metrics and events are unchanged. A failed write still answers 500; on the upload routes the handler now runs before that write, so its in-memory effect can precede the 500.

## 0.1.3

- New `Daemon::metrics()` returning `DaemonMetrics`: requests handled, `job.update` successes, `state.json` writes and their sizes, and device, job, idempotency, nonce and in-memory event counts. Counters only; request handling and persisted state are unchanged. `DaemonMetrics` is re-exported.
- New `benches/budget.rs` (`rightkit cargo bench -p rightkit-daemon --bench budget`) measures the runtime budget: 10,000 device-signed job submissions through the in-process host. Figures are in README "Runtime budget".

## 0.1.2

Contract changes (`contracts/daemon-api.v1.schema.json`, additive; the valid fixtures follow):

- Provider slug: `{provider}` in `/v1/oauth/{provider}/callback` and `/v1/webhooks/{provider}` must match `^[a-z0-9][a-z0-9-]{0,63}$` (`$defs/providerSlug`). Enforced at route dispatch: a non-matching provider is not a route and answers `404 not_found` before any handler or OAuth flow runs. Previously `Instagram` on a webhook answered 401 and on a callback reached the OAuth handler.
- Error enum now lists every code the daemon returns (adds `precondition_required` 428, `idempotency_key_reuse` 422, and `bad_request`, `method_not_allowed`, `body_too_large`, `internal`, `storage_error`, `already_enrolled`, `too_large`, `too_many_uploads`, `bad_chunk_size`, `bad_chunk_index`, `bad_chunk_length`, `chunk_too_large`, `chunk_digest_mismatch`, `chunk_conflict`, `already_complete`, `finalizing`, `hash_mismatch`, `incomplete`, `oauth_unavailable`, `duplicate_delivery`). The api-v1 fixture lists the two mutation codes.
- `job.update` responses are `[200, 400, 401, 403, 409, 422, 428]` (adds 400 bad body, 422 idempotency-key reuse, 428 missing `If-Match` or `Idempotency-Key`) in the route table, schema example and valid fixtures.
- Lifecycle events: new `job_updated`; `JOB_UPDATED` now maps to it instead of `job_queued`. `job_queued`, `job_published`, `job_outcome_unknown` and `token_refreshed` have no daemon state to emit from (no publish step, no refresh flow), so they stay in the vocabulary and are marked reserved in the schema (`x-reservedEvents`) rather than removed, which would break the existing fixture.
- `responses` on every route lists each status its handler returns for a contract outcome. Added: `device.enrol` 400; `upload.init` 400; `upload.chunk` 400, 403, 404; `upload.status` 403; `upload.complete` 403, 404, 409; `oauth.callback` 502 `oauth_unavailable`; `webhook.inbound` 429 `rate_limited`. Route-independent statuses (404 unknown path, 405, 413 body limit, 500 storage failure) are not listed; the `routes` description says so.
- `x-reservedErrors`: six codes stay in the enum but no route returns them (`upload_hash_mismatch`, `upload_out_of_range`, `webhook_signature_invalid`, `webhook_replay`, `oauth_state_invalid`, `scope_mismatch`). They are reserved rather than removed: removal is breaking for a v1 contract, and `scope_mismatch` is named by the planned P3 proof semantics. The daemon returns `hash_mismatch`, `bad_chunk_index`, `forbidden` and `unauthenticated` where those reserved names would apply.
- Internal events with no lifecycle name, by design: `STORAGE_ERROR`, `UPLOAD_REJECTED`, `WEBHOOK_ACCEPTED`, `OAUTH_COMPLETED` and `AUTH_REJECTED` outside the signed-webhook class. They are diagnostics in `events.jsonl`. A new emitted name must be mapped or classified in `INTERNAL_EVENTS`.
- Drift tests: the schema example routes, the valid fixture and the code route table agree route by route and status by status; the error enum equals the returned codes plus `x-reservedErrors` in both directions; every schema event is emitted or reserved; every emitted event is mapped or classified internal; `job.update` documents its statuses. The 0.1.2 entry above is the crate's only version bump in this change: the crate is `publish = false`, so it already carries 0.1.2 and this change extends that entry.

## 0.1.1

- Drop the unused `rustls-pki-types` dependency (the code reaches it through `rustls::pki_types`).
- Replace `url` with `form_urlencoded` (one query-string parse); behavior is unchanged.
- Keep `subtle` for `ct_eq`: the only `ring` equivalent, `ring::constant_time::verify_slices_are_equal`, is deprecated ("no promises regarding side channels").
- Depend on `rightkit-contracts` with `default-features = false`: the daemon uses only the typed structs, never `validate`, so `jsonschema` leaves its tree. The conformance tests re-enable `schema` through a dev-dependency.
