## 0.4.0 — unreleased

- Fixed (QA isolation, Windows): `Suite::per_user_default()` no longer follows `USERPROFILE`. It was `SHGetKnownFolderPath(FOLDERID_LocalAppData, NULL)`, which expands `%USERPROFILE%\AppData\Local` against the process environment, so a runner that sets `USERPROFILE` to a QA home (`rightkit-qa` 0.7.1) made `mode::default_protected_paths` protect `<QA home>\Documents` and `decide` refuse the QA root (`root-overlaps-user-data`). The root is now `<profile>\AppData\Local\Orthic Labs\shared` with `<profile>` from `GetUserProfileDirectoryW` on the process token (`OpenProcessToken`, `TOKEN_QUERY`). macOS and Linux were already immune (`getpwuid_r`).
- Fixed (fail closed): in a `test-mode` build on Windows, `default_protected_paths` returns no paths when the real root lies under a `USERPROFILE` or `LOCALAPPDATA` that differs from the account's own value, and `decide` now returns `Refusal::UserRootUnknown` whenever the protected list is empty (before, the real root alone was enough).
- Added: `suite::refuse_build_tool_real_data_for_mode(&suite, &mode)`. A suite inside the test root of a `Mode::Test` from `decide` passes the build-tool guard even when it is not under the temporary directory (macOS, where the QA home is under the user's home and `cargo test`/`cargo run` set `CARGO`/`CARGO_MANIFEST_DIR`). `Mode::Release`, or a suite outside the test root, gets the unchanged rule; there is no variable or flag. `refuse_build_tool_real_data` is unchanged.
- Tests: a Windows subprocess test runs with `USERPROFILE`/`LOCALAPPDATA` at a QA home (no in-process `set_var`) and proves the real root is unchanged, `decide` gives `Mode::Test` for the bound private home and real user folders still refuse; unit tests for the env-shaped check and the guard table.

- Recovery validates record/root identity, participant order & generation; mandatory approval audit also gates reconciliation success. Added refusal regressions for missing participants, copied records, record symlinks & failed reconciliation audit.
- Added (selected-subtree roots): `MigrationScope::{All, Roots}`, `MigrationStatus` & `AppRoot::migration_status(src)` read the persisted migration state and exact scope without taking a lock; malformed, unknown-version or invalid-scope metadata is an error, never evidence that a destination is untracked. `MigrateOptions::include_roots` and `RootCutover::tree_roots` select bounded roots (directory descendants included) for a tree move. The cutover record reads its selection back strictly: an invalid selection, a selected record without explicit scope, a legacy record carrying a scope, or a selection inconsistent with the phase or file move is refused. A failing or panicking root resolver is reported as a participant error.

The next release after 0.3.1 (0.3.1 ships first, from the candidate recorded below; nothing in the 0.3.1 section changes). Minor release (R5): `BuildError::Registration` (PK07-5, below) is a new variant of an exhaustive public enum, so exhaustive matches on `BuildError` need an arm. Everything else here is additive. ### PK07-3 / PK07-4 / PK07-5 / PK07-6: root cutover, approvals, service registration

Additive except one variant (below), which makes this a minor release (R5). Requires `rightkit-fs` 0.4.6 (feature `transaction`, PK01-6): the dependency now reads `version = "0.4.6"` with features `fs` and `transaction`, so this crate publishes after fs 0.4.6.

- Added (PK07-3): `RootCutover`, the composition of file moves and opaque lifecycle participants for moving an app's data root. `RootCutover::new(app_root, old_root).fs_move(..).participant(..)`, `run()`, `recover()`, `RootCutover::status(&app_root)`, `selected_root(&app_root, legacy)`, `retire_old_root(&app_root, RetireMode)`. Participants implement `CutoverParticipant` (`name`, `owned_paths`, and the hooks `prepare`, `quiesce`, `relocate`, `reopen`, `settle(Settlement::{Committed, Aborted})` & `recover_completed`, each defaulting to a no-op); the encrypted-database relocation of `rightkit-db` is wrapped by the app as one participant, so this crate has no db or credential dependency and db none on the daemon. File moves: `FsMove::Tree(MigrateOptions)` (the restart-safe `AppRoot::migrate_from_with`, minus the participants' owned paths and the cutover's own files) or `FsMove::Companions(paths)` (one `rightkit-fs` `FileTransaction` rooted at the new root, old files as candidates; an identical existing destination is accepted, a different one is `Collision`). The persisted selection is the record `.rightkit-root-cutover.json` (`CUTOVER_RECORD`, version 1, written atomically at every phase): `copying` and `aborted` select the old root, `switched` (the single decision, durable before any participant reopens) and `completed` the new one; a record that cannot be read, or is newer, is an error and never a guess. Before the switch a failure settles every prepared participant as aborted in reverse order and leaves the old root authoritative; the next run uses the next generation. After the switch there is no rollback in this version: while `switched`, `recover()` (run it at startup) reopens & completes (`CutoverError::ReopenPending`, `Undecided`). A participant panic is a failed hook. Both roots must still be the directories (by file identity) recorded at the start when the switch is written (`PathSubstituted`). One cutover per new root at a time (`Busy`, an OS lock). The old root is never modified; `retire_old_root` is a separate step that needs `completed` & durable settlement acknowledgement, re-checks the recorded identity of the old directory and then only renames it aside (`<name>.rk-retired-<id>`) or sends it to the trash.
- `CutoverParticipant::recover_completed(&CutoverContext) -> Result<(), ParticipantError>` retries selected-new cleanup after durable Completed, including fresh processes & partial prior settlement. It must be idempotent: already-clean state succeeds; unknown/mismatched retained authority fails. Completed recovery calls only this hook, never prepare/reopen or old-root resumption.
- `RootStatus::settlement_complete` records durable cleanup acknowledgement (missing legacy field means false); `needs_recovery()` remains true for Completed until acknowledgement. Committed settlement or acknowledgement-write failure returns `CutoverError::SettlementPending { generation, failures }`, preserves selected new root & retries cleanup. Successful `CutoverReport::settle_warnings` remains empty; committed cleanup failures no longer return successful reports with warnings. `retire_old_root` refuses until Completed settlement is durably acknowledged, then revalidates recorded old-root identity.
- Added: `MigrateOptions::exclude(path)`: leave an entry and everything below it (whole components) out of a tree migration, for state a participant moves by its own means. Not an omission and not a reason for `ReadyWithOmissions`.
- Added (PK07-4): module `approval`. `ApprovalCoordinator::{new, with_audit, with_clock, request, decide, cancel, revoke_account, sweep_expired, claim, settle, recover_claims, get, audit_failures}` over an `ApprovalStore` (atomic compare-and-set on `revision`, nonce ledger; `MemoryApprovalStore` is the reference), an app-supplied `ApprovalVerifier` (receives the stored request, the decision and the opaque proof; returns a `VerifiedPrincipal` with account scope and an optional nonce), an optional `AuditSink` and `EffectReconciler`. State machine `Pending -> Approved -> Claimed -> Settled` with `Denied`, `Revoked`, `Cancelled`, `Expired`. A decision binds to the request's revision; a nonce is accepted once across all requests; the principal's accounts must cover the request's account and, when named, the principal must be an approver; expiry is checked on every touch; `claim` is the single compare-and-set that hands out the non-`Clone` `ClaimToken` (concurrent claimants: exactly one wins); `AuditRequirement::BeforeEffect` makes every request/state transition row durable before insert or compare-and-set (a failed append leaves prior approval state unchanged; rows describe attempts, including later store conflicts); an unsettled claim is resolved by `recover_claims` as `EffectOutcome::OutcomeUnknown` unless the action is `reconcilable` and the app's reconciler answers. Per-action policy is data (`ApprovalProfile`, `ActionProfile`, serde-able): lifetimes, required account or client, audit requirement, reconcilable. `redact_detail` withholds any free text outside `[A-Za-z0-9_=. -]`. The wire (Pulse's `pulse.approval.v1` P-256 lines, Mail's account-scoped decisions) stays with the app's verifier: the coordinator never re-encodes signed bytes, actual Pulse signing-vector compatibility requires profile integration evidence.
- Added (PK07-5): `Registration`, `ServiceIdentity`, `MethodDescriptor`, `TransportProfile::{Local, LocalAndRemote}` and `ServiceBuilder::register(suite, registration, HostOptions)`: an app declares its identity, its method descriptors and one closure per method; RightKit owns the endpoint, peer authentication, admission, lifecycle and shutdown. Refused at registration: `ping`, a duplicate or malformed id, a method that remote devices could reach under the `Local` profile, an empty registration; `start` refuses a remote daemon for a `Local` registration. Adds no listener (a test reads the source for socket and server names).
- Changed: `BuildError` gains the variant `Registration(RegistrationError)` (an exhaustive match on `BuildError` needs an arm, which is why this is a minor release).
- Tests (PK07-6): `tests/root_cutover.rs` (hook order, abort and reverse settle, rerun with the next generation, panicking participant, failed reopen then `recover`, a cutover that never switched is left alone, old root replaced before the switch, companions and collision, owned paths left out of the tree, concurrent cutover is `Busy`, unreadable or newer record fails closed, retire needs `completed` and the recorded identity, nested or missing roots refused, `exclude`), `tests/approval.rs` (replay across actions, accounts and revisions, nonce replay, scope and approvers, expiry, revoke, account removal, cancel, concurrent double claim, failed claim and outcome audit rows, no sink for a `BeforeEffect` action, uncertain effect, crash recovery, reconciliation, validation, profile as data), `tests/registration.rs`. The migration cases of PK07-6 (linked empty directory, required and optional link creation denied, interrupted marker, old reader on an incomplete candidate, collision, path substitution) are the PK07-1 tests in `src/app_root.rs`, unchanged; `tests/root_cutover.rs` adds the cutover-level substitution and collision cases.

- Hardened: `BeforeEffect` audits every request/state mutation before insert/CAS; failed appends preserve prior approval state, while successful appends describe attempted transitions even if later CAS fails. Cutover revalidates current old-root content despite cached migration readiness, refuses stale destination extras & fails closed on ambiguous case aliases.

## 0.3.1 — 2026-10-20

- Fixed (PK07 migration): copied files use exclusive, owner-only staging & strict no-replace publication from `rightkit-fs` 0.4.6, preserving native user filenames even when they resemble generated temporary names; equal contenders remain idempotent & differing contenders report collisions. Metadata uses exclusive staging & refuses nonregular destination leaves. Legacy temporary links cannot truncate source files. Added source regressions for linked temporary names, competing destinations, native temp-shaped filenames & metadata symlinks.

- Added (additive, no breaking change; stays a patch release): opt-in link-preserving app-root migration (CodeRight O-1). `AppRoot::migrate_from_with(src, MigrateOptions)` returns the new `#[non_exhaustive]` `MigrationReport`; `MigrateOptions` is `#[non_exhaustive]` with builders `strict()` (the default), `preserve_links(bool)`, `skip_ephemeral_specials(bool)` and `optional_links(predicate)`. `AppRoot::migrate_from` is unchanged and strict: it still returns `MigrationOutcome` and any symlink or special file still returns `UnsupportedSource`. `MigrationOutcome` and `AppRootError` are unchanged (no new variant and no new field on an existing variant). Lock, restart, collision handling and the marker-last ordering are the same in every mode, and the old tree is never modified.
  - Links: a symlink is copied as a link entry and never traversed. A relative link that stays inside the migrated tree keeps its text. A relative link that leaves the tree (including one that leaves and re-enters it) becomes an absolute link to its original target, resolved lexically against the link's old location. An absolute link is copied verbatim; a dangling link stays a link. Verification compares `read_link` text (never follows), validates parent directories without following leaf links, and on Windows keeps the file or directory link kind.
  - A link the destination cannot create (Windows without the symlink privilege or Developer Mode) returns the existing `AppRootError::Io`, wrapping the new `#[non_exhaustive]` struct `LinkNotCreated { link, target, resolved, reason }`, before the completion marker is written. `AppRootError::link_not_created()` is the typed accessor and `AppRootError::is_retryable()` (true for it and for `WriterBusy`) is new. No completed marker exists while a required link is absent, the old tree stays intact, and a later call resumes. The caller's usable-root decision stays with the caller; the shared migration never activates an incomplete destination. A caller can name optional links with `optional_links`; an optional link that cannot be created is omitted and reported separately (`omitted_optional_links`), and the state is `ReadyWithOmissions` (see "Completion states" below).
  - Ephemeral specials: with `skip_ephemeral_specials(true)` sockets and FIFOs (Unix) are skipped without being opened and reported. Device nodes and other specials are still refused. No special file is ever created.
  - Report: `MigrationReport` has accessors `outcome()`, `into_outcome()`, `migrated_links()`, `skipped_specials()`, `omitted_optional_links()` and `complete()`. New exported types: `MigrateOptions`, `MigrationReport`, `MigratedLink`, `SkippedSpecial`, `SpecialKind`, `OmittedLink`, `LinkNotCreated`.
  - Marker: a strict migration writes the unchanged `{source, files, bytes}`. An opt-in migration adds `links`, `skipped_specials`, `omitted_optional_links` and `complete` (always true when it is written; see below). Readers only look at `source`, so old and new markers are read by both versions.
- Fixed in the 0.3.1 candidate (PK07-1; K07 "Root migration"). Public API stays additive; no published 0.3.0 signature, type or variant changed.
  - Empty directories are migrated, in every mode including strict (directories are now entries of their own, created private and verified). Before, a directory with no files was dropped, so a link to an empty directory dangled. `files` and `bytes` still count files only. A file where the source has a directory (or a link or junction at that path) is a `Collision`, and nothing is replaced.
  - Completion states. New `MigrationState { Ready, ReadyWithOmissions, Incomplete }` (`#[non_exhaustive]`; `as_str()`, `is_usable()`) in a versioned state file `.rightkit-migration-state.json` (`MIGRATION_STATE`, `"version": 2`; the unversioned marker is version 1). Fields: `version`, `state`, `source`, `files`, `bytes`, `links`, `skipped_specials`, `omitted_optional_links`, `skipped_reparse_points`, `unresolved` (omitted links and skipped reparse points with reasons) and, for an `Incomplete` run that stopped on an error, `error`.
    - `Incomplete` is written before the destination is first touched and stays on disk after any interruption (a crash included) or failure, for example a required link the destination cannot create. The old root stays the authority. A rerun verifies and finishes the whole copy.
    - `ReadyWithOmissions`: every required entry is in place; only entries the caller declared disposable are missing (optional links that could not be created, reparse points skipped on request), each recorded. The destination is usable (`is_usable()`).
    - `Ready`: everything migrated.
    - The historical marker `.rightkit-migrated.json` is written only for `Ready`, after the state file, in the unchanged shape (strict: `{source, files, bytes}`), so a reader of an earlier version never takes an incomplete or partial destination for a finished move. 0.3.1 candidates wrote the marker also for omitted optional links (`"complete": false`); that no longer happens. A marker that carries `"complete": false`, or none of the new files, is still read: a plain marker counts as `Ready`. A state file of a newer version, or with an unknown state, is refused (`AppRootError::Io`, `InvalidData`) instead of guessed at; an unparsable or unversioned one is ignored as before.
    - Reruns no longer return early on a source match when the state is not `Ready`. `Incomplete`: the full copy is repeated (existing files are compared, never overwritten). `ReadyWithOmissions`: only the omitted links are retried, so files the app changed on the destination meanwhile never turn the retry into a `Collision`; a link that still cannot be created, or whose destination path is now occupied, stays omitted; when nothing is left unresolved the state becomes `Ready` and the marker is written. A `Ready` state whose marker is missing (a crash between the two writes) is repaired by the next call.
    - New: `AppRoot::migration_state(src) -> Result<Option<MigrationState>, AppRootError>` (read-only, no lock), `MigrationReport::state()` and `MigrationReport::skipped_reparse_points()`. `MigrationReport::complete()` is now `state() == Ready`. The marker and state names are not entries at the root of the source (an earlier migration's own files are never copied over this root's).
  - Windows reparse points (explicit policy). Junctions (mount points) were reported by std as directory symlinks, so an opt-in migration recreated them as symlinks (needing the symlink privilege, and changing what they are); an `AF_UNIX` socket file (a reparse point std calls a file) failed on open. Now each entry with `FILE_ATTRIBUTE_REPARSE_POINT` is classified by its reparse tag (read with `FindFirstFileW`, which describes the entry itself): a symlink tag is a link as before; `AF_UNIX` is a socket (skipped with `skip_ephemeral_specials(true)`, else refused); a junction or any other tag is never followed, opened, copied, recreated or recursed into. Default and strict: `UnsupportedSource`, before anything is written. New `MigrateOptions::skip_reparse_points(bool)` (accessor `reparse_points()`): the entry is skipped and reported (`SkippedReparsePoint { path, kind: ReparseKind::{Junction, Other}, tag, reason }`, also in the state file) and the state is `ReadyWithOmissions`, never `Ready`. No effect on other platforms. New exported types and constant: `MigrationState`, `ReparseKind`, `SkippedReparsePoint`, `MIGRATION_STATE`.
  - Tests (in `src/app_root.rs`): linked empty directory, empty directories in every mode, directory collision, interrupted and failed runs (`Incomplete`, then rerun to `Ready`), old reader on an incomplete candidate (the old-shape marker is absent), retry of omitted links, occupied destination during retry, newer or unreadable state file, socket entry (Unix), junction not followed (Windows, `mklink /J`), reparse tag classification (Windows).
- Added (PK07-2): `ERROR_RATE_LIMITED` is exported from the crate root with the other `ERROR_*` codes (it was defined in the private `error` module and not re-exported, so callers could only match the string literal). The runtime budget (README "not measured") was not measured here.
- Known limits: the reparse policy is attribute and tag based and was written without a Windows build here; a cloud-placeholder or deduplicated file counts as "other" and is refused or skipped, never copied. `ReadyWithOmissions` never returns to `Ready` while a reparse point is skipped (skipping is permanent by policy). Written without compiling or running Cargo; the integrator builds and runs the tests on Windows and macOS and runs `cargo fmt`.

### PK06-4 / PK06-5 / PK06-6: client lifecycle and loopback host (staged in the 0.3.1 tree, not yet released)

Additive: no published 0.3.0 signature, type, variant or feature changed, and the version is unchanged (a minor bump belongs to the PK06 publication group, which the integrator decides). The integrator builds and runs the tests on Windows and macOS and runs the formatter.

- Added (PK06-4, K06): module `lifecycle`, the daemon client lifecycle with typed provenance. `Provenance::{Owned, Attached}`; `DaemonLifecycle::{attach_or_launch, attach_or_launch_local, acquire_session, release_session, shutdown_owned, reset_restart_budget, provenance, host, epoch, session_count}`; `Session::{call, provenance, host, epoch, label, is_valid}`; `HostGeneration` (endpoint, pid, process start time, publication time, taken from `service.json`); `GenerationFence`/`Ticket`/`Stale` (a reply from an earlier host generation cannot complete a request made under a later one); `LifecycleConfig` (startup timeout, poll interval, stop grace, restart policy, graceful stop request); `Launcher`; `HostBackend`/`HostLink`/`SpawnPermit` and `LocalBackend` (the `service.json` transport; the trait lets another transport, or a test, supply discovery and connection); `LifecycleError`, `ReleaseReport`, `ShutdownReport`; codes `stale_generation`, `not_owned`, `restart_exhausted`, `session_released`, `launch_failed`. Crate-root re-exports: `DaemonLifecycle`, `LifecycleError`, `Provenance` and the four codes `stale_generation`, `not_owned`, `restart_exhausted`, `session_released`.
  - Attaching never implies the right to kill. A host is `Owned` only when this lifecycle launched it, recorded the launched process's `AdoptedIdentity` (pid plus start time) and saw that same pid publish itself. `shutdown_owned` refuses an attached or absent host (`not_owned`, nothing sent, nothing signalled, the lifecycle unchanged), sends the app's graceful request only to a host still confirmed to be the launched generation, waits the grace, and kills the launched process tree only while the recorded identity still names the launched process. `release_session` closes that client's connection and never signals the host. Dropping a lifecycle that owns a host drops its `OwnedChild`, which ends the launched tree; dropping an attached one ends nothing.
  - Identity and generation are revalidated before each use: `acquire_session` (record, process birth time, the connection's own OS peer check through `Client::connect_expecting`, the kernel pid equal to the record's pid, the record read in the handshake equal to the discovered generation) and `Session::call` (before the request is written and again before the reply is returned; an owned child that exited but is not reaped yet is detected through its handle, because a Unix pid probe still sees a zombie). A host that fails the executable check is never attached (`LifecycleError::HostIdentity`, nothing sent).
  - Replacement: a host that exited is relaunched only by a lifecycle that was given a `Launcher`, under the cross-process spawn claim (`SpawnClaim`; the loser of two shells starting together waits for the winner's host and attaches), within the `RestartPolicy` budget (the tracker the private-child supervisor uses; failed launches are charged to it as the supervisor charges them); a spent budget is `restart_exhausted` until `reset_restart_budget`. The replacement is owned and its process identity is recorded as the first one's was. A host replaced by someone else is attached after the identity check, whatever the lifecycle held before.
  - A reply after a generation change is `stale_generation` and the request is not replayed (it may have run on the old host); a generation that cannot be confirmed (unreadable record) is the same refusal (`LifecycleError::Unconfirmed`).
  - `supervisor::supervise_adopted` is unchanged and stays the way to run a private child; the lifecycle is for resident services published through `service.json`.
- Added (PK06-5, K06, ruling D5): feature `remote-loopback` (an empty feature list: std only) and module `loopback`, a loopback-only HTTP host with a bearer token, CodeRight's current wire. It is not the `remote` host and does not enable or require it (`tests/loopback_features.rs` pins the split: the feature is `[]`, no other feature lists it, the module is gated by it alone, the sources name no tokio, axum, hyper, rustls, `remote` or `link`). `releaseSwitches.remoteHost` stays false for desktop apps. The release scanner (`release-switch-scan.mjs`, PK17-2; not in this crate) keeps refusing a desktop build that enables `remote`, which this feature does not change, and needs its own rule for `remote-loopback`.
  - Public API (module `loopback`): `Loopback::{start, port, base_url, token, record, presence, connections, shutdown, wait_stopped}`, `LoopbackConfig` (port, token, limits, `OriginPolicy`, routes, legacy token headers, `CapabilityVerifier`, `PresenceConfig`, busy probe, `on_idle`, record path and labels, connection cap, token bucket), `LoopbackApp::{handle, health}`, `LoopbackToken`, `RouteSpec`/`RouteClass`/`CapabilitySource`/`RoutePattern`, `CapabilityGrant`, `Authenticated`, `OriginPolicy`, `Limits`, the bounded HTTP types (`Request`, `Response`, `Body`, `Method`, `RequestReader`, `ParseError`, `StreamSink`), `Presence` and `PresenceConfig`, `LoopbackRecord` and `RecordLabels`.
  - Listener and parser: binds `127.0.0.1` only (there is no address option; a peer that is not loopback is dropped), std threads, a connection cap. Request line 8 KiB, head 16 KiB, 64 headers, body 1 MiB (configurable, capped at 64 MiB), head 10 s from the first byte, body 30 s, idle 30 s; only `HTTP/1.1`, origin-form targets without dot segments or encoded dot, slash, backslash or NUL, no obsolete folding or bare CR/LF, ASCII heads, no `Transfer-Encoding`, no `Expect`, a repeated `Host`, `Authorization`, `Content-Length`, `Content-Type`, `Origin`, `Cookie` or `Sec-Fetch-Site` refused. A JSON body is also checked with the depth and value guard `chunk` uses before any handler parses it. A response header holding CR, LF or another control byte turns the response into a 500.
  - Policy: `Host` must be a loopback name (`127.0.0.1`, `localhost`, `[::1]`, any port) or one the owner listed (421 otherwise: DNS rebinding); a request with `Origin` needs an origin the owner allowed or the host's own (403, `null` included); a state-changing request marked `Sec-Fetch-Site: cross-site` is refused even without `Origin`; a state-changing body must be `application/json` unless the route allows a form (415); a state-changing request authenticated by a cookie capability must carry an allowed `Origin`. CORS: preflight answered for allowed origins and the request headers the owner listed (no `Any`), allowed origins get `Access-Control-Allow-Origin` on every answer including 401.
  - Credentials, verified inside the owner before the handler: bearer by default (`Authorization: Bearer`, the owner's legacy headers read first as CodeRight reads `X-CodeRight-Token`, `?access_token=` only on routes declared `bearer_query_token`, GET only), constant-time compare; `RouteSpec::public` (exact method and path, the handler verifies its own signature and receives `Authenticated::Public`); `RouteSpec::capability` (a header, a path wildcard or a cookie, checked by the owner's `CapabilityVerifier`; an unknown capability is the same plain 401). A lookalike path, another method or a longer path is an ordinary bearer route again. Failed credentials feed `FailLimiter` (5 per connection and 30 overall in 60 s); a correct credential is never refused by it.
  - Wire points mirrored from CodeRight: bind and ephemeral port `main_runtime_server.rs:268`; carriers, exemptions, exact public routes, `401 unauthorized`, `429 rate limited`, token bucket 200/s burst 400 `auth.rs:37-184` (`require_token` :78, `rate_limit` :163); discovery record `daemon.port` in PascalCase `startup.rs:18-37` with the liveness check of `daemon-client/src/daemon_lifecycle.rs` (`daemon_port_process_matches`, 2 s tolerance); `/health`, `/clients` routes, bare statuses, `heartbeatSeconds` 10, `expirySeconds` 30, `lingerSeconds` 5, one live `app` (409), `should_shut_down` `api_clients.rs`; allowed webview origins `api_router.rs:35-65` (the owner lists them: `tauri://localhost`, `http://tauri.localhost`, `https://tauri.localhost`).
  - Not preserved: `allow_headers(Any)` (the owner lists the request headers) and an unbounded request line and head. A loopback caller is not a `Caller` variant (the published enum is exhaustive, so a variant would break downstream matches); the handler gets `Authenticated`.

## 0.2.7

Issues #295 (supervisor loop), #294 (chunked calls) and #306 (operator surface, partly). Written without compiling or running Cargo here; CI builds and runs the tests.

- Added (#295): module `supervisor`. `supervise(SupervisorConfig, launch, probe, on_event)` runs a `PrivateChild` under one thread that polls `try_wait`, probes through a caller closure (`ping_probe`: connect with the child's secret, optional `HostExpectation`, `ping`), feeds `HealthTracker`, and on an exit, an unhealthy child or a startup that never answered stops the child (stdin closed, then the tree killed after `stop_grace`) and applies `RestartTracker` (relaunch after backoff, `AwaitingDemand`, `Exhausted`). `SupervisorHandle::{status, restart_now, stop}`; `SupervisorEvent` for the app's log. Choices: failures before the first success never count as unhealthy (only the startup timeout acts); the first success calls `RestartTracker::ready`; a failed launch is charged to the budget; `restart_now` on a running child counts as an exit, and after exhaustion forgets the budget. The probe runs on the supervisor thread, so give it a short deadline. Tests: `tests/supervisor.rs` (launch-failure paths, no child process needed).
- Added (#294): module `chunk`, `Client::call_large`, `HostOptions::max_message`. The frame cap is unchanged. A request above half the host's frame is cut into pieces and sent through the reserved method `rk.upload`; the host assembles them (one upload at a time per connection, order checked, bounded by `max_message`, off by default since #323, below) and runs the real method through the usual allowlist and handler path. A client that opts in per request (`chunked_ok`, set by `call_large`) receives a result above the frame as `{result: null, chunked: {id, bytes, count}}` and reads the pieces with `rk.fetch`; a client that does not opt in still gets `response_too_large`. `hello` now also carries `frame_limit`, `max_message` and `chunk_bytes`. New exported codes `request_too_large` (the client's own frame-limit refusal now uses the constant) and `bad_chunk`; both are in the HTTP status table (413, 400). `rk.` is a reserved method prefix. Pieces are plain JSON text (no new dependency); escaping at most doubles a piece on the wire. Tests: `tests/chunked.rs`, unit tests in `src/chunk.rs`. Not built: the shared-file handoff (it needs a decision on who owns the directory and how a path is authorised); events above the frame limit still drop.
- Security (#323), behaviour change inside the unpublished 0.2.7: the assembled `rk.upload` request was parsed (`serde_json::from_str` into a `Value`) before the allowlist or any handler auth, so 64 MiB of dense JSON such as `[0,0,...]` cost about 1 GiB per connection for any same-user peer that claimed an allowlisted label, and `host()` enabled chunking at 256 MiB for every service. Fixes:
  1. **Chunking is off by default.** `HostOptions::max_message` (and `chunk::DEFAULT_MAX_MESSAGE`) is now `0`, so `host()` refuses `rk.upload`, advertises `max_message: 0` in `hello`, and never chunks a result. A service that takes large calls opts in, e.g. `HostOptions::new().max_message(chunk::SUGGESTED_MAX_MESSAGE)` (new constant, 64 MiB). The README example and the `chunk` docs say so. Callers that relied on the 256 MiB default must now set `max_message`.
  2. **Authorise before assembly.** The allowlist check for the carried method now runs when the first piece arrives, before any byte is buffered; an unauthorised peer gets `not_allowed` at once (and a `Denied` event), and no assembly state exists. A refused first piece also frees the assembly it would have replaced. The final dispatch still checks again.
  3. **Bound the work.** One assembly per connection (`chunk::MAX_ASSEMBLIES_PER_CONNECTION`, a new first piece replaces the old), so in-flight bytes per connection are at most `max_message`; an over-long first piece is refused before it is stored. Before the parse the assembled text is scanned once, without allocating, and refused if it nests deeper than `MAX_JSON_DEPTH` (64, `bad_chunk`) or holds more than `MAX_JSON_NODES` (1 Mi values, `request_too_large`); a dense body can no longer be amplified into a `Value`. An assembly idle for `UPLOAD_IDLE_TIMEOUT` (60 s) is dropped when the connection next sends any frame, any error drops it, and it goes with the connection on disconnect.
  4. **Connection cap on Unix.** New `HostOptions::max_connections` (default `DEFAULT_MAX_CONNECTIONS`, 64): a connection over the cap is closed before any frame is read (event `PeerRejected`). It is not a retryable "busy" as on Windows; the client sees the connection close. Ignored on Windows, where `max_pipe_instances` applies.
  Not done: the idle timeout does not wake a connection blocked in a read, so a half-sent upload keeps its (bounded) buffer until the peer sends another frame or disconnects; a read timeout would change the transport. Frames themselves are still parsed to a `Value` under the 16 MiB frame limit before method checks (every request, not only uploads, after `hello`).
  Tests: `tests/chunked.rs` (default refuses, unauthorised first piece, deep and dense bodies, cleanup, Unix cap) and unit tests in `src/chunk.rs`.
- Added (#306, the part that is contract-neutral): `Daemon::list_devices` and `DeviceInfo` (device listing, no key, `linked` from the live links); device roles as `role:<name>` scopes (`role_scope`, `role_of`, `Caller::role`, `CallContext::role`; exactly one role scope gives a role, none or several give `None`; the scopes are read from the device record after the signature verified, so no environment variable or request field sets a role); a live-update primitive, `EventLog::since` / `wait_since` and `Daemon::events_since` / `wait_events` with a `seq` on every event and an `epoch` that makes a cursor from an earlier run come back `reset`. The event log keeps its 10,000-event window in a `VecDeque` (it was a `Vec` with `remove(0)`). Tests: `tests/remote_operator.rs`.
- Open, #306 items that need a decision or work outside this crate:
  1. M1-M28 (the 28 operator calls: calendar, job approve/reject/pause, accounts, failures, inbox, devices, phone sessions, events, media bytes) and the v2 read routes. The list of calls is not in this repository (the issue points at PostRight), and they are the app's methods: the mechanism (`MethodTable`, `DeviceCalls`, `POST /v1/call/{method}`) exists. ### Added (M7 lane D: outbound link and durable tasks)

- **`rk-link/1`, the outbound link** (feature `link` for the device client, `remote` for the host). A machine with no inbound port opens TLS to the host and upgrades `GET /v1/link` (`Upgrade: rk-link/1`), signed with the device key like every other device request (signature, nonce, replay window; scope `link`). The connection then carries newline-delimited JSON frames in both directions: `hello{device, resume_seq}`, `welcome`, `task{id, seq, epoch, method, params, lease_ttl}`, `ack`, `result{id, epoch, ok|error}`, `settled`, `request`/`response` (a machine calling upward through the same device contract as `POST /v1/call/{method}`), `ping`, `close`. Each frame is `<tag> <json>`: the tag is the device's Ed25519 signature (machine to host) or an HMAC under a per-connection session key issued in the upgrade response (host to machine), bound to direction, connection id and exact payload bytes. Frames carry a sequence number that must be exactly the previous plus one, so a replayed, duplicated, reordered or dropped frame ends the connection. TLS only, pinned roots only, no plaintext fallback. 20 s heartbeat each way, dead after 60 s. One blocked reader per link, no polling thread.
- **Durable task leases with epoch fencing** (`Daemon::enqueue_task`, `task`, `tasks`, `tasks_sweep`, `TaskSpec`, `TaskInfo`, `TaskStatus`; state in `state.json`). `queued -> leased(device, epoch, expires) -> done | failed`. One owner per task at a time. The epoch grows by one on every lease grant. A result is accepted only from the device's current connection and the current epoch: a stale epoch is `lease_lost`, a superseded connection is `superseded`, the same `(task, epoch)` result twice is `duplicate`. A disconnect releases nothing: the device reconnects and gets every leased task it has not acked again, with the same epoch, whatever its `resume_seq` says (a re-lease reuses `seq`; the device journal dedups by `(id, epoch)`). A lease lapses only when its owner sends no frame for `lease_ttl`; the sweep that observes the lapse re-queues the task in the same step, so it re-queues exactly once, and the next grant (epoch + 1) fences the old holder. Two connections of one device: the newer supersedes, the older is closed with `superseded`. Unpinned tasks go to the linked device holding the fewest leases. Events: `LINK_UP`, `LINK_DOWN{reason}`, `LINK_FRAME_REJECTED{reason}`, `TASK_QUEUED`, `TASK_LEASED`, `TASK_DONE`, `TASK_FAILED`, `TASK_LEASE_LOST{reason}`; `DaemonMetrics` gains `links`, `tasks_queued`, `tasks_leased`.
- **Blocking client** `rightkit_daemon::link::client` (`LinkClient::start`, `LinkConfig`, `LinkHandle`, `TaskHandler`, `LinkTask`): std sockets and rustls only, so a `link`-only build has no tokio, axum or hyper (`tests/link_features.rs` pins this against the manifest and the sources). Reconnects with capped exponential backoff (1 s to 60 s, jitter) and a fresh signature; writes each task to a journal (fsync) before it is acknowledged; keeps each result until the host settles it and resends it after a reconnect; runs journalled unfinished tasks again after a restart (at-least-once; handlers key on `id` and `epoch`). `LinkHandle::call` is a machine-to-host request over the link.
- The HTTP listener now serves with `with_upgrades` and drains connections with its own stop signal and the connection permits instead of hyper-util's `GracefulShutdown` (which does not cover upgradable connections); links are closed first at shutdown. `GET /v1/link` is handled before the daemon-api route table, which, with `ROUTES` and the 1.1.0 fixtures, is unchanged.
- Tests: `tests/link.rs` (host logic in process with a manual clock, and the real client over TLS: kill the connection mid-task and the same device resumes, a result finished while down is delivered after reconnect, stale epoch refused, supersede, lease expiry re-queues once under concurrent sweeps, replay and forged frames refused, plaintext refused), `tests/link_features.rs` (runs in both `test-mode` states, no gate).

### 0.1.5 entries folded in

- Fix: `Client::call` returned `request_timeout` after the full deadline when the host's reply was larger than the client's 16 MiB frame limit (the host's `frame_limit` may be larger): the oversized frame was drained and then ignored while the client kept waiting for it.
