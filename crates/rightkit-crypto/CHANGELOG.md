# Changelog

## 0.1.2 (unpublished)

- Ed25519 sign/verify, ECDSA P-256 verify (ASN.1 and fixed), AES-256-GCM and ChaCha20-Poly1305 (`aead`), HKDF-SHA256, PBKDF2 (SHA-256/SHA-512), system RNG and a zeroizing `Secret` (#845). Backend decision: `ring` 0.17.14, the version rightkit-mesh, rightkit-daemon and rightkit-context-runtime already pin and every named consumer (Pulse, coderight, heardright, mailright, scraperight, rightkit-vault, rightkit-sync) already uses; RustCrypto would add several crates per primitive.
- RSA PKCS#1 v1.5 SHA-256 verify (2048 to 8192 bit), `hmac(Sha1|Sha256|Sha512)` and RFC 6238 `totp` (#1172).
- New dependency `ring`: the crate's Cargo.lock must be regenerated by the root integration.

## 0.1.1 (unpublished)

- Unit tests and debug-assertion switches removed (Adrian, 2026-11-03: end-to-end tests only; no debug assertions). Release behaviour unchanged.

## 0.1.0 (2026-10-17)

- New crate 0.1.0 (Orthic-Labs/rightkit#370, #372, #417, #477). `sha256`, `hmac_sha256` (RFC 2104/4231), `ct_eq`, `base64` and `base64url` encode/decode (RFC 4648), `hex`, `blake3_text`, `canonical_json` (sorted keys, compact), and `approval` token `mint` / `verify` (HMAC-SHA256 over a length-prefixed encoding of purpose, subject, issued-at and expiry, constant-time verify).
- Cross-crate items from #417 not implemented here: LLM token counting (rightkit-llm) and the ignore-aware repo walk (rightkit-fs).
- Not compiled or run when written; verification is the CI run.
