# Changelog

## 0.3.3

Additive; no existing item changes. Written without compiling or running anything: the macOS build of the PDFKit backend and the CI gate are the verification. Needs the lockfile's `rightkit-pdf` entry moved to 0.3.3 and the new macOS-only optional dependencies added (`objc2`, `objc2-app-kit`, `objc2-foundation`, `objc2-pdf-kit`, `block2`; none is built off macOS or without the feature). Requested by PK08-6 (ViewRight `mac_pdf_view.rs` donor).

- **`host` feature (off by default): native PDF view host.** `host::{PdfHost, HostConfig, HostHooks, HostError, NativeParent, AuthorizedPdfPath, PdfPassword, OpenRequest, UpdateRequest, FindRequest, HostState, HostFindResult, HostOutlineItem, HostViewMeta, HostFrame, HostKey, HostResourceEvent, ResourcePhase, HostCounts}` and the helpers `normalized_rotation`, `clamp_page`, `pick_active`. One PDF view per window, keyed by the caller's window label first, so a window never reaches another window's document (`NotOpen`); the owner token is a stale-call guard (`StaleOwner`, nothing changes). `open` (frame, canvas colour, initial page, zoom, fit, rotation, password), `update`, `state`, `find` (match case, whole word, step with wrap-around), `print`, `suspend`, `close`, `release_window`, `reap`, `dispose_all`, `sweep`, `next_sweep_in`, `counts`, `drain_events`. Suspended views are kept for reuse in a bounded cache (default 8 views, 30 s, at most 64 and ten minutes), reused only by the same window and path while a streaming SHA-256 taken at open still matches, never for an encrypted document, and expired by calls and `sweep`, never by a timer in this crate. The file is an `AuthorizedPdfPath` (absolute, UTF-8, a regular file within `HostConfig::max_file_bytes`); the host never resolves a string the page supplied. Lifecycle changes are `HostResourceEvent`s in a bounded outbox the caller drains after each call. Requests are validated before any native call (frame, scale, fit, panel, query and password sizes, label and owner text).
- **PDFKit backend (macOS only).** Ported from ViewRight `mac_pdf_view.rs`: `PDFView` with a continuous single-page vertical layout, outline, thumbnail rail (`HostConfig::thumbnail_rail`), read-only widgets, file-launch, script and remote-document actions removed in memory, link clicks through `HostHooks::open_link` (default: refuse), key presses the app claims (`HostHooks::with_key_claim`) forwarded while the view has focus, print panel with no lock held. Every entry point checks it runs on the AppKit main thread (`HostError::NotMainThread` otherwise). One PDFKit host per process.
- **Every other platform** builds no native code: `PdfHost::new` answers a host whose every call is `HostError::Unsupported`.
- Differences from the donor: `close` needs an owner or a path (the donor closed whatever was active when both were empty); `fit`, `panel` and `scale` that are not valid are `Invalid` instead of ignored; a failed open keeps the previous view and releases a reused one; a view that cannot be parked is released.
- Tests: `host/tests.rs` over a fake backend, so they run on every platform: owner isolation between windows, stale owner on every call, replace and reuse, identity mismatch, age and count bounds, encrypted not parked, failed open and failed reopen, teardown and reaping with a leak count, bounded outbox, find stepping, validation refusals, unsupported host for every call, wire shapes.

## 0.3.2

Additive; no existing item changes. Not compiled or run when written, so the CI run is the verification; `Cargo.lock` needs its `rightkit-pdf` entry moved to 0.3.2 (CI patch). Requested in Orthic-Labs/rightkit#282 (Ember #240).

- **Document writer for new PDFs (`write`, always built).** `write::{Document, PageId, IccId, JpegInfo, WriteError, MAX_PAGE_SIDE_PT}`. `Document::new(version)` (1.0 to 1.7; 1.4 supported), `add_icc_profile`, `add_page(width_pt, height_pt)`, `place_jpeg`, `add_jpeg_page`, `finish() -> Vec<u8>`, and (feature `edit`) `write_to(path)` through `commit::write_atomic`. Full-page JPEG placement: DCTDecode, 8 bits per component, DeviceRGB, DeviceGray or `[/ICCBased n 0 R]` with an embedded profile stream (written once, shared by pages), drawn with `q w 0 0 h 0 0 cm /Im0 Do Q`. Deterministic bytes: insertion-order object numbers, classic xref table, no dates or `/Info`, `/ID` is the SHA-256 of the body. `JpegInfo::parse` reads the SOF header (baseline, extended-sequential and progressive Huffman; 1 or 3 components); CMYK, 12-bit, lossless and arithmetic JPEGs, a profile whose component count differs from the JPEG's, and ICC under PDF 1.2 or earlier are typed refusals. Streams are stored uncompressed. Vector text (item 3, feature `fonts`): `Document::add_font(ttf_bytes, face_index)`, `measure_text`, `draw_text(page, font, size_pt, x, y, rgb, text)`, `try_finish()` (and `finish()`, which panics only if the subsetter rejects a font `add_font` accepted). Each used font is subset once at finish over all its text with `font::subset_for_pdf` (the existing `subsetter` 0.2.6 and `ttf-parser` 0.25.1 dependencies, both already in the lock, no new crate; licences MIT OR Apache-2.0 for both, taken from their crates.io metadata, not re-checked in this repository) and embedded as Type0 / CIDFontType2 / `FontFile2` with `/Encoding /Identity-H`, `/CIDToGIDMap /Identity` (CID is the subset glyph id), a `/W` array, a `ToUnicode` CMap (`font::build_to_unicode_cmap`), a descriptor from the font's own metrics, and a subset tag derived from the subset program, so output stays deterministic. Strings are written as 2-byte hex glyph codes. Gaps: TrueType glyf/loca only (CFF-flavoured OpenType fails in the subsetter), no shaping, kerning, bidi, wrapping or ligatures (one call is one run), a character without a glyph is refused rather than substituted, no `/CIDSet`, variable fonts are written at their default instance, text is always painted after the page image. `font::face_embedding_permissions` became `pub(crate)`. The acceptance (Ember's print, slideshow and book PDF tests green with the engine's `Pdf` swapped) is Ember's to run; this crate's own tests read the output back with `lopdf`.

## 0.3.1

Additive: five features and one page-organise module, no existing item changes. 0.3.1 is the next published version. None of it has been compiled or run yet (see "Verification" in the README); `Cargo.lock` needs its `rightkit-pdf` entry moved to 0.3.1 (CI patch).

- **`redact` feature (off by default, Orthic-Labs/rightkit#274).** `redact::{RedactMark, RedactMarks, RedactOptions, RedactReport, RedactOutcome, RedactError, apply_marks, verify_redacted}`. Removes content under marked rectangles instead of covering it: glyphs are cut from `Tj`/`TJ`/`'`/`"` and replaced by a same-advance `TJ` number; an overlapping image `Do` is removed whole (partly covered images are dropped, not pixel-cleared); overlapping vector paths and annotations are removed; `/ActualText`, `/Alt`, `/E` are stripped from inline `BDC` lists; `/Info`, `/Metadata`, `/PieceInfo`, page `/Thumb`, the structure tree and the embedded-file and JavaScript name trees are removed (`sanitize`, default on); the file is written whole with unreferenced objects pruned; a box is painted last. Fails closed (`RedactError`): unpositionable text, a glyph whose advance cannot be a `TJ` number, a stream that does not parse strictly or is shared by two pages, an overlapping inline image, form XObject or shading (`remove_unsupported` removes the operator whole instead), an encrypted file, and any result whose second walk finds content under a mark. The guarantee and what is not covered (form XObject interiors, `/Properties` names, sub-glyph precision) are in the module documentation.
- **Page organise (feature `merge`, #275).** New module `organize`: `delete_pages`, `reorder_pages`, `rotate_pages`, `insert_pages`, `verify_structure`, `OrganizeError`. Bytes in, bytes out (the input is the undo snapshot). Flat page tree rebuilt from materialised inherited attributes; page objects keep their ids so outline items and destinations stay valid; the outline loses only destinations of deleted pages; page labels are rebuilt for the new order (`/St` adjusted); deleted pages and what only they reached are pruned; every result is reloaded and checked. `merge::load`, `materialize_inherited` and `SharedValues` became `pub(crate)`.
- **`forms` feature (off by default, #276).** `forms::{list_fields, set_values, reset_fields, FormField, FieldKind, FieldValue, FormOptions, FillOutcome, FormError}`. Lists terminal fields (qualified names, kinds, options, flags, button states); sets text, check box, radio, combo and list values; generates appearance streams for text and combo fields (`/MK` colours and border, clipping, `/Q`, auto size, wrapping); fields it cannot draw keep their value, are named in `FillOutcome::without_appearance`, and `/NeedAppearances` is set. Typed refusals instead of substitution: read-only, too long, not an option, characters the font cannot show, password / file-select / comb fields, XFA and signed documents (unless `FormOptions` allows). The written file is read back and compared. `inspect::standard14_width` became `pub(crate)`.
- **`optimize` feature (off by default, #277).** `optimize::{optimize, optimize_with_progress, OptimizeOptions (standard 150 ppi, mobile 96 ppi), OptimizeReport, SkipReason, Stage, Progress, OptimizeError}`. Measures each image's effective resolution through the CTM and forms (12 deep), downsamples 8-bit Gray/RGB images to the target by area average, re-encodes as Flate (kept only if smaller), removes unused objects, compresses unfiltered streams, and returns the input unchanged if the result is not smaller. An image whose resolution is unknown (referenced as a mask, listed by a form no page paints, a pattern or a Type 3 font, unmeasurable matrix) is never resampled. Not done: page-printer strip merging, JPEG re-encoding, colour conversion.
- **Extraction quality harness (#278), test-only.** `tests/extract_quality.rs` (feature `extract`, ignored): word F1 and an LCS reading-order score against poppler `pdftotext` on a corpus pinned by `manifest.json` sha256 (default: the four in-repo fixtures; `pin_corpus_manifest` pins another offline). A missing `pdftotext` fails unless `RIGHTKIT_PDF_QUALITY_ALLOW_SKIP=1` (printed skip). Ends with a column-aware-ordering verdict. The baseline in `tests/fixtures/extract-quality/baseline.json` is **not recorded yet**: it needs a run with poppler. Scoring functions have ordinary tests.

## 0.3.0

Published version number: this release changes or removes public items, so it is a breaking release under Cargo's rules for 0.x versions. It includes everything under the 0.2.1 heading below, which was never published. `PdfTextIsland` has private fields, enums gained variants, saving goes through rightkit-fs 0.4.0, and island grouping changed on pages with a scaled CTM.

- **Page rasterization for scanned PDFs (OCR input, Orthic-Labs/rightkit#170).** Additive; no version bump (0.3.0 is not on crates.io, whose only published version is 0.1.0). New module `scan` (always built): `classify_page`, `classify_page_doc`, `scanned_pages`, `PageProfile` (`has_text`, `has_visible_text`, `image_count`, `largest_image_coverage`, `is_scanned()` = no text layer and an image over at least half the page; an invisible OCR text layer counts as text) and `RasterError`. New feature `raster` (off by default; dependency `image` 0.25 with only the `png` and `jpeg` codecs, optional): `rasterize_page`, `rasterize_page_doc`, `rasterize_page_png`, `rasterize_scanned_pages`, `RasterOptions { dpi (1..=1200, default 300), max_pixels (default 60 million, checked before allocating), format: Gray8 | Rgba8 }`, `RasterPage { width, height, pixels, limitations }` and `RasterPage::to_png`. This is not a general renderer (the crate has none, and no PDFium): it draws image XObjects (also inside forms) through the CTM, crop box and `/Rotate` on white, and reports in `limitations` anything it did not draw (visible text, vector graphics, inline images). Images: Flate, LZW, ASCII85 and DCT (8-bit gray or RGB JPEG); Gray/RGB/CMYK/ICC/Indexed, `/Decode`, `ImageMask`, `/SMask`. `CCITTFaxDecode`, `JBIG2Decode` and `JPXDecode` images (common in scans) return `RasterError::UnsupportedImage`; `/Mask` is ignored. Internal: six `inspect` helpers became `pub(crate)`. `Cargo.lock` needs the `image` entry added to `rightkit-pdf` (CI patch).
- Fixes a changed-font replacement drawn in the wrong place and at the wrong size (present since 0.2.0, also in 0.2.1 as staged). The replacement block runs in its own stream in the default graphics state, but was emitted as `1 0 0 1 <availableBounds.x> <availableBounds.y> Tm` with `Tf` at the source's text-space size. On a page whose producer positions each run with `cm` outside the text object (`0.1 0 0 0.1 0 0 cm`, `1 0 0 1 0 7920 cm`, then one `cm` per run; `fed-annual.pdf` page 7) the run's placement lived in the CTM the block no longer had, so the new text was drawn about ten times too large at the page origin, the original spot was left blank, and the edit still read back as the requested text. The block's `Tm` is now the source run's first-glyph `text matrix x CTM` (all six numbers: rotation, skew, negative and non-uniform scale survive) with `Tf` unchanged, so `Tf size x Tm x identity` equals the source's `Tf size x Tm x CTM`. The new run is placed from the island, no longer from `availableBounds`, and its fit is measured along the island's own axis in device space (it was measured with the text-space size as if it were points). A composed batch is now read back (`verification_failed`): each replacement's first glyph must be within 0.5 pt of the source run's and its size and direction within 2 percent. Add Text and the OCR correction text are unchanged (an upright `1 0 0 1 x y Tm` at a page-space point). Not reproduced: the block resets `Tz` (horizontal scaling), `Ts` (rise), `Tc`, `Tw` and the render mode, as before, and draws the catalog font's glyphs. The read-back compares `text matrix x CTM`, which excludes rise on both sides, so a source run with a non-zero `Ts` is redrawn lower or higher by rise times scale and still passes; it compares the size that was requested, and `appearance.sizePt` is in the island's text-space units (the value the island reports), so it cannot catch a caller that sends page points on a scaled page. The fit checks extent only: if `availableBounds` starts left of the island's origin the run can overflow right by that offset. The read-back finds each run by its own content stream and compares that stream's first glyph, not the island it was grouped into (the join rule does not compare fonts, so a run within the join window of a preceding same-colour run on the same baseline shares its island). The same-font in-place edit never emitted coordinates and is unaffected.
- **Behaviour change on pages with a scaled CTM:** island grouping measured its join window (`may_join`: baseline offset, gap, overlap) and the painted-content check between two glyphs (`has_intervening_painted_content`) with the text-space `Tf` size as the em, but compared it with device-space gaps, so on a page under `0.1 0 0 0.1 0 0 cm` the window was ten times too wide and runs 30 pt apart were one island (present in published 0.2.0). The em is now the glyph's `Tf` size times the length of its baseline axis (the `(a, b)` row of text matrix x CTM, the larger of the two glyphs; 1.0 only for a zero or non-finite scale), in both functions. Islands that were wrongly merged are now separate, so islands, quads, `island_digest`s and locators taken on such a page with an older build do not match; inspect the page again. A page where the device size equals the `Tf` size (no scaling in `Tm` or `cm`) groups as before, except that text below 1 device point no longer floors the em at 1; a page that scales through `Tm` (a `Tf 1` with a `12 0 0 12 Tm`) is now measured at its real size too. Text turned a quarter on a scaled page, which the loose window used to join by accident, is now split into one island per glyph, as it already was on an unscaled page: grouping measures gaps along page x and baseline offsets along page y, not along the baseline (README, limits). Not fixed here.
- **Breaking, not listed before:** `PdfTextIsland` gained private fields, so code outside the crate can no longer build one with a struct literal (0.2.0 had only public fields). Take islands from the page graph.
- Fixes a 0.2.1 regression (unpublished): Add Text and a changed-font replacement returned `malformed_content` on a page whose `/Contents` is cut between an operator's operands and the operator (`irs-1040.pdf`, `irs-p17.pdf`, `irs-w9.pdf`; ISO 32000-1 7.8.2 allows the cut, 0.2.0 composed them); the isolation wrapper now counts such a stream as it stands, while a stream ending in an open string, an open array or an unreadable byte is still refused.

## 0.2.1 - 2026-10-11

Additive except for the public enum changes marked below. Answers gap ledger row 93 (ViewRight corpus run). Not yet published. Includes the fixes for the 2026-10-11 independent read (`docs/audits/2026-10-11-astra-rightkit-pdf-0.2.1.md`, findings 1-12); the hostile-input items (1, 9) exist in published 0.2.0.

- **Honest editability.** `PdfTextIsland::editable` is now the decision `compose_candidate` makes (one shared `ReverseTable` per font), not a constant `true`. A font that can never be re-encoded gives `editable: false`, `rejection: unsupported_encoding` and the new `editBlocker` (`unsupported_font_type`, `no_reversible_encoding`, `missing_metrics`, `mixed_text_state`, `unmapped_glyphs`, `spans_across_streams`). New `substitutionEditable`. Existing serde names are unchanged.
- **Typed missing glyphs.** New `PdfEditError::MissingGlyphs(Vec<char>)` (wire code `missing_glyph`, message names the characters, `missing_chars()` accessor) for a replacement that needs a character the island's own font has no usable code for. The enum is not `#[non_exhaustive]`: an exhaustive external `match` on `PdfEditError` needs one new arm.
- **Exact fit check.** The in-place write was measured as `chars * size * 0.5` and refused same-width swaps (`proof-text-50page.pdf`: 324 pt estimate against a 286.8 pt box). It now sums the font's real widths with the walker's `Tc`/`Tw`/`Tz`/matrix rules and allows 0.05 pt.
- **Re-encoding coverage.** In-place writes now cover (1) islands spanning several operands (kerned `TJ`, adjacent `Tj`) and (2) `Identity-H` CID fonts through `ToUnicode` and `/W`. Reverse tables never guess: an unreadable `/Encoding` dictionary, a built-in encoding with no `ToUnicode`, and `/Differences` codes the file does not list are refused.
- **`/Contents` as an indirect array** (the `uscis-i9.pdf` failure: `page_graph_from_bytes` returned `malformed_content`). Handled in inspection, add-text, content-CTM and save verification.
- **Text state across content streams.** The walker now carries `Tf`, `Tc`, `Tw`, `cm`, `q` across a page's `/Contents` streams instead of resetting at each one.
- **No silent truncation.** Compose parses a stream strictly and returns `malformed_content` rather than rewriting a stream whose tail the parser dropped.
- **Word gaps (fix for LaTeX lines losing their spaces).** Island text now contains a synthesised space at every `TJ`/position gap wider than 0.2 em (`gaps` lists them); in-place edits no longer flatten a kerned run: only the changed middle is rewritten, unchanged words and adjustments stay byte for byte, same-length edits overwrite glyphs in place, and changed spaces regenerate gaps of the original width. Islands whose gaps come from position moves, or with a positioning/state operator between show operators, are `editable: false` with `editBlocker: positioned_text_run`. New fields: `gaps`; new blocker `positioned_text_run`.
- `tests/fixtures/proof-text-50page.pdf`; `tests/corpus_coverage.rs` (ignored) measures the coverage above.

### Reduction after the fifth independent read (`docs/audits/2026-10-11-astra-pdf-fifth-read.md`, `docs/audits/2026-10-11-astra-publication-path-consult.md`)

Five review rounds did not converge because each added platform mechanisms that had never compiled. This round removes them, keeps the fixes that were reviewed and closed, and adds no platform call. The sections below that describe the removed mechanisms are history; where they differ from this one, this one governs.

**Removed**

- The crate's own file writer: the `ReplaceFileW` call, the Unix `fchown`/`chmod` handling of the temp file, the owner-only temp creation, the `getrandom` temp name and the `write_atomic` body. The write is now `rightkit_fs::AtomicWriter` (default replace mode: `rename(2)` on Unix, `std::fs::rename` on Windows). `ReplaceFileW` without a backup deleted the original on a failed replace and the error path then deleted the replacement (fifth read 13).
- The token "upper bound" byte scan (`token_upper_bound`) and its tests. It counted runs of regular characters, so `0q0q0q...` was one token and 32 MiB of it passed (fifth read 14).
- The per-page cloning of inherited page attributes in `merge`, and the entry budget (`MAX_MATERIALIZED_ENTRIES`) that charged it shallowly (fifth read 15).

**Kept, unchanged in kind:** the destination lock, the source re-validation, resolving a symlink destination once, invalidating tokens including hard-link siblings, the Windows file identity (`windows-sys`, `FILE_ID_INFO`; reviewed and closed as finding 3), and the other budgets.

**Added**

- Dependency `rightkit-fs` 0.3.4 (`default-features = false`, feature `fs`) behind the `edit` feature; dev-dependency `rightkit-fs` with `fs` and `testing` (fault seam around the replace call; debug and test builds only). `windows-sys` stays (identity only).
- A comparison of the new temp file with the destination before any byte is written. The save is **refused**, original untouched, when it finds a difference in owner, group or permission bits (Unix), when an owner-only destination is, or may be, under an extended ACL (macOS, through `rightkit_fs::private::is_owner_only`), or when the destination is read-only or EFS-encrypted (Windows). What is not examined (Windows DACL, macOS ACL on a wider mode, POSIX ACLs, extended attributes) is listed per platform in the README and the `commit` module docs.
- Page content is charged **one token per byte** of decoded content, before the parse allocates (every object the parser builds starts at a byte of its own, so this cannot undercount).
- Inherited `Resources`, `MediaBox`, `CropBox` (and any direct container) are shared by one indirect object per ancestor.
- Inspection and composition read one predicate (`inspect::is_line_moving_show`) for glyphs shown by `'` and `"`.

**Public API.** `commit::CommitError` gains `Refused(Unpreserved)` and `Replaced(io::Error)`; the enum is not `#[non_exhaustive]`, so an exhaustive external `match` needs two arms. New `commit::Unpreserved` (`#[non_exhaustive]`: `ReadOnly`, `Encrypted`, `Owner`, `Group`, `Mode`, `Acl`). `commit::write_atomic` keeps its signature; its `io::Error` can now carry a `CommitError` (`get_ref().downcast_ref`). `PdfTextIsland::substitution_editable` is `false` for text shown by `'` or `"` (it was `true` and the composer refused it).

**Consumer**

- A save over an existing file is refused (`CommitError::Refused`) where the new file would have another owner, group or permission bits, or would drop a macOS ACL on an owner-only file, or where a Windows file is read-only or encrypted. Before, the save replaced the file and weakened it silently.
- `CommitError::Replaced`: the new bytes are in place and only the directory sync failed (Unix). Treat as saved.
- A page whose decoded content exceeds 8 MiB (2^23 bytes) is `malformed_content`; the previous guard (64 MiB decoded, 2^23 tokens counted by the byte scan) is replaced by the stricter, sound one. The 64 MiB decode buffer limit is unchanged.
- `merge_pdfs` and `select_pages` output shares one indirect `/Resources` (and box) object per ancestor instead of a copy on every page; the pages render the same. They no longer fail with "inherited page attributes are too large to copy".
- `Cargo.lock` needs `rightkit-fs` added to the `rightkit-pdf` entry (CI patch).

### Fixes from the fourth independent read (`docs/audits/2026-10-11-astra-pdf-fourth-read.md`, findings 7-12)

No public API change except `model::PositionedGlyph` gaining the field `pen_advance` (text-space pen advance of the glyph, before `Tz`); construct it with the walker's value. Behaviour changes a consumer can see are marked **Consumer**.

- **7. Saving kept no file protection.** *(Superseded: the Unix temp handling and the Windows `ReplaceFileW` below were removed after the fifth read; see the reduction section above.)* `commit::write_atomic` (the one writer; `commit_pdf_save` calls it) creates the temp sibling exclusively (`create_new`), owner-only (`0600`) on Unix when it will replace an existing file, and gives it the original's owner, group (best effort) and permission bits before the rename, so a `0600` PDF stays `0600`. On Windows an existing target is replaced with `ReplaceFileW`, which carries the original's DACL, attributes and creation time instead of inheriting the directory's ACL. A new destination is created as before. `write_atomic` also resolves a symlink target first. **Not done:** macOS extended attributes and ACL entries are not copied (no `libc`/`copyfile` dependency).
- **8. Hard-link sibling tokens.** After a successful commit every staged source that names the *replaced* file (read under the lock before the rename; a hard link keeps the old bytes under its own name) or the file the destination is now is invalidated, and so is every staged path if the destination cannot be read back (it used to return an error after the write, skipping invalidation). Regression: two candidates staged against A, A hard-linked to B, first commit to B, second commit to B is `write_conflict`.
- **9. Changed-font replacement moved neighbouring text.** Removing the old glyphs deleted their pen advance. Each removed glyph is now replaced by the `TJ` number that moves the pen exactly as the glyph did (a whole number, reproducing the walker's step bit for bit, whenever the file can say so; otherwise the nearest PDF real). A `Tj` becomes a `TJ` at the same operator index; a `TJ` string item is split around the removed ranges. Glyphs shown by `'` and `"` are refused (`unsupported_encoding`): a `TJ` cannot carry their line move. **Consumer:** a catalog-font replacement of a `'`/`"` run that used to compose is now refused.
- **10. Memory before budgets.** A page's content is decoded and parsed under one `ContentBudget` shared by every `/Contents` entry as listed: 64 MiB decoded in total (each stream decoded with the remaining budget as its limit, one decoded stream held at a time, none retained) and 2^23 tokens, the latter from a byte scan taken before `Content::decode` allocates (this replaces the 2^24 operation cap, which was checked after the parse had already built every operation). *(Superseded: the byte scan undercounted; the budget now charges one token per byte, see the reduction section above.)* Composition (`decode_stream_content`, the isolation wrapper's `q`/`Q` count) uses the same budget. Also bounded before allocating: unclosed `q` operators the wrapper must close (65 536), the page arrays rewritten when a stream is shared (2^20 references, and one copy of the stream however many pages share it), the resource fingerprint (2^21 entries; `resource_fingerprint` now returns `Result` and an oversized one is `malformed_content`/`verification_failed`, never truncated), fonts per page (512), `ToUnicode` bytes (32 MiB) and `ToUnicode`/`/W` assignments (2^21) summed over a page's fonts, `ToUnicode` tokens per block (2^19), merge's inherited attributes (2^21 entries) and, in merge, the same bounded loader. The document-load decode limit is 64 MiB (was 256 MiB). **Consumer:** a page whose decoded content exceeds 64 MiB or 8.4 million tokens is `malformed_content`.
- **11. Glyph allocation preceded the glyph limit.** `decode_show_operand` checks the operand's glyph count against the page's remaining glyph budget before reserving, and reserves with `try_reserve_exact`.
- **12. Wrappers invalidated later commands in the batch.** The isolation wrappers and the new streams (add text, OCR cover, the new run of a changed-font replacement) are installed once, after the last command, in command order; per-command installation prepended a stream and shifted every original `contents_index`, which the island digest binds. The `ReplaceSourceText` commands for one page now run back to front by source address so splitting a `TJ` string item cannot move an item a pending command still needs. **Consumer:** a page edited by several commands has one `q` wrapper and one `Q` wrapper instead of one pair per command.
- Tests: `tests/hostile_input.rs` (a stream listed 1 024 times, one 3-million-code operand, 9 million empty strings and operands, 600 fonts over one CMap), `commit.rs` (mode, symlink, sibling hard-link tokens), `compose.rs` (batches of add text and several replacements against one page asserting untouched islands keep their quads bit for bit and sit one stream later (their `island_digest` changes with it), interleaved `TJ` items, repeated island, shared stream, unclosed `q` flood), `inspect.rs` (pen number, token bound, budget, fingerprint bound).

### Fixes from the third independent read (`docs/audits/2026-10-11-astra-pdf-third-read.md`)

No public API change. New target dependency on Windows only: `windows-sys` 0.61 (`Win32_Foundation`, `Win32_Storage_FileSystem`), for file identity; `Cargo.lock` needs the CI patch.

- **Decoded Unicode is bounded (finding 1).** A `ToUnicode` destination longer than 64 UTF-16 units is not read and makes the CMap inexact (`no_reversible_encoding`). Each page also has a decode budget of 2 097 152 glyphs and 8 MiB of decoded Unicode in total, charged before any string is cloned; exhausting it refuses the page with `PdfEditError::TextOverflow` (`text_overflow`) instead of allocating. Reproducer (1 MiB destination shown 50 000 times, 48 GiB) is in `tests/hostile_input.rs`.
- **Bounded parse work (gap ledger row 155).** A page may present at most 16 777 216 content-stream operations across its streams; past that it is refused as `malformed_content` before the walk. Together with the decode budget and the existing 256 MiB stream limit, a hostile file's work is bounded by its size and fixed caps. This is a deterministic work cap, not a wall-clock deadline.
- **Symlink commits no longer lose edits (finding 2).** `commit_pdf_save` resolves the destination once, locks and rechecks that file, and replaces it - the rename no longer replaces a symlink with a regular file. The destination is resolved again after the lock is obtained and a retargeted link fails with `WriteConflict`. A dangling symlink is refused.
- **Windows file identity (finding 3).** The destination's identity is the volume serial and 128-bit file id read from an opened handle (`FILE_ID_INFO`, falling back to the 64-bit file index), as `dev`/`ino` is on Unix, so a hard link to the staged source still triggers the source recheck. An existing destination whose identity cannot be read fails the commit with an I/O error instead of being compared by path. If the identity of a staged path cannot be read, its tokens are invalidated.
- **Added and rewritten text is isolated from the page's graphics state (finding 4).** Appended content (`AddText`, `CorrectOcrText`, and the new run of a changed-font replacement) now goes in its own stream, with the original streams wrapped in `q` ... `Q` streams sized from the original's own `q`/`Q` balance. A leftover clip (`W n`), an `ExtGState` with `/ca 0` or a blend mode, or a stray CTM can no longer hide it. Original streams are not modified; the page's `/Contents` gains a `q` stream first and a `Q` stream before the added one (so `/Contents` has three more entries than before). The changed-font run is no longer appended inside the edited stream, and the old CTM-reset `cm` is gone because the new stream starts in the default state. Content that cannot be parsed strictly is refused as `malformed_content` for these three commands.
- **Locators must be complete (finding 5).** `ReplaceSourceText` requires the locator's spans to equal the page's current spans for the island (same count, order, addresses and digests); a locator with a span removed, reordered or repeated fails with `source_digest_mismatch`. Mutations use the freshly inspected spans, not the caller's copy.
- **Race regression test (finding 6).** The two-commit test now reads the source before the rendezvous and returns that snapshot, so both contenders hold identical bytes and the test fails without the destination lock.

### Fixes from the independent read (hostile input, wrong-output edits)

- **Hostile input (also in 0.2.0).** Every loop driven by a number in the file is now bounded by what the file contains and by a hard cap, and arithmetic on file integers is checked: `/W` CID ranges and arrays are clamped to the two-byte CID space (`u32::MAX` no longer overflows or refills the map), `bfrange` source and destination arithmetic is checked, the `ToUnicode` reader has a work budget, `/FirstChar`..`/LastChar` is bounded by the `/Widths` array, inherited page attributes stop on a `/Parent` cycle (visited set) and at depth 64, and streams decode under a 256 MiB limit (documents load with the same limit). A malformed entry is skipped or the font is marked not reversibly encoded; nothing panics. `tests/hostile_input.rs` is the in-memory adversarial corpus, each case under a wall-clock guard.
- **Array-form `bfrange`** (`<lo> <hi> [<d0> <d1> ...]`) is read correctly: code `lo+i` maps to `d_i`, nothing is invented. A `ToUnicode` CMap the reader cannot read exactly (unbalanced array, bad token, `usecmap`, work budget exhausted) makes the font `editable: false` (`no_reversible_encoding`).
- **`gs`.** An ExtGState that sets `/Font` (or one the page's resources cannot resolve) drops the walker's active font, so the text after it is an unresolved-font island instead of being decoded through the previous font, and it is a seam in the run.
- **Flattened edits** zero every kern between the replaced glyphs, and every in-place write is **read back**: the island at the same source position must read as exactly the requested text (so spacing the encoding cannot represent is refused with `missing_glyph` for the space, or `verification_failed`) and must fit the available bounds as the walker now measures it.
- **Same-length edits** account for `Tw` when a space is introduced or removed, and the replaced region's trailing `Tw`.
- **`compose_candidate` refuses a non-editable island whose appearance is unchanged** (`unsupported_encoding`) before choosing a strategy. A changed appearance still redraws in a catalog font. Behaviour change: a `ReplaceSourceText` for an island with `editable: false` and unchanged appearance used to fall through to a catalog-font redraw when the resolver could resolve the island's font id.
- **Shared content streams.** Editing a page whose `/Contents` stream is also used by another page gives the other pages a byte-identical copy first; `affected_pages` lists only the edited page. A second command in the same batch aimed at one of the other pages is refused as `source_digest_mismatch`.
- **TJ provenance** survives an empty string and a show-operator boundary (`[(a) -333 () (b)] TJ`, `[(a) -333] TJ (b) Tj`).
- **`substitutionEditable`** is `false` for an island whose source spans live in more than one content stream (the composer refuses that edit); **`gaps[].widthPt`** is the distance beyond `Tc`, as documented.

### Fixes from the second independent read (`docs/audits/2026-10-11-astra-rightkit-pdf-second-read.md`, findings 1-8)

Behaviour changes a consumer (ViewRight) can see are marked **Consumer**.

- **1. `TJ` gap provenance was quadratic.** An empty string operand cloned the accumulated adjustment numbers into the spacing map, so `[(A) 0 () 0 () ... (B)] TJ` with 50 000 empty strings retained about 1.25 billion entries. Empty operands now touch nothing; a real string takes the numbers by move. A per-page budget (2^20 numbers) bounds the rest: past it a gap has no provenance (its island is `positioned_text_run`, not editable), never a partial list.
- **2. Font insertion hid inherited resources.** `AddText`, OCR correction and a catalog-font rewrite built a page-local `/Resources` holding only the new font when `/Resources` sat on an ancestor `/Pages` node. The nearest inherited `/Resources` is now resolved (bounded; cycle or depth over 64 is `malformed_content`), cloned, and the font added to the copy. `compose_candidate` compares the fonts, XObjects, graphics states, colour spaces, patterns, shadings and property lists each page resolves before and after and returns `verification_failed` if any is lost. **Consumer:** new `save::stage_prepared_save_against_base` makes the same check on the save path against the compose base bytes (additive; `stage_prepared_save` cannot see the source and is unchanged); call it from `prepare_pdf_save`.
- **3. `Q` restored the wrong font state.** `q`/`Q` now save and restore `Tf` (font and size), `Tc`, `Tw`, `Tz`, `TL`, `Ts` and `Tr` with the graphics state, and leave the text matrices alone. **Consumer:** islands after a `Q` that follows a state change inside `q ... Q` now take the restored font, size and spacing (their geometry and `appearance` change; the old values were wrong). `q` nesting over 65 536 is `malformed_content` (the stack is bounded because each entry now carries the text state).
- **4. `Tw` followed Unicode, not bytes.** Word spacing applies to the single-byte code 32 only, in decoding (`visit_text_show`), in the replacement measure (`EncodedRun::advance`, same-length and flattened deltas, the gap between regenerated words) and in the read-back; it never applies to a multi-byte (`Identity-H`) code. The pen jump `Tw` makes after a code-32 glyph is not read back as a word gap. **Consumer:** quads and fit checks change for fonts that map code 32 to a letter, put the space on another code, or use `Identity-H` with a CID that maps to a space.
- **5. Concurrent commits lost edits.** `commit_pdf_save` takes a per-destination lock across the source recheck, the replacement and the invalidation of other tokens staged against the written file. The second of two candidates staged against one source now fails with `write_conflict` instead of overwriting the first. **Consumer:** a successful commit now invalidates the other tokens staged against that file (`invalidate_source` was public but never called by the commit path).
- **6. Path aliases skipped the source recheck.** "Is the target the source?" is a filesystem-identity comparison (device and file id on Unix, canonical path elsewhere and as the fallback), so `dir/./memo.pdf`, a hard link, a symlink and a case variant on a case-insensitive volume are rechecked. New `save::resolve_commit_with` takes the comparison; `save::resolve_commit` keeps string equality.
- **7. Appended text inherited the page's text state.** The `AddText` and OCR text block now sets `Tr 0`, `Tc 0`, `Tw 0`, `Tz 100` and `Ts 0` inside its `q`/`Q`. **Consumer:** the appended stream has five more operators per block.
- **8. `/W` work was unbounded across ranges.** `/W` has a total assignment budget (2^20), as the `ToUnicode` reader does. A font whose `/W` ran out is displayed but `editable: false` (`missing_metrics`), and a code it has no width for is rejected instead of measured with the default.
- **CI fixes (first run).** `finding10_a_real_positioning_move_still_makes_the_gap_a_positioned_run` was wrong, not the provenance code: `0 0 Td` returns to the *line start* (ISO 32000-1 9.4.2), so "big" was drawn on top of "hello" and the page read as two islands. The test now moves by `28.33 0 Td` (where the adjustment would have put the pen), which keeps the case it names, and a new test pins the line-start behaviour. Two clippy findings fixed (`chars_last_cmp`, `manual_is_multiple_of`).
