# Changelog

## 0.3.0 (unpublished)

CodeRight's binary (`engine/bins/coderight`, 36356aa9b) is merged into this crate, so a host binary is a thin `main` that names itself and calls `run`. A fix, a hardening or a stricter check of CodeRight's applies to every host, and a product convention goes behind a host option that defaults to this crate's earlier behaviour. What CodeRight deliberately deleted is deleted here for every host (see "Deleted for every host"). Written, not compiled, and not yet reviewed after the fix pass below.

- Breaking: `run` takes only the `HostIdentity`. The skill catalog and the skill host are no longer passed: the slash-command table, custom commands and skill manifests are `rightkit-agent-skills`, and a host that wants its own skill catalog installs it with `rightkit-agent-host-traits` before `run`. `run` now also: scrubs the licence variables first, names the hook and terminal-UI crates from the configuration names, redacts crash reports with every key the host holds and keeps the newest 20, exits quietly with status 141 on a closed pipe, installs the stderr tracing (info for `serve`, off otherwise; the command word skips `-c`, `--config`, `--caller` and their values). A host names its environment prefix, state folder and display name (`rightkit_agent_config::ensure_host_names`) and sets the options of the shared crates first; the crate documentation lists the order.
- New public module `host_options` (once-per-process setters and getters, each defaulting to this crate's behaviour): `query_token_on_sse_route`, `yes_flag_is_auto_approve`, `custom_command_template_arguments`, `custom_commands_claude_user_folder`, `membrane_context_fills_window`, `message_origin_on_replies`, `role_model_split_open_to_all`, `license_enforced`, `stamp_event_schema_version`, `shared_user_skill_dirs`, `provider_keys_from_environment`, `doctor_block_exits_with_one`, `mcp_public_server`, `destructive_cli_verbs_need_yes`, `daemon_endpoint_from_environment`, `cloud_workspaces`, `guest_shares`, `lan_listener`, `browser_consent_routes`, `license_status_route`, `rpc_mode`, `remote_ssh`, `cli_contract`, `active_stream_limit`, `bundled_skills`, `tool_registry_controls`, `web_client_assets`, and, from the fix pass, `state_store_paths_from_environment`, `plugin_marketplace`, `adapt_routes`, `acp_server`, `legacy_auto_approve_flags`, `license_file_clock`, `legacy_token_header`, `unattended_turns_auto_safe`, `notifications_dropped_in_quiet_hours`, `embedder_runtime_setup`. The two options for CodeRight's context pull (`conductor_context_pull`, `memory_recall_unverified_items`) are gone: the code has one path, CodeRight's.
- New public `scrub_inherited_licence_env`: a host calls it right after naming itself; `run` repeats it harmlessly. `HostIdentity::with_version` sets the version the server reports (`--version`, health and status routes, crash reports, MCP server info, the call journal); without it the version of this library is reported.
- The tool registry controls (`host_options::set_tool_registry_controls`) run once on every registry the server builds (session tools, tool listing, driver gateways, onboarding), so a host can replace tools the shared tools crate registers with its own bounded versions.
- Sessions: `POST /sessions/{id}/clone` is gone (`fork` replaces it; the response fields are renamed); the event stream skips rows it cannot decode and lists them as `skippedSeqs`; rewind restores through the history store; approvals check authority, then the remember flag (400), then guest links (403), then the session (404); the 310 second approval timeout on Claude `can_use_tool` is dropped; sessions hold a lease and start-up marks sessions left running as interrupted. The CLI JSON error is `{error:{code,message,retryable}}` (`cli.error.v1` is gone); `--context-mode` is removed; `web` replaces `web-url`; `/cli-runtime/matrix-cell` and `cli-runtime` are removed; the plugin marketplace (routes, commands, provenance fields) stays behind `plugin_marketplace` and `mcp status` behind `mcp_public_server`; `acp-server` stays behind `acp_server`; `run` and `review` keep `--auto-approve` behind `legacy_auto_approve_flags`. `recipe run --auto-approve` and `run --bypass-approvals` are removed for every host. A removed command or flag is hidden from the help and refused as an unrecognised subcommand or unexpected argument.
- Daemon: the single-owner takeover is CodeRight's: it stops only the daemon the published discovery record names, through `rightkit_daemon::stop_identity` with the expected executable, and never bypasses the lock; the reload saga is `rightkit_daemon::reload` with CodeRight's launch and activation hooks (`daemon/reload.rs`, `daemon/lifecycle_backend.rs`); the worker journal is `.rkj` (an old `.jsonl` journal is removed at start); ordered shutdown and idle eviction take CodeRight's shapes (`HandoffAttempt`, `EvictionDrain`); the router carries no CORS layer, because the loopback host (`loopback_adapter`, over `rightkit_daemon::loopback`) applies CORS, the Host and Origin checks and the per-class request rate before it; `tower-http` and the `auth::RateLimiter` are gone.
- Optional modules a host turns on with options: the forge connection and cloud workspace routes, guest share links with the guest-only LAN listener (`serve --lan`, `discover`), the browser consent routes and `/browser-consent`, `GET /license/status`, the `rpc` command, the `ssh` command, the `contract` command with the per-call journal and dry-run receipts, and the `/web` client files.
- Other wire changes: process rows carry nullable lease fields; browser workspace errors have codes and named shared browser profiles are removed; the qualification matrix is `ops006.v2` (six more rows); schedule handlers return message bodies; new `/runtime/instincts` and `/runtime/admission-trace`; workspace skill routes `/workspace/skills*`.
- Fixes and hardening taken from CodeRight: a route's provider key is read only from the host's credential source (a name outside `<PREFIX>_<NAME>_API_KEY` finds nothing); the Github sign-in no longer reads the `gh` CLI or `GH_TOKEN`; scheduled runs in an untrusted workspace fail early, and an untrusted workspace gets no workflow mapping or admission; webhook and scheduled sessions run in `ask` (`auto-safe` where the host sets `unattended_turns_auto_safe`); the background provider and the projection are egress-checked (a private LAN base URL is refused unless approved); a LAN query-string token and an overflowing `share --expires` are refused; the per-workspace policy refuses paths the default deny list names; an approval card's letter keys decide only while the composer is empty, from 400 ms after the first draw (the 0.2.0 rule), so a key typed over a draft never decides it.
- Environment names that were literal `RIGHTKIT_` are read under the host's prefix: `A2A_EXECUTOR_URL`, `A2A_TRUST_ROOT_PUBKEY`, `A2A_DESCRIPTOR_JSON`, `WORKFLOW_SCHEDULE_CUTOVER`, `PEER_TEAM_STORE_ROOT`. The generic webhook header names in the API contract follow the host (`X-<App>-Signature-256`, `-Delivery-Id`, `-Event`). The ACP version refusal names the host.
- Dependencies: adds `rightkit-agent-skills` 0.2.0, `rightkit-agent-engine-history` 0.1.6, `rightkit-agent-tools` 0.4.4 (no default features), `tower` 0.5 (`util`), and the `lan-discovery` feature of `rightkit-daemon`; enables the `host` feature of `rightkit-agent-coding-tools`; drops `tower-http` and `rightkit-agent-host-traits`. Requirements are raised to the versions CodeRight's binary was built against: `rightkit-agent-config` 0.1.6, `rightkit-agent-engine-core` 0.2.1, `rightkit-agent-coding-tools` 0.2.1, `rightkit-agent-orchestration` 0.1.8, `rightkit-llm` 0.7.2, `rightkit-hooks` 0.3.1, `rightkit-agent-policy` 0.2.4, `rightkit-agent-engine-protocol` 0.4.1, `rightkit-agent-engine-storage` 0.3.1, `rightkit-agent-engine-attention` 0.2.2, `rightkit-memory-client` 0.1.1, `rightkit-bot-messaging` 0.3.2, `rightkit-daemon` 0.9.4 and the other path crates named in the manifest.
- Removed: the `dogfood_inventory` dump (CodeRight deleted `__dogfood-inventory`), the `Command::CliRuntime` definition, `DaemonState::gateway_credentials`, `ContextMode`, and the local `blueprint_tools` copy (the Membrane read aliases come from `rightkit-memory-client`). `memory_save` is this crate's own tool (`memory_save_tool`): it refuses every write whose origin is not the user's own session unless the operator approved that exact call (`rightkit_agent_policy::memory_write_is_authorized`), for every host; the shared tool of `rightkit-memory-client` asks only for outside content and writes provenance records, and is not registered.

## 0.1.0

- Initial release: engine binary library moved from CodeRight.
- Licensing: the daemon no longer reads the owner's credential store (preflight C3-05). It holds an
  `EngineSnapshotCell` and verifies the owner's snapshot with `EngineEntitlements::from_snapshot`
  over the owner's read-only anti-rollback ledger. The owner delivers the snapshot as a
  `rightkit_credentials::handoff` Reply frame to `POST /internal/license-snapshot` (per-launch
  bearer token) and gets the Ack frame back. Until the first delivery the gate is not Pro.
- The only licence launch locator is `RIGHTKIT_LICENSE_DIR`; `LicenseLocators` lost the credential
  service and account fields. `LicenseGate::open` no longer opens any credential store, and
  `with_parts` is replaced by `with_config`. The `rightkit-device` dependency is dropped and
  `rightkit-license` is used with `engine-snapshot` instead of `client`.
