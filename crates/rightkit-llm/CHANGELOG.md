# Changelog

## Unreleased

- Request-level response schema (Orthic-Labs/rightkit#584): `SchemaConstraint`, `ChatRequest::with_response_schema`, `ChatRequest::check_schema`, `ChatResponse::schema_output`. OpenAI-compatible routes send `response_format` (`json_schema`); Anthropic sends a synthetic forced tool. Combining a schema with `tools` or `force_tool` is `LlmError::InvalidRequest`.
- Public circuit breaker (Orthic-Labs/rightkit#659): module `breaker` (`CircuitBreaker`, `BreakerConfig`, `Phase`, `Outcome`).
- Public route health (Orthic-Labs/rightkit#660): module `health` (`RouteHealth`, `HealthPolicy`, `HealthState`, process registry `record_success`, `record_failure`, `state`, `snapshot`).
- Tool-call chunk reassembly (Orthic-Labs/rightkit#664): module `reassembler` (`ToolCallChunkReassembler`, `ReassembledToolCall`, `ReassembleError`).
- Image generation client and image-route catalogue (Orthic-Labs/rightkit#663): module `generation`. The images request and response field names are unverified against this repository.
- **Breaking:** `FailoverEvent` gains `breaker_skipped`. Routes skipped because their breaker is cooling now emit an event with `breaker_skipped: true`.

## 0.3.0

- Tool executor (Orthic-Labs/rightkit#297). New module `tools`: `ToolRegistry` (tool spec plus a `ToolHandler`, closures work), `ToolGate` (`AllowAll`, `AllowTools`, closures; no default gate, so allowing everything is explicit), `ToolBudget` (model rounds 8, tool calls 32, 64 KiB per result, 512 KiB total, optional token and wall-clock bounds) and `ToolExecutor`. `ToolExecutor::run(&provider, request)` loops model call, tool calls, one user message of `ToolResult` blocks in call order, next model call, until the model answers without a tool or a bound stops it (`StopCause`: `Completed`, `RoundLimit`, `CallLimit`, `ResultBytesLimit`, `TokenLimit`, `Deadline`, `Cancelled`; `Failed` only on error). Every call gets a result: a denied, unknown, failed, panicking or skipped call is an `is_error` result with the reason, and each is recorded in `ToolCallRecord` (`ToolOutcome`). `ToolExecutor::execute_round` runs one response's calls for hosts with their own loop. Tools are not run when a bound stops the run after a response that asked for them. A provider failure returns `ToolLoopError` with `partial` (rounds, transcript, records, summed usage with `usage_known`) so earlier spend is kept. Limits: bounds are checked between calls (a running handler is not interrupted, so a blocking handler needs its own timeout); tool input is not validated against the JSON schema; a handler panic is caught, a gate panic is not; calls run one at a time. Not included: a scene-detection tool for motion decode (needs a video decoder, which is the host's).
- Image and video-frame input on the model client (Orthic-Labs/rightkit#298). **Breaking:** `ContentBlock` gains `Image { source: ImageSource }`, so exhaustive matches need an arm. New module `image`: `ImageSource` (`Base64 { media_type, data }`, `Url { url }`, with `from_bytes`, `url` and `validate`), `Frame { image, at }` (label `Frame at 1.500 s:`), `SUPPORTED_MEDIA_TYPES` (`image/png`, `image/jpeg`, `image/gif`, `image/webp`) and `base64_encode`. Builders: `ContentBlock::image_bytes`, `image_url`, `Message::user_blocks`, `user_with_images`, `user_with_frames`, and `ChatRequest::has_images`. Anthropic sends `image` blocks with a `base64` or `url` source; OpenAI-compatible endpoints get a content-part array with `image_url` parts (a `data:` URL for base64), and a text-only user message keeps its plain string. Both providers validate images before sending and fail with `LlmError::InvalidRequest` (bad media type, empty or non-base64 data, non-http URL, image outside a user message); provider size and pixel limits are not enforced here. The CLI route rejects images with `CliError::Unsupported`. A tool result still carries text only. Not included: video decoding, frame extraction and scene detection (the host supplies frames).
- Versioned, dated, qualified price catalogue (Orthic-Labs/rightkit#302), in this crate: module `catalogue`, `PriceCatalogue`, `CatalogueRow`, `PriceKind` (`Llm`, `Transcriber`, `Scraper`, `Genright`, `PlatformFee`), `PriceUnit`, `PriceComponent`, `Qualification` (`Estimate < DocAsserted < Verified`), `CatalogueError`. The catalogue carries `schema` (1), `version` and `published`; each row carries its components, `effective_from` and optional `effective_until` (`YYYY-MM-DD`), `qualification`, `source` and `checked_on`. `price_at(kind, id, date, min)` returns the row in effect or a typed `Unpriced`, `NotInEffect`, `BelowQualification` or `BadDate`; there is no prefix match and no fallback to an older row. `llm_cost_at` prices a call and requires a cache component when the usage has cache tokens (no default multiplier). `llm_table_at` derives a `PriceTable` for a date and floor. `from_json` rejects bad dates, negative amounts, empty source or id, a repeated unit and overlapping windows; `merge` adds rows and refuses a same-start different row (`Conflict`) or an overlap. `PriceTable::from_rows` is new.
- What ships in the catalogue: `assets/price-catalogue.json` holds the 23 LLM rows of the bundled price table as `DocAsserted`, with no `checked_on` (a test keeps it equal to the bundled table). It holds no transcriber, scraper, GenRight or platform-fee prices: this crate has no sourced figures for them, so the host supplies those rows (`from_json` then `merge`). Cost scenarios S3 and S5 need those rows from their owners.
- Pricing no longer guesses or overrides silently (Orthic-Labs/rightkit#303). **Breaking:** `PriceTable::lookup`, `cost`, `cost_of`, `cache_savings` and `context_window` now match the normalized slug exactly; the longest-prefix fallback (`claude-sonnet-5-5` priced as `claude-sonnet-5`) is gone from them. It remains as the explicit `PriceTable::lookup_prefix` and `PriceMatch::LongestPrefix`. `PriceTable::merged_with` is removed: `merge` fails with `PriceError::Conflict { slug, existing, incoming }` on a same-slug row with different values (new and identical rows are accepted), and `merge_overriding` replaces on purpose and returns a `Vec<PriceOverride>` of every replaced row. `PriceTable::from_json` now returns `Result<_, PriceError>` (was `String`) and rejects duplicate normalized slugs and negative or non-finite prices.
- **Breaking:** `PriceError::Conflict` now carries `existing` and `incoming` as `Box<ModelPrice>` so `Result<_, PriceError>` stays small (clippy `result_large_err`). Field access auto-dereferences; code that builds `Conflict` by struct literal needs `Box::new`, and a pattern that binds a row by value needs `*`.
- New typed gate for a paid route: `PriceTable::require`, `try_cost` and `try_cost_of(&ChatResponse, PriceMatch)` return `PriceError::Unpriced { model }` for an unknown model; a per-token response is checked even when its usage is unknown, and a subscription-metered response is `Ok(None)`. `PriceTable::rows()` lists the rows. `PriceMatch` is `pricing::Match`.
- Usage and billing on failed attempts (Orthic-Labs/rightkit#304). `AttemptBilling { spend, metering }` with `Spend::{NotSpent, Reported(Usage), Unknown}` (new; `NotSpent` = nothing sent or an HTTP 4xx other than 408, `Unknown` = dispatched with no counts, `Reported` = counts the route sent). `LlmError::billing()` classifies any error; `ChatResponse::billing()` does the same for a response; a command-line route is `Metering::Subscription` (`CliError::spend()`). **Breaking:** `Attempt` gains `billing`, so `AllRoutesFailed` entries (and `CliAttempt::attempt`) say what each failed route may have cost; code that builds `Attempt` by struct literal needs the field.
- `ChatRequest::report_failed_usage()` (field `report_failed_usage`, default off). When set, a failure after the provider reported counts is returned as the new `LlmError::Billed { error, billing }`: a truncated or refused answer, an answer whose tool arguments do not parse, a stream that fails or is cancelled after its usage frame (Anthropic `message_start`, OpenAI final usage chunk). `root()`, `status()`, `raw()`, `is_failover_trigger()` and `Display` look through it, and it composes with `Captured`. Off by default so existing matches on `Truncated`, `Refused` and the others keep working; `LlmError` gains a variant, so exhaustive matches need an arm. The `Anthropic` stream assembler now keeps its usage when `finish` fails.
- The `cli` feature is part of this release as it stands in the tree (Orthic-Labs/rightkit#317): `provider::cli::CliProvider`, `CliSpec::claude_code` and `CliSpec::codex_exec` (stdin prompt, environment allow-list, wall-clock and idle timeouts, byte caps, process-tree kill, `CancelHandle`), unchanged from the 0.2.x `cli` code that Pulse already uses apart from the entries below. Nothing new was needed in code for #317: crates.io's latest is 0.2.1, so the open work is publishing 0.3.0. Pin with `rightkit-llm = { version = "=0.3.0", features = ["cli"] }`.
- CLI provider child now dies with its parent on every OS, SIGKILL of the host included (Orthic-Labs/rightkit#137). Linux: `kill_on_parent_exit(true)` (`PR_SET_PDEATHSIG`). Windows: the existing kill-on-close job object. macOS and other non-Linux Unix: `rightkit-child-process` has no parent-death primitive there, so the tool runs under a `/bin/sh` supervisor with a one-second watcher that kills the tool's process group when the host dies (up to about one second after the death). The tool's argv, stdin, stdout, stderr and exit status pass through unchanged. The graceful-stop wait asked for in #137 is not part of this change. Test `child_dies_when_the_parent_is_sigkilled` SIGKILLs a parent process that is mid-call and asserts the fake CLI and its background child exit.
- `provider::cli::CancelHandle` (new; `Clone`, shared flag): `cancel()` and `is_cancelled()`. `CliProvider::complete_detailed_cancellable(&req, &cancel)` runs one call that can be cancelled mid-run. A cancel kills the whole child process tree through `rightkit-child-process` is detected within one poll tick (about 25 ms); the call returns after the tree is reaped (about 300 ms grace, at most 5 s for a child that ignores TERM) with the new typed `CliError::Cancelled` ("CLI call was cancelled"). A handle cancelled before the call starts returns `Cancelled` without spawning the tool. If the tree cannot be confirmed dead, the error is `CliError::Kill` as for other bounds. `Cancelled` is not a failover trigger, and a cancel that lands after the tool exited but before its pipes drained still returns `Cancelled`. **Breaking:** `CliError` gains a variant and is now `#[non_exhaustive]` (one break, so later variants are additive), hence 0.3.0. The `Provider` trait and `complete_detailed` are unchanged.
- Claude Code answer-only preset (`CliSpec::claude_code`) now also passes `--disallowedTools "*"`. The CLI reference (https://code.claude.com/docs/en/cli-reference) says `--tools ""` disables built-in tools but "doesn't affect MCP tools"; `"*"` removes every tool, MCP included. The preset argv is now `-p --output-format json --no-session-persistence --disable-slash-commands --strict-mcp-config --setting-sources local --disallowedTools * --tools ""` (plus `--model <id>` when a model is named). Prompt still goes on stdin.
- Verified on Claude Code 2.1.300 (`claude --version`), against `claude --help` (read-only) and the CLI reference above: `--tools ""`, `--disallowedTools`, `--strict-mcp-config`, `--setting-sources`, `--disable-slash-commands` and `--no-session-persistence` are documented as stated. This is static verification: no model call was made, so the runtime "no tool runs" effect is not observed live.
- Contract test `claude_code_answer_only_preset_argv_is_exact` asserts the exact argv a stand-in `claude` receives. Cancel tests: a mid-run cancel kills a fake CLI and its background child, and a pre-cancelled handle spawns nothing.
- Comment on `CliSpec::claude_code` corrected to the verified CLI version (2.1.300; it previously cited 2.1.295).

## 0.2.1

- Republished on the renamed dependencies: `rightkit-child-process` (was `rightkit-process`). The 0.2.0 on crates.io was packaged before the renames and still named the old crates.
- Raw response capture for `complete()` (additive, off by default; for an on-device payload ledger). `with_raw_capture(max_body_bytes)` on `OpenAiCompatProvider` and `AnthropicProvider` keeps a `RawExchange` per call that got an HTTP response: `status`, `request_id` (`x-request-id`, else `request-id`), `attempts`, the body bytes up to the cap (`body`, `received_bytes`, `truncated`; a cap of 0 keeps no body), and `credential_removed`. `CallRecord` gains `raw: Option<&RawHandle>`, so the observer receives it for every such call, success or failure. `RawHandle` is `Arc<RawExchange>`; `RawExchange` is `#[non_exhaustive]` and its `Debug` prints sizes, not the body. The request side is unchanged: no credential and no auth header ever reaches the observer, and the exact credential text is replaced with `[redacted]` in the retained bytes. New module `raw` documents what the body can contain; the app owns that data.
- `LlmError::Captured { error, raw }` (new variant; exhaustive matches need an arm). With capture on, `Truncated` and `Malformed` are returned wrapped in it so they carry the same `RawHandle` the observer received; with capture off they are returned bare, as before. `LlmError::root()`, `raw()`, `is_truncated()` and `is_malformed()` look through it; `Display`, `status()` and `is_failover_trigger()` answer for the inner error, and `FailoverOn::matches` (including `FailoverOn::custom`) is applied to the inner error. Code that turns capture on and matches `LlmError::Truncated` or `Malformed` directly must match `err.root()` instead.
- Not covered: `stream()` (it reports `raw: None` and attaches nothing, whatever the setting), and the responses of attempts that `rightkit-http` retried inside one call (a `RawExchange` is the final attempt; `without_retries()` makes each attempt its own observed call).
- `CallRecord::request_body` and the observer contract are unchanged otherwise. `CallRecord` has a new public field, so code that builds one by struct literal needs `raw`.
- `ChatRequest` gains `retry: CallRetry`, `extra_body: ExtraBody` and `reject_truncated: bool`. Defaults keep the previous behaviour. Code that builds `ChatRequest` with a struct literal must switch to `ChatRequest::new` or `simple` (the struct is not `#[non_exhaustive]`).
- `ChatRequest::with_extra`, `with_extra_override`, `with_retry`, `without_retries`, `reject_truncated_output`. Extra top-level body fields are merged for both HTTP providers; a key the crate sets is rejected with `LlmError::InvalidRequest` unless it was added with `with_extra_override`.
- `CallRetry` (`Client` default, `Disabled`, `Policy(RetryPolicy)`) selects the attempt policy per call on both providers. `OpenAiCompatProvider` and `AnthropicProvider` previously had no per-call override.
- `LlmError` gains `Auth { status, message }` (rejected key on `list_models`), `InvalidRequest(String)` and `Truncated { output_tokens }`. Exhaustive matches on `LlmError` need the new arms. `is_failover_trigger` is unchanged for every existing variant.
- `FailoverOn` (`Retryable` default, `AnyError`, `custom`) with `FailoverChain::fail_over_on`. Under every policy a route that already delivered output is not failed over.
- `OpenAiCompatProvider::list_models` (`GET {base}/models`) and `validate_credential`, plus `openai::parse_model_ids`.
- NVIDIA NIM preset `nvidia` (`https://integrate.api.nvidia.com/v1`, from NVIDIA's public API documentation).
- `with_observer` on both HTTP providers: a `CallRecord` with the sent body and the response or error, never the credential or auth header.
- `ChatRequest::keep_empty_messages(bool)` (field `keep_empty_messages`, default `false`). Default keeps today's behaviour: an OpenAI-compatible user message with no text is dropped. With `true` it is sent as `""`. Anthropic has no empty content, so with `true` an empty message fails with `LlmError::InvalidRequest` before anything is sent; with the default the message is sent unchanged, as before. Struct literals of `ChatRequest` need the new field too.
- Behaviour change: an OpenAI-compatible `choices` answer is now two errors, both `LlmError::Malformed`. An absent or null `choices` is `"missing choices field"`; an empty array is `"empty choices array"`. Both were `"missing choices[0]"` before. Matches on the variant still work; text matches on the old message do not.
- Behaviour change: a first choice with no text (`content` null, absent or not a string), no tool call and no refusal is no longer `Ok("")`. It is `LlmError::Malformed("empty completion: ...")`. An explicit `""` is still accepted and returns `""`. A refusal, or a `finish_reason` of `content_filter` with no text and no tool call, is the new `LlmError::Refused { message }`, which is not a failover trigger. The streaming path is unchanged.
- `LlmError::Refused { message }` is a new variant. Exhaustive matches on `LlmError` need an arm for it.
- Behaviour change: `temperature` is written as its shortest decimal that round-trips the `f32`, so `0.3` goes on the wire as `0.3` (was `0.30000001192092896`). Both HTTP providers. The `with_temperature(f32)` signature is unchanged; `temperature` is the only `f32` request field.

## 0.2.0

- New `cli` feature (default off) and `provider::cli`: `CliProvider` runs an already-installed, already-signed-in assistant CLI (Claude Code `claude -p`, Codex `codex exec`) as a bounded child process through `rightkit-process`, so a daemon can draft text with no API key stored by the app. `CliSpec` describes the tool as data (absolute program path, fixed argument template, stdin or `--`-terminated prompt, text or JSON output with JSON-pointer usage extraction, environment allow-list, not-signed-in patterns); `CliSpec::claude_code` and `CliSpec::codex_exec` are presets. Bounded by wall-clock timeout, idle timeout and stdout/stderr byte caps; any bound kills the process tree. Typed `CliError` surfaces as `LlmError::Cli`.
- `provider` is now a directory module (`provider/mod.rs`); the public path `rightkit_llm::provider::Provider` is unchanged.
- `ChatResponse` gains `usage_known: bool` and `metering: Metering` (`PerToken` or `Subscription`). The HTTP providers set `PerToken`; `usage_known` is true when the response carried usage. This is a breaking change for code that builds `ChatResponse` by struct literal.
- `ToolSpec` gains `strict: bool` (default false) with `ToolSpec::new(..)` and `.strict(true)`. When set, the Anthropic builder sends `"strict": true` on the tool and the OpenAI-compatible builder on the function; when unset the request body is byte-identical to before. Breaking for code that builds `ToolSpec` by struct literal.
- Re-exports `rightkit_http` as `rightkit_llm::http`, plus `Client`, `ClientConfig`, `ProxyMode`, `RetryPolicy`, `AddressPolicy` and `HttpError` at the crate root, so hosts configure the transport without a direct `rightkit-http` dependency.
- `PriceTable::cost_of(&ChatResponse)` returns `None` for subscription-metered or unknown-usage responses.

## 0.1.0

- First release. Brand-neutral BYOK LLM clients: Anthropic Messages and OpenAI-compatible chat providers, streaming, tool use and forced-tool structured output, retryable-only route failover with a first-token timeout and circuit breaker, bundled model price table, and prompt-cache breakpoint discipline.
