# Changelog

## 0.2.1 (2026-11-16)

- Added `host`: `host::set_options(HostOptions)` installs once per process (first call wins; a refused call installs nothing) the places where a media host's shipped behaviour differs from the defaults. Every field defaults to today's behaviour, so a host that never calls it is unchanged: `app_name` (default none: the character messages say "This app" / "the app"; a host passes its own name and they read "<name> does not upload LoRA weights" and "Only the <name> app can approve it"), `training_approval_prefix` (default `rightkit-train-v1`: the first segment of the text hashed into a character-training plan id, so the approval basis and every token minted over it is the host's), `content_root_env` (default `RIGHTKIT_CONTENT_ROOT`: the variable the video templates read their content root from), `preflight_source` (default `video_preflight`: the preflight meta `source`, stored in the draft's `composed_meta` and `request.composer_meta` and therefore bound by the draft's approval), `video_brand_order` (default the order given to `brands::set_brands`: the order the video brand error lists the codes in), `omit_node_depends_on` (default `false`: leave `depends_on` out of each node status of `studio.recipes.catalogue`) and `overlay`.
- Added the data overlay (`HostOptions::overlay`): JSON keyed `recipes/<library>` or `video/<library>` merged over the embedded library by key before first use. Objects merge by key (recursively; keys the patch does not name stay, in place), arrays and scalars replace whole, `null` deletes the key, a patch for an unknown library is refused. The merged library is validated before anything is installed (it stays an object, `items` stay objects of objects, the built-in shot contract templates still pass `video_templates::validate_shot_contract`); `HostOptionsError::{AlreadySet, LibrariesInUse, InvalidOverlay}` says why a call was refused. `_brand_defaults` stays the business of `brands::set_brands`, which wins over a `_brand_defaults` key an overlay carries.
- Added `swap_templates::set_downloader(Box<dyn Fn(&str) -> Result<PathBuf, RecipeError> + Send + Sync>)` (feature `commands`): the host's URL downloader for `templates.import`. The error's `code`, `message` and `details` reach the caller unchanged. Without one, a URL import is `downloader_contract_unavailable` as before.
- `recipes::approval_inputs`, `recipes::tpl_approval_inputs` and `video_templates::approval_inputs` (feature `commands`) are public: the approval inputs and displayed hash of a stored draft, for a host's approval registration (`training_approval_inputs` already was).

## 0.2.0

- Changed (breaking): the default build is the pure library over the embedded data: contracts and validator, the recipe composer (`recipes::compose`, `compose_edit`, `libraries`), the image workflow catalogue, the character and LoRA lock data and the video shot-contract templates. It no longer depends on `rightkit-media-gen` or `rightkit-media-gen-approvals`. The `studio.<area>.*` command handlers (`commands`, `dispatch`, each module's `handle`) and the two modules that join the engine's registry (`recipe_catalogue`, `swap_templates`) are behind feature `commands`, a thin adapter over a `rightkit_media_gen::Context`.
- Changed (breaking): fallible calls return `RecipeError` / `RecipeResult` (same `{code, message, details?}` shape); with `commands` it converts to and from `rightkit_media_gen::GenError`, and `dispatch` still returns the engine's result type.
- Removed (breaking): `kdp` and `data/kdp` (one product's Kindle colouring-page workflow; it stays in the GenRight app) and `brands` with `data/brands/brands.json` (the owner's brand list and the `studio.brands.*` commands; the gallery's brand catalogue in `rightkit-media-gen` is the host-registered one).
- Added `brands` (new content): the host's brands. `brands::set_brands(Brands { codes, defaults })` installs the brand codes a request may carry and their per-library defaults (`recipes/<library>` and `video/<library>` keys); `NA` (no brand) is always accepted. The shipped data no longer carries the owner's `_brand_defaults`, brand list or venture list; `catalog::brands()`, the video venture check and the video brand check read the host's set.
- Removed owner brand names from the video template data (ad patterns, aesthetics, text overlays). The video preflight meta `source` is `video_preflight`.
- `studio.recipes.catalogue` reports each node's `depends_on`, so a UI reads the graph edges from the engine instead of embedding the seeded files.
- Taken on the recommended option of the 2026-11-11 shape review, pending the owner's confirmation (docs/audits/2026-11-11-shape-matrix/reports/genright-redraw.md).

Same calls, same records; a challenge issued before the move is not read (the app asks for a new one).
- Unit tests and debug-assertion switches removed (Adrian, 2026-11-03: end-to-end tests only; no debug assertions). Release behaviour unchanged.
