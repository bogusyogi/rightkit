# Changelog

## 0.1.0 (unreleased)

Verified on the Dell (Windows): the crate builds, the 83 unit tests, the doc test and the ignored desktop smoke test (`tests/windows_smoke.rs`) pass. The changes listed under "Review fixes" below were made after that run and are source-level until the integration owner reruns it, together with the new ignored `tests/windows_gdi_handles.rs` and a manual demo pass on a mixed-DPI host.

- New crate. `OverlayWindow` / `OverlayHandle`: a layered, topmost, never-activating Win32 window on its own owner thread, driven by queued commands (`set_frame`, `show`, `hide`, `set_painter`, `invalidate`, `animate`, `stop_animation`, `set_hit_regions`, `reassert_topmost`, `close`) and an event stream (`HoverEnter`, `HoverMove`, `HoverLeave`, `Click`, `DpiChanged`, `MonitorChanged`, `Closed`).
- Policy reused from `rightkit-overlay` 0.2.0: `OverlayStyle`, `HoverGate` (enter and leave debounce), `WorkArea::clamp`, `windows::create_overlay_window`, `apply_style`, `show_noactivate`, `hide`, `reassert_if_needed` and `monitor_at`.
- `PaintCtx`: premultiplied-BGRA software canvas in logical pixels with per-monitor DPI scaling. Rounded rectangles, strokes, discs, arcs, paths (non-zero and even-odd fill, round-joined strokes), GDI text with a string cache, level bars and a cached glass layer. `PaintCtx::offscreen` renders without a window.
- `PathCmd`, `parse_svg_path` and an `icons` set (line icons on a 24-unit grid).
- Animation: `Animation { duration_ms, easing, repeat }`, five easings, frames paced by `DwmFlush` only while an animation is active.
- Idle invariant: with no animation and the pointer away the owner thread blocks in `GetMessage` with no timer; the 40 ms hover leave-debounce timer exists only between the pointer leaving a region and the gate settling.
- Multi-monitor and per-monitor-v2 DPI: the owner thread is made per-monitor-v2 aware; the frame position is physical, its size logical and scaled by the monitor under it; `DpiChanged` and `MonitorChanged` are reported.
- Optional DWM backdrop (`Backdrop::Blur`, `Backdrop::Acrylic`), best effort and reported by `backdrop_applied`.
- Held-resource runtime class declared in `Cargo.toml`: one thread, one window, one DIB and one canvas per `OverlayWindow`, released on drop.

### Review fixes (after the adversarial review of the first import)

- Glass is bounded: the blur is clamped to 64 device pixels, a layer is at most 4096 pixels on a side and 2,000,000 pixels of padded area, 32 MB of build memory (16 bytes per pixel while built), a body that does not fit with its full shadow gets a narrower shadow, and a body too large even without one is not drawn. The size arithmetic is 64-bit, so no request can overflow `i32` or abort on allocation. Non-finite blur, radius and rectangles draw nothing or read as zero; nothing panics.
- Resizing is cheap: the DIB behind a window is grow-only with hysteresis (a quarter of headroom, given back only below half), the canvas is resized in place, and both are kept across size changes, so animating a window size no longer rebuilds the surface and drops the text and glass caches every frame. `Surface` publishes only the window part of a larger DIB.
- `PaintCtx::fill_squircle` and `stroke_squircle` (the Pulse continuous-curvature corner) and `blit_rgba` / `blit_premultiplied` (bilinear, source-over, clipped, edge-faded) were carried over from Pulse, with bounds tests. `NOTICE` no longer says they were left out.
- The glass look is parameterised: `GlassStyle { blur_px, tint, border: GlassBorder, highlight: GlassHighlight }` with `PaintCtx::glass_layer_styled`. `glass_layer(rect, radius, blur_px, tint)` keeps its signature and draws `GlassStyle::new(blur_px, tint)`, the look it always had. One visible difference: the rim width is now 1 logical pixel (it was 1 device pixel), so it is thicker at scales above 100%.
- Hit testing is edge-inclusive, matching `rightkit_overlay::Rect::contains` (it was half-open). `OverlayEvent` stays a separate type from `rightkit_overlay::OverlayEvent` (the pill state feed); the reason is documented on the type and in the README, along with the `Rect` convention (physical position, logical size) on `set_frame` and in the README.
- New ignored test `tests/windows_gdi_handles.rs` asserts that the process GDI object count and thread count return to baseline after creating, showing, animating, hiding and closing many overlays, that resizing a window 400 times does not accumulate GDI objects, and that the window class goes away with the last window.
- The owner thread always ends cleanly: a panic in the message loop is caught so `finish` still sends `Closed` and clears the handle. The published `HWND` is reset to 0 at `WM_DESTROY`, not at thread end. `tracking_leave` is reset when the window is hidden. The window class is reference-counted and unregistered when the last window of that name closes.
- `OverlayHandle` no longer drops a replaced painter (user code) while holding the command-queue lock, and `Shared::finish` drops the queued commands outside it.
- Event channels are bounded (`EVENT_CHANNEL_CAPACITY`, 256 per receiver): a reader that stops reading misses new events instead of growing memory without bound, and the receiver still disconnects when the window closes. The GDI font list is a bounded least-recently-used list (32), font sizes and text length are clamped, and a DIB whose bitmap cannot be selected is released rather than leaked.
- Close ordering: `Shared::finish` marks the window closed while holding the subscriber lock and `events()` checks closed and registers under the same lock, so a subscriber racing the close receives exactly one `Closed` (test `racing_subscriptions_receive_exactly_one_closed`). Delivery uses `try_send` on the bounded channels, so a full receiver never blocks the owner thread. The GDI font eviction test `lru_eviction_deletes_only_the_cold_font` checks that only the cold `HFONT` is deleted.
- Animation frames pause while the session is locked or disconnected (`WM_WTSSESSION_CHANGE`) and resume with one repaint when it is back. Occlusion by other windows is not detected.
- The comment on `SetThreadDpiAwarenessContext` now says it is a static import (Windows 10 1607+), not a run-time lookup that is ignored on older builds.
- `README.md` has an "API contract and deviations" section listing what the HeardRight native pill coded against and the shipped deviations. Non-Windows hosts allow dead code in the crate (`#![cfg_attr(not(windows), allow(dead_code))]`).
