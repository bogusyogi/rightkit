# Changelog

## 0.2.1

Taken from GenRight's shipped pipeline (`pipeline_workflows`, `brief.rs`, `caller_tag`) so it can delete its copies. Every default keeps RightKit's behaviour; each option is additive. Requires `rightkit-media-gen` 0.2.2.

- Added `PipelineHostConfig`, `configure_pipeline` and `pipeline_config` (set once at startup, beside `rightkit_media_gen::host::configure_media`): `producer` (the provider recorded in the facts of derived assets; default `rightkit-media-pipeline`), `engine_name` (the binary in the `brief run` usage; default none, `<engine>`), `finishing_app` (`FinishingApp { app, engine }`, default none: the neutral "timeline app" wording) and `qa_guard` (default `true`). GenRight calls `configure_pipeline(PipelineHostConfig { producer: "genright-pipeline".into(), engine_name: Some("genright-engine".into()), finishing_app: Some(FinishingApp { app: "CutRight".into(), engine: "cutright-engine".into() }), qa_guard: false })` and still registers its discovery with `finish::set_engine_resolver`.
- Added the Vox SFX cue feature (GenRight's, shipped first): the `sfx_cues` workflow input (a JSON array, or a string holding one, of `{prompt, at_s, gain_db?, duration_s?}`; at most 6 cues; `gain_db` -60 to 12, default -6; `duration_s` 1 to 120, default 4) expands the `vox_director` template with one optional `sfx_<n>` step per cue after `narration` (catalogued `fal` model `fal-ai/stable-audio-3/small/sfx/text-to-audio`, kind `sfx`, `MEDIA_KINDS` now includes `sfx`), and `finish` waits for all of them. The finishing step takes narration from the first audio outside the `sfx_<n>` steps and passes each succeeded cue's file with its `at_s` and `gain_db`, after any explicit `inputs.sfx`. A run with no cues is unchanged.
- Changed: the finishing step's title, summary, not-installed reason and hint, engine error text and `project_dir` message name the finishing app (`finishing_app`): default "Timeline finishing (optional)", "the finishing engine"; with `CutRight` / `cutright-engine`, GenRight's text ("CutRight finishing (optional)", "Install CutRight to finish through cutright-engine; the native GenRight composition is unchanged.", with `MediaHostConfig::app_name` `GenRight`). Step and command ids keep their `cutright_*` names.
- Changed: the Whisper overrides are read as `<PREFIX>_WHISPER` and `<PREFIX>_WHISPER_MODEL`, then the `RIGHTKIT_` names, and the "no whisper.cpp binary" / "no whisper model" messages and the ffmpeg readiness message name the host-prefixed variable (`GENRIGHT_WHISPER`, `GENRIGHT_WHISPER_MODEL`, `GENRIGHT_FFMPEG` under GenRight's prefix). Default prefix: unchanged.
- Changed: `brief run` registers the caller in the user's library with `Context::production_in(user_root)` (`rightkit-media-gen` 0.2.2), so a host with a context factory gets its own database (GenRight: `genright.sqlite3`, its credential store) instead of `media-gen.sqlite3`. No factory: `Context::new(user_root)` as before.
- Changed: the QA marker guard (`brief::qa_marked`: `<PREFIX>_QA`, then `RIGHTKIT_QA`, set and not `0`: refuse a run with no data folder, never register in the user's library) is read only while `qa_guard` is true (the default). GenRight has no QA marker and passes `qa_guard: false`, so the variable is never read there. The caller-tag commands follow the same rule.
- Added `brief::usage()`: `USAGE` with `<engine>` replaced by `engine_name` (`USAGE` stays neutral). The `brief run` refusal texts ("not produced by {app}", "no deliverable {app} produces", "{app}'s only 0 USD image route", "not a {app} deliverable") and the pipeline run-lock message ("another {app} process is changing pipeline run ...") name `MediaHostConfig::app_name` when set, the neutral text otherwise.
- Changelog: the 0.2.0 section had its entries under a stale "Unreleased" heading although 0.2.0 was published with them; they are folded under 0.2.0.

## 0.2.0

- Requires `rightkit-media-gen` 0.2.0 (breaking: the media-gen types this crate exposes come from the new major). The H.264 rule is `rightkit_ffmpeg::h264_rule` (compose, motion encode, media capabilities); `rightkit_media_gen::host::h264` was a copy and is gone. Same rule, same behaviour.
- Taken on the recommended option of the 2026-11-11 shape review, pending the owner's confirmation (docs/audits/2026-11-11-shape-matrix/reports/genright-redraw.md).
- Breaking (feature `motion`): requires `rightkit-motion` 0.4.0, whose `Encoder` `motion::encode::pick_encoder` and `pick_alpha_encoder` return. Version 0.2.0. Taken on the recommended option of the shape review (`docs/audits/2026-11-11-shape-matrix/reports/cut-post-redraw.md`), pending the owner's confirmation.
- The human-eyes gate (`eyes::review_gate`) comes from `rightkit-media-gen-approvals` 0.1.0, where the GenRight approvals moved when `rightkit-approvals` 0.2.0 became the one approvals core (decision 3 of the 2026-11-11 shape review, taken on the recommended option, pending the owner's confirmation). Same code, same behaviour.
- Follows rightkit-motion 0.3.0 (#1144): dependency requirement only; `ProjectServer::start` is unchanged. Its `ChromeSource` can move to `rightkit_motion::browser_source::BrowserFrameSource`.
- Follows rightkit-browser 0.3.9 (#921): the omit-background screenshot literal uses `..Default::default()` because `ScreenshotOptions` gained fields. Capture behaviour unchanged.
- Unit tests and debug-assertion switches removed (Adrian, 2026-11-03: end-to-end tests only; no debug assertions). Release behaviour unchanged.

## 0.1.0 (unreleased)

- First RightKit release, moved from `genright-studio` (genright).
- Feature `motion` (off by default): `motion`, the HyperFrames HTML-composition render the resident engine owns (`motion.status`, `motion.render`, `motion.cancel`; loopback `rightkit_motion::project_server`, managed headless Chrome through `rightkit-browser`, encode through `rightkit-motion`; `motion://progress` topic events), and `motion::encode` (ffmpeg resolution, encoder pick and the shared `h264_encoder_unavailable` shape), moved from `genright-engine` `motion_service.rs` and `motion_encode.rs`. GSAP is not bundled: `motion::set_gsap` registers the build to serve.
- `brief`: the engine side of `brief run` (RightKit content-brief in, validated delivery envelope out; keyless local-image stills and carousels only, human-eyes review gate through `rightkit-approvals`, project-local job state in `<project>/.<namespace>/`, caller registration in the user's library), and `caller_tag` (tagging `job run`/`generate` outputs with the named caller), moved from `genright-engine` `brief.rs` and `caller_tag.rs`. The `Engine::Genright` envelope value and the `genright.export-manifest.v1` manifest schema id are kept: they are contract and on-disk ids.
