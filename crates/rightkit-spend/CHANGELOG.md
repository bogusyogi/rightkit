# Changelog

## 0.2.0 (unreleased)

GenRight's ledger port (bogusyogi/rightkit#473, duplicate of #462): the semantics of `genright-gen/src/ledger.rs` now live in the crate so GenRight can delete its copy. Schema version 3 (migration `spend-caps-groups-budgets-reconcile`) is purely additive: new tables `spend_cap_audit`, `spend_groups`, `spend_group_legs`, `spend_device_allowances`, `spend_budget_tags`, `spend_adjustments`, `spend_provider_reported`, `spend_invoices`, `spend_invoice_lines`; no existing table, column or migration changes. Existing method signatures are unchanged. `ReserveOptions` gained private fields (read-only through the new builders), so a struct literal of it must use `..Default::default()` or the constructors; minor bump for the new API.

- **Carry-over.** `ReserveOptions::carry_over(true)` (and `Cap::carry_over(true)`) counts the open (`reserved`, `in_flight`) estimates of earlier periods of the same scope against the new period's cap. "Earlier" is text order on a period string of the same length, so a month never carries into a day. Committed, released and expired reservations do not carry. Not part of the request-id idempotency check.
- **Atomic multi-cap reserve.** `reserve_multi(request_id, &[Cap], route, price_version, estimate, &ReserveOptions)` holds one estimate against every cap under one request id, all or nothing, returning `GroupOutcome` (one `Outcome` per leg). The first refusal is `SpendError::CapRefused { scope, period, cause }` and no row, total, group record or budget tag is written. Idempotent on the request id (route, price version, estimate, options and caps must match, else `RequestMismatch`). Legs are ordinary reservations with request ids `<request_id>#<leg>`. `mark_in_flight_group`, `commit_group`, `release_group` settle every leg together; `group(request_id)` reads them back.
- **Epoch-reset device allowance.** `set_device_allowance(scope, device_id, Some(limit) | None, note)` starts a new epoch on every set or clear: a set creates a fresh allowance `device:<id>:<epoch>` with nothing counted, so spend and open reservations of earlier epochs stop counting (they settle on their own epoch's allowance); a clear lifts the cap. `Cap::device(scope, device_id)` resolves to the current epoch when `reserve_multi` runs; a device with no allowance set takes no leg. `device_allowance(scope, device_id)` reads it.
- **Budget scopes.** `Budget::new(key, limit_micro)`; `ReserveOptions::caller_budget(budget)` for one request's key and `Ledger::set_process_budget(Some(budget))` for every reservation made through the ledger value (a run). Counted as open estimates plus committed actuals of the reservations tagged with the key; checked after the caps, so a budget only ever refuses more (`SpendError::BudgetExceeded { kind, key, needed_micro, remaining_micro }`). A multi-cap reservation is tagged on its first leg, so its estimate counts once. `budget_spend(kind, key)`, `check_budget(kind, &budget, estimate)`.
- **Provider cost and invoices.** `record_provider_reported(id, micro, source)` stores the provider's figure beside the ledger and moves no cap. `adjust_actual(id, actual, source, note)` corrects a committed actual and the allowance's committed total in one compare-and-swap (past the limit if need be), follows the overrun flag to the new actual, clears `billed_unknown`, and writes a `spend_adjustments` row. `reconcile_invoice(&InvoiceInput)` records an invoice (reference-idempotent, `InvoiceConflict` on a changed provider, period or total), matches lines by reservation or request id for the provider (route id equal to it or starting `<provider>/`) and period (`created_at`), reports unmatched lines and reservations, never overwrites a line another invoice took, and with `adjust_committed` sets matched committed actuals to their invoice lines. `provider_reported(id)`, `invoice(ref)`.
- **Cap audit.** Every allowance create or limit change and every device-allowance set or clear writes a `spend_cap_audit` row in the same transaction (old and new limit, revision or epoch, note, `who` from `Ledger::with_actor`); `cap_audit(scope, limit)` reads it, newest first. A dropped `_in` transaction takes its audit rows with it.
- **Fail closed.** A stored allowance limit that is not a finite non-negative number (`inf`, `NaN` text, a negative) reads as 0, so the allowance refuses every non-zero reservation until the owner resets it through `set_allowance`. `micro_from_units(f64)` converts decimal units and rejects `NaN`, infinities and negatives.
- **Optional overrun gate.** `Ledger::with_overrun_gate(false)` / `set_overrun_gate`: overruns are still flagged, counted and acknowledgeable, but never block `reserve`. On by default.
- **Variants.** Every new write has `_in` (caller's `Transaction`) and `_on` (caller's `&Connection` with an open transaction, `NoActiveTransaction` otherwise) forms and runs in a savepoint: `reserve_multi`, `mark_in_flight_group`, `commit_group`, `release_group`, `set_device_allowance`, `record_provider_reported`, `adjust_actual`, `reconcile_invoice`.
- Semantics that differ from GenRight's `ledger.rs` are listed in the README ("Differences from GenRight's ledger").
- **`Scope` (Orthic-Labs/rightkit#328, PostRight gap 9).** New `Scope` (venture, channel, account) and `ScopeError`. `Scope::new` and `Scope::parse` validate (non-empty parts with no `/`, `:`, whitespace or control character); `key()` gives the opaque `venture/channel/account` string for the ledger's `scope` argument, and `namespaced("tokens" | "cache" | "spend" | "proof")` gives `namespace:venture/channel/account` so token, cache, spend and proof lookups of one scope share one identity. Additive; the ledger API is unchanged.
- Not compiled or run when written; verification is the lead's build and test run.

## 0.1.1 (2026-10-17)

PostRight's spend-ledger port needed five app shims; each is now native (bogusyogi/rightkit#471). Schema version 2 (migration `spend-account-currency-unknown`) adds three columns to `spend_reservations`; existing rows keep a NULL account and currency, and ceiling commits of expired in-flight leases become `billed_unknown`. Existing method signatures are unchanged. The new `Reservation` and `Report` fields are private and read through accessors (`Reservation::account`, `currency`, `billed_unknown`; `Report::billed_unknown`), so the public fields of 0.1.1 are unchanged. Struct literals and exhaustive destructuring of those two structs still fail to compile because of the private fields; the version bump that signals this is the lead's call, so the crate stays at 0.1.1 in this change.

- **`commit_unknown(id, reason)`.** Commits a `reserved` or `in_flight` reservation at its ceiling (the estimate) in one compare-and-swap and one row update, flagged `billed_unknown` and `over_reservation`, so `reserve` refuses (`OverrunUnacknowledged`) until `acknowledge_overrun`. `reason` defaults to `billed_unknown`. Repeating it on a billed-unknown row is a replay (strict mode: `InvalidTransition`); on any other settled row it is `InvalidTransition`. `Reservation::billed_unknown`, `Report::billed_unknown`. `expire_stale` now flags its ceiling commits `billed_unknown` too (same behaviour otherwise, reason still `lease_expired_in_flight`).
- **Account key.** `ReserveOptions { account, currency }` with `ReserveOptions::with_account(..)` and `.currency(..)`; `Ledger::reserve_with(.., &ReserveOptions)`. `reserve` is `reserve_with` with default options. `Reservation::account`. `expire_stale_account(scope, account, older_than_secs)` settles stale leases of one account only; `expire_stale` still takes every account of the scope.
- **Connection variants.** `set_allowance_on`, `reserve_on`, `mark_in_flight_on`, `commit_on`, `commit_unknown_on`, `release_on`, `expire_stale_on`, `expire_stale_account_on`, `acknowledge_overrun_on` take a `&rusqlite::Connection` that already has an open transaction, and run in a savepoint. In autocommit mode they return `SpendError::NoActiveTransaction` and write nothing.
- **Schema v2 backfill.** `billed_unknown` is backfilled only for rows that are `committed`, `over_reservation` and committed at their estimate, not for any row whose reason text is `lease_expired_in_flight`.
- **Caller transaction.** `Ledger::begin()` opens a `BEGIN IMMEDIATE` transaction on the ledger's connection. Every write has an `_in` variant taking `&rusqlite::Transaction` that neither commits nor rolls back: `set_allowance_in`, `reserve_in`, `mark_in_flight_in`, `commit_in`, `commit_unknown_in`, `release_in`, `expire_stale_in`, `expire_stale_account_in`, `acknowledge_overrun_in`. Each runs in a savepoint, so a failed call leaves none of its partial writes and the caller's transaction stays usable. Dropping the transaction rolls back the ledger and the app's sidecar rows together.
- **Strict mode.** `Ledger::with_strict(bool)`, `set_strict`, `is_strict`. In strict mode a repeated `release`, `commit` with the same actual, `commit_unknown` or `mark_in_flight` returns `InvalidTransition { from, to }` instead of the stored state. `reserve` by request id stays idempotent. Off by default.
- **Currency per reservation.** `ReserveOptions::currency` is stored on the reservation at reserve time and never rewritten (`Reservation::currency`). The account and currency are part of the request-id idempotency check (`RequestMismatch`). An allowance still holds no currency.
- Not compiled or run when written; verification is the lead's build and test run.

## 0.1.0 - unreleased

- New crate (Orthic-Labs/rightkit#301, PostRight RK-C1; second consumer: GenRight, which reserves against daily and monthly caps and a per-device offline allowance, `crates/genright-e2e/tests/paid_spend_allowance.rs`). `Ledger` (`attach`, `attach_with_clock`, `set_allowance`, `allowance`, `reserve`, `mark_in_flight`, `commit`, `release`, `expire_stale`, `acknowledge_overrun`, `report`, `reservation`), `Allowance`, `Reservation`, `ReservationState`, `Outcome`, `ExpireReport`, `Report`, `RouteTotal`, `SpendError`.
- Behaviour follows PostRight's engine spend ledger (`docs/SPEND-LEDGER.md`) apart from these differences: allowances are keyed by an opaque `(scope, period)` instead of venture, channel and month; the ledger holds no price rows and stores the route and price version it is given as opaque text; no currency is stored; `commit` with the same actual, `release` of a released reservation and a repeated `mark_in_flight` return the stored state instead of `invalid_transition`; `report().open_micro` counts `reserved` and `in_flight` estimates.
- Tables are `spend_allowances`, `spend_reservations`, `spend_overrun_acks`; the schema version is in `rightkit_spend_meta`.
- Not compiled or run when written; verification is the CI run.
