# Changelog

## 0.4.2 (2026-10-23)

- Catalog: new declaration-only capability `right-suite-api`, owned by `rightkit-license` (the Right Suite API host contract, rightkit#940). No source change.

## 0.4.1 (2026-10-23)

- **A catalog digest that differs from the digest pinned in protected trust is a warning, not a refusal (judge ruling; `decisions.md` 2026-10-15 retired ownership trust-sync, and `docs/OWNERSHIP-ENFORCEMENT.md` puts the catalog in the policy bundle).** `validate_ownership_floor` pushed `catalog digest below protected pinned digest` into the problems whenever `trust.minimumCatalogDigest` differed from the scanned catalog digest, which refused `RK_OWNERSHIP_POLICY_DOWNGRADE` with no way left to re-pin. It now reports `CATALOG_DIGEST_DRIFT_WARNING` (byte-identical to `@rightkit/release`'s constant) and admits.
  - Unchanged and still hard: the numeric `minimumScannerVersion` and `minimumCatalogVersion` floors (a missing, malformed or lower version refuses whatever the digest says), external-trust-unavailable, registration, signature, revocation and source-integrity checks. No trust-file write, automatic re-pin or bypass flag is added.
  - **BREAKING (source): `validate_ownership_floor` returns `OwnershipFloor { problems, warnings }` (with `ok()`) instead of `Result<(), Vec<String>>`; `Checked` gains `warnings: Vec<String>`.** The verdict carries the floor warning in `Decision.warnings` on an admitted result; evidence reports it in `Checked.warnings` (not in `result.warnings`), as `@rightkit/release` does.
  - Golden fixtures: `*-downgrade-catalog-digest-pin*` became `verdict-catalog-digest-pin-drift-warns`, `scan-catalog-digest-pin-drift-warns` and `verdict-catalog-digest-pin-match-quiet`; new cases cover a higher catalog version with drift (warns), and a below or malformed catalog version (refuses regardless of digest).

## 0.4.0 (2026-10-22)

- **New block-tier rule `appkit.autorelease.thread-loop-no-pool` (capability `appkit-autorelease-pool`, package `rightkit-ownership`; Orthic-Labs/rightkit#893, heardright#292).** A long-lived `std::thread` loop that calls AppKit, Accessibility (`AX*`) or CoreFoundation without an `objc2::rc::autoreleasepool` inside the loop fails the ownership scan in every macOS app. Minor bump: a scan that passed on 0.3.x can now fail, as with the 0.3.0 default-browser rules; neither this CHANGELOG nor the README states that new rules are patch-level.
  - Mechanism: new `src/autorelease.rs`, a native pass over each `.rs` file (the catalog fingerprints are single-pattern regular expressions and cannot match a thread closure, its loop and the absence of a pool inside it, and a regular expression that exhausts its backtracking budget reports no match, which would be a silent clean). It uses the comment and literal mask of `source_non_code`, matches brackets, and runs only when the scanned catalog declares the `appkit-autorelease-pool` capability, so the catalog digest still controls it. `scan_internal` calls it after the catalog source rules; findings have the source-finding shape (`file`, `line` = the spawn line, `lineText`, `ordinal`, `text` naming the API and the fix "drain objc2::rc::autoreleasepool once per loop iteration") and `ownershipVerdict`'s refusal text now appends that `text` for this rule.
  - Scope: `.rs` files whose path contains `/macos/` or `macos_` or ends `_macos.rs` or `/macos.rs`, or that name a non-negated `target_os = "macos"` in a `cfg` attribute. A non-macOS file never fails.
  - Detects: closures (or same-file functions named as the argument) passed to `thread::spawn`, `.spawn(..)` or `.spawn_scoped(..)`; every `loop` and `while` in them, also in same-file helpers they call (three hops); calls into `objc2_app_kit`, `objc2_application_services`, `objc2_core_foundation`, `core_foundation(_sys)`, `accessibility_sys`, `objc2_foundation::NS*`, `NS*`/`AX*`/`CF*` calls and `msg_send!`/`msg_send_id!`. A call is covered only by an `autoreleasepool(..)` that lies inside the loop body; a pool around the whole loop never drains and still fails. Not seen: helpers in other files, calls through trait objects or stored closures, methods on a value obtained outside the loop, `for` loops.
  - Exception: a plain entry in `.rightkit/ownership-exceptions.json` with `capability: "appkit-autorelease-pool"`, `package: "rightkit-ownership"`, optional `fingerprint` and `path`, plus `reason`, `owner`, `date`.
  - `scannerPolicyDigest` now covers `autorelease.rs`; the embedded catalog and `rightkit-ownership.json` declare the capability (declaration-only, no catalog fingerprints). The other catalog copies (`packages/release/rightkit-ownership.json`, `packages/build-control-policy/src/ownership-session-catalog.json`) must be regenerated to match; `embedded_catalog_matches_canonical_source` fails until they are.
  - Tests: `src/autorelease.rs` (fixtures in `tests/fixtures/appkit-autorelease/`), `autorelease_wiring_tests` and an exception test in `src/scan.rs`. Not compiled locally; CI is the compiler.

## 0.3.1 (2026-10-17)

- **Git URL classification fails closed; pinned-git records reach evidence (Astra wave 4).** `deps.rs` now classifies Git URLs with the `url` crate (schemes http, https, ssh, git and their `git+`/`ssh+` forms) and a separate scp parser (`[user@]host:org/repo`); the host is lowercased with default and explicit ports, userinfo and a trailing dot removed, so `https://github.com:443/Orthic-Labs/x` and `ssh://git@github.com:2222/Orthic-Labs/x` are first-party. `file:`, other schemes, local or path-like text, `localhost`, IP literals, numeric or escaped org segments and unparseable text are treated as first-party, so they stay fatal `git-dependency-source` gaps. `Scanned` gains `coverage_notes`, built from `DepsResult.covered` as `{path, status: "pinned-git-dependency", reason, fingerprint, scanned: false}` (the field shape of `deps.covered` in `ownership.mjs`); they appear as `coverageNotes` in the report, in `metadata`, and in the aggregated evidence result, are never counted as coverage gaps, and `verdict.rs` validates them (status must be `pinned-git-dependency`, `scanned` must be `false`). Not built or run here.
- **BREAKING (source): `DepsResult` has a new required public field `covered: Vec<Covered>`.** Code that builds or exhaustively destructures `DepsResult` (or `Scanned`, which gained `coverage_notes`) must add the field or use `..`. Nothing in this repository constructs either outside the crate.

- **Pinned third-party Git dependencies are not a fatal gap (mirror of Orthic-Labs/rightkit#677).** In `deps.rs`, a Cargo Git dependency with a full 40-hex `rev` (and no `branch`/`tag`) whose URL host/org is not first-party is recorded on `DepsResult.covered` as `pinned-git-dependency` (`scanned: false`, fingerprint `<url>@<rev>`) instead of a `git-dependency-source:<name>` coverage gap. First-party URLs (github.com/Orthic-Labs, github.com/bogusyogi), unparseable URLs, branches, tags, short revs and missing revs stay unscanned gaps. `DepsResult` gains a `covered` field. Tests in `deps.rs`. Not built or run here.

## 0.3.1

- **Inventory hashing runs on a bounded shared pool and reuses unchanged inputs (Orthic-Labs/rightkit#336).** `git_listed_inventory` reads and hashes dirty inputs on at most `min(4, cores)` workers, shared by every inventory in the process (`inventory_worker_limit`, `peak_hash_workers`), not per call. A dirty input read and hashed once is kept (64 MiB total) and reused while its size and mtime are unchanged; it is never kept when size or mtime moved while it was read or when it was modified within the last 2 seconds, and a changed, deleted or replaced file is read again. Ordering, digests, coverage and the lock-root and `pnpm-workspace.yaml` inputs are unchanged, and `packages/release/ownership-git-inventory.mjs` behaves the same (it is single-threaded, so it hashes one input at a time). `clear_inventory_cache` drops every kept input. Tests: `inventory_hash_workers_are_bounded_and_shared`, `inventory_reuses_inputs_only_while_size_and_mtime_hold`, `inventory_never_keeps_a_file_modified_inside_the_racy_window` in `src/tests.rs`. Not built or run here.

## 0.3.0

- **Catalog: default-browser sign-in rule (Orthic-Labs/rightkit#279).** Three block-tier source fingerprints under `oauth-sign-in` flag an app rendering an auth URL in its own webview: `oauth.webview.auth-url-load` (WebviewWindowBuilder / WebviewUrl::External / WKWebView / loadRequest / loadUrl / navigate / eval with accounts.google.com, appleid.apple.com or /oauth/authorize on the line), `oauth.webview.on-navigation-intercept` (`on_navigation` with a code/redirect_uri/oauth/token hint) and `oauth.webview.bundled-chromium-login` (chromiumoxide, headless_chrome or CEF with an auth URL). The four byte-identical catalog copies and the rightkit-oauth manifest carry them. Test `oauth_webview_rules` in `tests/ownership_fixtures.rs`. Not built or run here.

## 0.2.4

- **Pending approval enrollment is a reported warning everywhere (Orthic-Labs/rightkit#262).** `ownership_verdict` no longer refuses on `enrollmentPending` (`PENDING_ENROLLMENT` is never produced); with pending enrollment and no trust it skips the registry and floor checks, and `Decision` gains `warnings`, which `decision_json` emits when non-empty. `create_evidence`: `ok` ignores pending enrollment, an absent trust registry is no longer a floor failure, and registration diagnostics and stale exception warnings go to `result["warnings"]` (only when non-empty) instead of `problems`. `Scanner::scan_protected` no longer short-circuits on a pending preflight. Real finding, coverage, floor and registry gates are unchanged. Tests and the shared Node fixtures were updated (not built or run here).

## 0.2.3

- **Plain exception entries; signed exceptions retired (Orthic-Labs/rightkit#262).** `scan.rs` reads the same plain entries as `packages/release/ownership.mjs` (`{capability, package or crate, reason, owner, date}`, optional `fingerprint` and `path`), matches them the same way, marks every matching finding `excepted`, and reports an entry that matches no finding as a stale warning (`exception #N (capability/package): stale, matches no current finding (...)`). A missing field or a legacy signed record (`schema`/`payload`/`signature`) is a problem. `verify_exception`, `ExceptionContext` and the exception signature check are removed from `approval.rs`; key-log, trust-registry, floor and provenance code is unchanged.
- **Pending enrollment no longer blocks `check_app` / `check_committed`.** It was only needed for signed approvals; it is now a warning and `ok` ignores it. The report keeps `enrollmentPending: false` from these entry points.
- Tests: `exception_tests` in `scan.rs` (plain match, alias/fingerprint/path narrowing, stale warning, malformed and legacy entries, duplicate entries, enrollment warning). Not built or run here.
