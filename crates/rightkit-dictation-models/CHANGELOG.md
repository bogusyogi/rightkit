## 0.3.0

- Add host-configured `model_flow` archive & shared-store download orchestration with host-owned progress text, byte limits & activation.

Closes the 2026-11-19 owner findings on this crate (every delete confined to a verified directory, shared reference updates under the store's lock, private-network grants restricted, cache identifier validated, downloads and extraction bounded, child waits bounded). Source only: not compiled or run here.

- Breaking, API: `resumable_download::DownloadRequest` and `RefreshingDownloadRequest` gain `max_bytes` (`1..=MAX_DOWNLOAD_BYTES_CEILING`, 16 GiB); `archive_install::install_single_top_level_tar_gz` and `_as` gain `limits: &ExtractLimits` (build one with `archive_install::extract_limits`; names must satisfy `archive_install::is_plain_name`); `whisper_model::partial_archive_path` returns `Result<PathBuf, String>` (refuses a model name that is not a plain name and a digest that is not 64 hex digits); `model_fetch::download_and_verify` gains `max_bytes` and returns the bytes received; `resumable_download::unlimited_download_client` is replaced by `streaming_download_client` (30 s connect, 60 s headers, 120 s without a body byte, 6 h in all; it had no limit). Requires `rightkit-models` 0.7.2 (bounded extraction).
- Every delete goes through pinned directory handles (`confined_remove`, private): the ANE cache prune and the explicit Core ML cache clear, the retired Windows and macOS model reclaim, the retired Unified reclaim, the retired-model leftovers, the activation-record and reclaim markers, the verified-archive discard and the model-fetch temp file. The root is opened one component at a time without following a link, each child is opened through its parent's handle, a link inside a tree is removed as the link and never entered, and a tree removal is bounded (32 levels, 20 000 entries). A data folder reached through a link is not cleaned up. The explicit cache clear still fails when an entry cannot be removed, and its message no longer carries a path.
- `shared`: other apps' `refs/*.json` are updated only under the store's registry guards (`refs::acquire_registries`, then `refs::strip_ids_all_locked`), in every registry the store answers to; before, `strip_foreign_speech_refs` rewrote them with no lock. The activation record is read through one capped handle (64 KiB).
- `model_download_grant::acquire_model_grant`: the worker base must be a plain `https://` origin and the grant request always uses the public-web address policy. Before, any host other than the compiled-in one got the private-address policy lifted. Only a build with the non-default `dev-worker-override` feature may reach the one host named by `RIGHTKIT_MODEL_WORKER_BASE` at a local address. The grant token is bounded (8 KiB, no control character). The compiled-in worker host constant is removed.
- `ane_cache_prune`: `is_valid_bundle_identifier` and `MAX_BUNDLE_IDENTIFIER_LEN` are new; `configure_bundle_identifier` returns false and configures nothing for an identifier that is not one plain name (ASCII letters, digits, `.`, `-`, `_`, at most 128 bytes, no `..`), so the cache helpers stay inert. Before, the identifier was joined into the path that was deleted from unchecked.
- Downloads: the archive download is capped at `max_bytes` (the size the server reports before any byte is written, and the bytes received while streaming), a completed archive already on disk is measured and hashed through one handle and discarded if larger than the cap, and the model-fetch download writes through a limit and `create_new`, hashing while it writes. The shared store's transport (`shared::http_client`) has stall limits. The model-fetch manifest is read through a capped handle and bounded (256 files, 4 GiB a file, 16 GiB in all, https only), and `ensure_model` and `load_manifest` refuse a name that is not one path component.
- Extraction: `install_single_top_level_tar_gz*` stops at the first member or byte past the host's limits (members, bytes per file, bytes in all), and refuses limits above 20 000 members or 32 GiB; `recover_orphaned_previous_install` refuses a name that is not a plain name before any path is built. The Whisper archive uses ceilings of 4 GiB / 8 GiB (macOS) and 2 GiB / 4 GiB (Windows) that are not measured against the real archives.
- Child process and preparation: `whisper_model::download_whisper_model_within(host, budget)` (new) and `download_whisper_model_blocking` (unchanged signature) fix one absolute deadline when the caller enters; waiting for the model's operation gate (`try_lock`, no unbounded acquisition), admission to the preparation, the macOS `prepare-whisper` run and its termination are each given only what is left, and the typed `WhisperModelError::{Timeout, PreparationUnreaped, Failed}` is returned when it passes. Preparation is single-flight per model (`Idle`, `Running` with a shared result, `Spawning`, `Done`, `Unreaped`): callers that arrive while it runs wait on that result for their remaining time and never start a second preparation, and a failed run is retried only by a later call. The engine is started on a module-owned spawn thread, because `OwnedCommand::spawn` with `kill_on_parent_exit(true)` can block inside `rightkit-child-process` without a bound: the caller waits for it only until the end of the run window, and a child the spawn returns later is terminated and parked through the reaper path, never dropped; the model is `Spawning`, then `Unreaped` (`spawn_pending`, or `spawn_failed_after_launch` when the crate reports a failure after it launched something) and refuses a new preparation until the spawn is resolved. The engine is stopped with `OwnedChild::terminate_tree_bounded` (no unbounded wait) and tied to the process with `kill_on_parent_exit(true)`, which is lifecycle policy (an app-owned engine stops with its parent), best effort (the watchdog can exit when the leader exits before it sends the group KILL, so a same-group helper can survive the parent's death) and not retirement proof. A child without the group-empty evidence by the deadline is handed to one module-owned reaper thread (at most 4 outstanding) and the model's preparation is refused with `PreparationUnreaped` until that evidence: the leader reaped by `terminate_tree_bounded` and the engine's process group then observed to have no members (`wait_process_group_empty`). That evidence shows only the group's membership at that moment: a descendant that left the group, and work an OS daemon does on the engine's behalf, are not covered and not claimed stopped. A reaper error, a failed thread start and a full or disconnected queue keep the model `Unreaped` (stable reason codes, `whisper_preparation_unreaped_code()`), and the next preparation attempt retries the stop within its own deadline. The download is cut off by the same deadline, passed down as an absolute instant (`resumable_download::download_resumable_by`, `rightkit_models::download::download_resumable_capped_by`): each request's timeout, each pause, each wait for body bytes and the check before each chunk is derived from that instant when it starts, not from a duration taken before the entitlement and file-system work; the extraction cannot be interrupted and is bounded by its size limits. The operation gate is released before the compile. The call's entry instant is taken before the gate is waited for, so callers already queued behind a run that fails take its result instead of starting another; a zero or spent budget returns `Timeout` before the gate, the download, the choice of runner and the engine's spawn; an install into the model's directory is refused while an engine process of that model is not confirmed gone; the engine child is never dropped alive and its drop wait is zero (set on the spawn thread before the child is handed over). Before, the wait had no bound, ran under the gate, and each queued caller could restart the compile.
- `whisper_model::model_operation_lock` keeps at most 64 gates; later names share one.
