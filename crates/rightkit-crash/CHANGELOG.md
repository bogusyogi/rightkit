# Changelog

## 0.2.2

- Owner gap OG16-5, Rust side (additive, default off, no new dependency). Feature `window-errors`: `record_window_error(&CrashConfig, &WindowErrorGate, &WindowErrorReport)` records a renderer error forwarded by the webview as a `window_error` or `window_rejection` report with `process_kind = window`, through `record_report` (owner scrub, `redact_values`, retention, sink). The webview is an untrusted caller, so the message (1000 chars), stack (8 KiB) and source (query and fragment stripped) are bounded again, and `WindowErrorGate` allows at most 5 reports per minute and 25 per process by default. The app registers its own Tauri command that deserializes a `WindowErrorReport` and calls it; nothing is recorded until it does. The JavaScript half is `installWindowCrashCapture` in `@rightkit/logs`.

- Owner gaps OG16-7, OG16-9, OG16-2 (additive, no breaking change). `CrashConfig::redact_values(Vec<String>)`: app-supplied known secrets (API keys, database keys, tokens) are replaced with `[redacted]` in every report field, the final serialized value handed to the file and the sink, and the macOS native sample text, on top of the pattern scrub (empty strings ignored; `Debug` never prints them; same contract as `rightkit-http` `ClientConfig::redact_values`). Fallback crash directory: when `crash_dir` cannot be created or written, reports go to a private per-app folder in the OS temp directory (`fallback_crash_dir(app_name)`, `0700` on Unix, refused if it is a symlink or not the current user's), announced by one `rightkit-crash:` stderr line; if the fallback is also unusable the stderr line says no report file was written. Apps list it at next launch with `list_pending(&fallback_crash_dir(app))`. `capture_native_for_pid(&CrashConfig, kind, pid)`: native sample (macOS) or minidump (Windows) of a child process the parent names, through the same single-flight guard and, on macOS, the same scrub-before-publish path as the panic hook; the Windows dump stays unscrubbed and local. The helper must still be alive when called.
- Process-kind coverage. Additive: `ProcessKind` (`Window`, `Engine`, `Helper`), `CrashConfig::process_kind`, `install_process_hook` (one install path per process kind) and `record_helper_exit` (supervisor-side report for a helper that exits abnormally, with helper name, exit status and restart count). Reports carry an optional `process_kind` (omitted when unset; older reports still parse). Breaking: none.
- macOS native sample privacy fix. `sample` now writes to a hidden, owner-only raw file (`.sample_raw_*.raw`) that the support bundle, `prune` and `list_pending` do not match; only scrubbed bytes are published, atomically and owner-only, as `sample_*.txt`. Previously a failed read or write during scrubbing left the unscrubbed sample under a bundle-eligible name and still reported it as captured. Now any failure returns `None`, deletes the raw file, keeps nothing and is reported through the new additive `CrashReport::native_capture_note` field (omitted from JSON when empty; older reports still parse) and one `rightkit-crash:` stderr line. `prune` and the next macOS capture sweep raw files older than five minutes. Windows minidumps are unchanged (never scrubbed, bundled only on explicit opt-in); the README now says so. Breaking: none (new public field on `CrashReport`, which apps do not construct themselves).
- Panic hook fixes (consumer-reported). A sink whose thread cannot be spawned now runs inline instead of losing the record; the re-entrancy guard is per thread, so a panic on another thread during a slow sink is recorded (the sink thread holds its own guard, so a sink panic still cannot recurse); the file record is written before the sink runs, so under `panic = "abort"` it survives a panicking sink, and `with_sink` documents unwind-only containment; sink-only mode no longer creates `crash_dir`. Additive: `CrashConfig::capture_backtrace(bool)` (default `true`, unchanged behaviour) skips the unbounded backtrace capture in the panic hook. `rightkit-logs` requirement raised to `0.2.2`. Breaking: none.
- Panic capture hardening: the re-entrancy flag is cleared by a drop guard, so a failed record no longer disables later reports; reports are written owner-only (0600 on Unix, current-user-only DACL on Windows) through `rightkit-fs` atomic writes; `set_recording_enabled` / `recording_enabled` add a runtime off switch (default on). Additive: `CrashConfig::with_sink` hands each redacted report to a host callback (run on a bounded thread, so a sink panic is contained), and `CrashConfig::write_report_file(false)` turns off the `crash_dir` file. Breaking: none.

## 0.2.1

- **`support-bundle` feature (default on).** The `zip` dependency is now optional behind `support-bundle`, which gates `build_support_bundle`, `SupportBundleOptions`, `BundleManifest` and `create_zip` (about 200 lines). Panic capture, pending-report handoff, native capture and retention are unchanged without it. Default builds are unchanged.
