# Changelog

## 0.3.6 — 2026-10-21

- Hang watchdog review fixes: the native capture removes the configured `redact_values` from the macOS sample; recording consent, the stop flag and the loop's registration are re-checked right before each write step; a late check is detected by more than max(2 intervals, 1 interval + 250 ms) since the previous check (first check measured from start), independent of the threshold; a loop whose last `Heartbeat` dropped is skipped via an atomic flag (the drop never waits for a report and briefly takes the registry lock; a report already in progress may still complete); hangs no longer use the `CrashConfig` sink: new `HangOptions::on_hang(Fn(&HangEvent))` and `HangEvent` (loop name, stall duration, report path, recovered flag) are called synchronously on the watchdog thread for each hang and recovery, and callbacks must return promptly; `stop()`/drop set stop and wait for the watchdog thread, including any `on_hang` callback and native capture in progress, so once it returns no callback runs and nothing is written; report, sample, dump and hang-tail file names gain a process-wide sequence number (`next_file_seq`) so reports within one second never overwrite each other; the crate is declared `continuous = "held-resource"` with a resources table.
- A check that runs far later than scheduled (system sleep, suspended process) is skipped, so resuming from sleep is not reported as a hang. On Windows the all-threads minidump needs the `rightkit-dump-helper` binary next to the app (see `set_dump_helper`); without it the hang report is still written.
- Loop names have configured secrets removed before filtering; a hang skipped while recording was off is reported once it is back on.
- Added: hang watchdog (resolves #882), additive and non-breaking. `HangWatchdog::start(config, HangOptions)`, `HangWatchdog::heartbeat(name) -> Heartbeat` (`beat()` is one atomic store; dropping the last clone unregisters the loop), `HangWatchdog::pump_via(name, post)` for event loops the app cannot beat itself (Tauri: `run_on_main_thread`), `stop()`/drop joins promptly. A loop silent for the threshold (default 10 s, minimum 2 s) records one `hang` report per episode through `record_report`, takes the all-threads native capture (Windows minidump, macOS `sample`; on by default), writes the scrubbed tail of the configured log files to an owner-only `sample_hang_logs_*.txt`, and logs `hang` and `hang-recovered` lines on stderr. Respects `set_recording_enabled`. Adds a watcher thread (`rightkit-hang-watchdog`) and, for `pump_via`, a poster thread (`rightkit-hang-pump`) per call; neither runs unless the app starts the watchdog. Tests not run here.

## 0.3.5 — 2026-10-21

- Fixed: renderer report limits no longer truncate credentials before redaction. Oversized fields and query/fragment-bearing sources are omitted; intact accepted fields retain shared scrubbing. Field inspection stays bounded. Regression coverage includes generic and configured secrets crossing caps or source delimiters, plus UTF-8 boundaries (#841).

## 0.3.4 — 2026-10-20

- Changed: known-value redaction (`CrashConfig::redact_values`) now uses `rightkit_logs::KnownSecrets` instead of a private copy. A secret is also removed in its percent-encoded and JSON- or Debug-escaped forms, and overlapping secrets leave no fragment. Requires `rightkit-logs` 0.3.4 (the manifest floor; `KnownSecrets` is public from 0.3.4). Test: `report::tests::encoded_and_escaped_forms_of_a_known_secret_are_removed_from_a_report`.

## 0.3.3 (published)

- Serializes idempotent crash-report handoff.
- Changed: `chain_default_hook` now defaults to `false` in release builds, so a panic payload no longer reaches stderr unless the app opts in; builds with debug assertions still chain. `chain_default_hook(true)` restores the old release behaviour.


## 0.3.2 (2026-10-17)

- **Non-chaining panic hook (rightkit#513).** New `CrashConfig::chain_default_hook(bool)` (default `true`, nothing changes). With `false` the panic hook does not call the previous hook; it writes one fixed stderr line that names the app and says a crash report was recorded, so the panic payload is not printed. Additive: the struct keeps its private fields and `new`. Tests not run here.
- **Scrub-before-bundle (#227), already in place.** Support bundles scrub every `sample_*` text on its way in (`bundle.rs:119-123`, test `an_unscrubbed_sample_in_the_crash_folder_is_scrubbed_on_its_way_into_the_bundle`). No code change in this entry.

## 0.3.2

- Android native-crash and ANR records (Orthic-Labs/rightkit#156): `record_android_exits`, `AndroidExit`, `AndroidExitReason`, `reduce_trace`, `unseen_exits`. The Kotlin shell passes the entries of `getHistoricalProcessExitReasons` (crash 4, native crash 5, ANR 6) at launch; each unseen one becomes a redacted report through `record_report`, with a cursor file so it is recorded once. Tombstone traces keep the header and backtrace only (stack contents, memory, registers, memory map, open files and logs are dropped). The OS detects the ANR, so no thread of ours runs and no `unsafe` signal handler exists. No new dependency; the logic is host-tested on every OS, the Android shell side is not built or run. The Windows dump helper and the `support-bundle` and `window-errors` features are not needed on Android (use `--no-default-features`).

## 0.3.1

- Privacy fix (#227), macOS native sample: no unscrubbed byte is ever written to the crash folder, the folder a support bundle is built from. `sample` now writes to a private `0700` directory in the OS temp directory (refused if it would fall inside the crash folder) that is deleted on every path; the old hidden `.sample_raw_*.raw` file inside the crash folder is gone. When scrubbing fails (read error, scrubber panic, or a `redact_values` secret still present in the output) the sample is dropped and the `sample_*.txt` file holds only `sample withheld: scrub failed`, with `native_capture_note` set to `sample_scrub_failed` or `sample_read_failed`. If even that file cannot be written the capture returns `None` (`sample_publish_failed`). `prune` and the next capture also sweep stale raw directories from the temp directory and leftover `.sample_raw_*.raw` from 0.3.0 and earlier.
- Support bundle: `sample_*` text copied under `include_native_dumps` is scrubbed again on the way in (an older release may have left one unscrubbed), written straight from memory to staging, and replaced by the marker if that fails. Windows minidumps are unchanged.
- Tests (run on every host, not only macOS): fixture with home paths, an email, a token and a bearer credential is scrubbed before it reaches the crash folder; a scrubber panic, a leaky scrubber and an unreadable raw file each yield the marker and never raw text; no file under the crash folder or the temp base holds raw fixture data; raw directory is private, outside the crash folder and deleted; bundle re-scrub test reads the produced ZIP. Breaking: none.

## 0.2.2

- Owner gap OG16-5, Rust side (additive, default off, no new dependency). Feature `window-errors`: `record_window_error(&CrashConfig, &WindowErrorGate, &WindowErrorReport)` records a renderer error forwarded by the webview as a `window_error` or `window_rejection` report with `process_kind = window`, through `record_report` (owner scrub, `redact_values`, retention, sink). The webview is an untrusted caller, so the message (1000 chars), stack (8 KiB) and source (query and fragment stripped) are bounded again, and `WindowErrorGate` allows at most 5 reports per minute and 25 per process by default. The app registers its own Tauri command that deserializes a `WindowErrorReport` and calls it; nothing is recorded until it does. The JavaScript half is `installWindowCrashCapture` in `@rightkit/logs`.

- Owner gaps OG16-7, OG16-9, OG16-2 (additive, no breaking change). `CrashConfig::redact_values(Vec<String>)`: app-supplied known secrets (API keys, database keys, tokens) are replaced with `[redacted]` in every report field, the final serialized value handed to the file and the sink, and the macOS native sample text, on top of the pattern scrub (empty strings ignored; `Debug` never prints them; same contract as `rightkit-http` `ClientConfig::redact_values`). Fallback crash directory: when `crash_dir` cannot be created or written, reports go to a private per-app folder in the OS temp directory (`fallback_crash_dir(app_name)`, `0700` on Unix, refused if it is a symlink or not the current user's), announced by one `rightkit-crash:` stderr line; if the fallback is also unusable the stderr line says no report file was written. Apps list it at next launch with `list_pending(&fallback_crash_dir(app))`. `capture_native_for_pid(&CrashConfig, kind, pid)`: native sample (macOS) or minidump (Windows) of a child process the parent names, through the same single-flight guard and, on macOS, the same scrub-before-publish path as the panic hook; the Windows dump stays unscrubbed and local. The helper must still be alive when called.
- Process-kind coverage. Additive: `ProcessKind` (`Window`, `Engine`, `Helper`), `CrashConfig::process_kind`, `install_process_hook` (one install path per process kind) and `record_helper_exit` (supervisor-side report for a helper that exits abnormally, with helper name, exit status and restart count). Reports carry an optional `process_kind` (omitted when unset; older reports still parse). Breaking: none.
- macOS native sample privacy fix. `sample` now writes to a hidden, owner-only raw file (`.sample_raw_*.raw`) that the support bundle, `prune` and `list_pending` do not match; only scrubbed bytes are published, atomically and owner-only, as `sample_*.txt`. Previously a failed read or write during scrubbing left the unscrubbed sample under a bundle-eligible name and still reported it as captured. Now any failure returns `None`, deletes the raw file, keeps nothing and is reported through the new additive `CrashReport::native_capture_note` field (omitted from JSON when empty; older reports still parse) and one `rightkit-crash:` stderr line. `prune` and the next macOS capture sweep raw files older than five minutes. Windows minidumps are unchanged (never scrubbed, bundled only on explicit opt-in); the README now says so. Breaking: none (new public field on `CrashReport`, which apps do not construct themselves).
- Panic hook fixes (consumer-reported). A sink whose thread cannot be spawned now runs inline instead of losing the record; the re-entrancy guard is per thread, so a panic on another thread during a slow sink is recorded (the sink thread holds its own guard, so a sink panic still cannot recurse); the file record is written before the sink runs, so under `panic = "abort"` it survives a panicking sink, and `with_sink` documents unwind-only containment; sink-only mode no longer creates `crash_dir`. Additive: `CrashConfig::capture_backtrace(bool)` (default `true`, unchanged behaviour) skips the unbounded backtrace capture in the panic hook. `rightkit-logs` requirement raised to `0.2.2`. Breaking: none.
- Panic capture hardening: the re-entrancy flag is cleared by a drop guard, so a failed record no longer disables later reports; reports are written owner-only (0600 on Unix, current-user-only DACL on Windows) through `rightkit-fs` atomic writes; `set_recording_enabled` / `recording_enabled` add a runtime off switch (default on). Additive: `CrashConfig::with_sink` hands each redacted report to a host callback (run on a bounded thread, so a sink panic is contained), and `CrashConfig::write_report_file(false)` turns off the `crash_dir` file. Breaking: none.
