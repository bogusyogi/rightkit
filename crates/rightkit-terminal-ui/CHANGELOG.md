# Changelog

## 0.1.8

Additive: no public item is removed or changed and no signature moves. Stage 5 of moving CodeRight's terminal UI crate onto this one (bogusyogi/coderight#567; bogusyogi/rightkit#1791): the transcript, session picker, observability pane and timeline. New public items are listed; everything else changes how existing code behaves.

- **The typed timeline is bounded.** `transcript::timeline::Timeline` keeps at most `TIMELINE_MAX_ENTRIES` (20,000) entries; past the cap plus a 1,024 slack the oldest settled entries are dropped from the front, never an entry that can still change, so a long session no longer grows without bound. `Timeline::entries()` is now the newest window; new `Timeline::evicted()` counts what was dropped and `Timeline::get(absolute)` reads by the index an entry had when pushed. A journey can lower the cap with `<PREFIX>_TIMELINE_MAX_ENTRIES` (the host's prefix from `terminal::notify::env_name`, `RIGHTKIT_` by default; read once, honoured only between 50 and the default). `latest_route()` is kept as entries are pushed instead of scanning the history.
- **Streaming Markdown holds a table whose header has no leading pipe** (`a | b`) until the next line shows whether it is a delimiter row, and keeps the rows of such a table held, so a table is not committed half built.
- **The answer no longer ends with a `  copy · c` line.** The `c` key still copies. A host that matched that text (a click on the line) must stop doing so.
- **Deeply nested lists keep their text.** Once the indent of a nested block is wider than half the wrap width, leading spaces come off its prefix so the text no longer wraps one character per row.
- **F3 is a find key** (`transcript::find::FindState`): it opens the bar, and with the bar open steps to the next match (Shift+F3 the previous one).
- **Session picker content matches.** New `nav::NavView::set_content_matches(query, rows)` lists sessions whose message text matched a full-text search beside the title matches, marked "matches message text" with a snippet line, while the typed filter is still that query; `session_query()` reads the filter text. The query and matches are cleared when the picker opens.
- **`transcript::Transcript`:** `push_expansion_cell` (a cell the user expanded; the fold key leaves these out of a reprint), `reprint_lines(width, fold)` (the settled part of the chat rendered for a repaint after a clear) and `code_blocks_of(markdown)`.
- **`observability_pane`:** `ProviderRateLimit`, `parse_cache_miss_notice`, and on `ObservabilityPane` `set_rate_limit`, `rate_limit_line`, `set_cache_ttl_ms`, `cache_ttl_line`, `set_last_cache_miss`; `lines()` appends the cache-expiry, rate-limit and last-cache-miss rows when the host has set them.
- **`scheduler`:** `RenderMetrics` and `FrameRequester` gain `record_maintenance_tick` and `record_timeline`; `RenderMetricsSnapshot` gains `maintenance_ticks`, `timeline_entries` and `timeline_evicted`.
- **`diff_review_pane::DiffReview::take_feedback`** returns the comments as feedback text and clears them, so a second send does not repeat them.
- Not in this version, left for 0.2.0 because it changes a public shape: the `DaemonEvent::ToolArgumentsPartial` and `RateLimit` variants and the new `Usage` fields (`completion`, `cost_billed`, `rate_limit`, `cache_ttl_ms`); `nav::SessionDetail` `unread`, `pinned` and `root` with `NavIntent::TogglePinSession`, the `*` pin key, the pinned-first order and `NavView::session_root`. CodeRight's other additions in these files are `#[allow(dead_code)]` code with no caller in its crate or bin (markdown copy serialisation, streaming code highlighter and theme override, live row builder, markdown stream collector, the status, accent and selection styles, adaptive wrapping helpers, the fence tracker, startup colour probe) and are not ported.

## 0.1.7

Additive: no public item is removed or changed. Stage 4 of moving CodeRight's terminal UI crate onto this one (bogusyogi/coderight#567; bogusyogi/rightkit#1789): the composer. The one new public item is `composer::Composer::note_ctrl_c_turn_cancel`; the rest changes how the composer behaves.

- **Undo in the prompt outside Vim mode.** Ctrl+_ (which crossterm reports as Ctrl+8, or Ctrl+7 and Ctrl+/ on terminals that map it so) steps back through up to 64 earlier drafts; a run of plain typing is one step, a submission ends the history, a draft over 256 KiB is not recorded, and it is off while Vim editing is on (Vim keeps its own undo) and while Ctrl+R search is open.
- **A trailing `\` before Enter inserts a newline** instead of submitting, for terminals that cannot send Shift+Enter; the backslash is dropped, and backslash then space is sent as typed. Not applied in Vim normal mode or to a queueing Enter.
- **Ctrl-C.** While Ctrl+R search is open it belongs to the search (it restores the saved draft and closes the search) instead of clearing the draft. On an idle prompt it still clears the draft and arms the quit, and the cleared text now stays recallable with Up and Ctrl+R for the rest of the session (never written to the history file). With a turn running, the first press cancels the turn and no longer arms the quit; a host that cancels the turn itself calls the new `Composer::note_ctrl_c_turn_cancel` so that a second press within 500 ms keeps the draft and only arms the quit (a third press within 500 ms quits). `set_streaming(true)` forgets the cancel.
- **Pasted text held back by the burst detector is let into the draft before Ctrl-G opens the external editor and before the Esc checks run**, so the editor and the empty-prompt tests see what the user pasted.
- **The `/` command list is grouped.** The bare `/` shows up to 12 available commands in six groups (session, review, model, policy, info, other) in two columns when the width is 72 or more, each with a short phrase; commands the built-in group table does not name fall in "other" (one row in the bare view; typing reaches them all). Commands that cannot run now stay hidden until their name is typed, and prose in a description never surfaces a disabled command. Typing shows one column, best match first, with the matched letters bold and a count row (`n of m`). `CompletionPopup::calculate_required_height` now uses its width argument.
- **`composer::history_search`:** the cursor after `reverse-i-search: <query>` is placed by display width, not bytes, so a non-ASCII query keeps the cursor on its glyph.
- **`composer::history_store`:** appends and compaction of every session share one lock file next to the history file (`history.jsonl.lock`, waiting up to one second); if the lock cannot be taken the line is still appended and compaction waits for a later append. `default_history_path(state_root)` is unchanged.
- Not in this version: CodeRight's other composer additions are `#[allow(dead_code)]` code with no caller in its crate or bin (the keymap contexts and chord matcher, `textarea` snapshots, masked rendering and keymap swap, `set_keymap_bindings`, `set_text_content`, `append_recovered_drafts`, the mention decoder, the text helpers, the page and jump moves of `ScrollState`, the `GenericDisplayRow` counters, the mouse-selection copy hooks and others). `composer::clipboard_copy` therefore stays unused. CodeRight's default command catalog (which reads `coderight_skills`) is not taken: the default stays `help`, the interactive command effects and `quit`, and the host sets its own.

## 0.1.6

Additive: no public item is removed and no signature changes. Stage 3 of moving CodeRight's terminal UI crate onto this one (bogusyogi/coderight#567): the security and leaf modules. Several functions draw or decide differently; each is listed.

- **`render::sanitize::sanitize` strips invisible spoofing characters.** Besides control characters it now removes the bidi controls (U+061C, U+200E, U+200F, U+202A to U+202E, U+2066 to U+2069), zero-width space (U+200B), word joiner (U+2060), BOM (U+FEFF), soft hyphen (U+00AD) and the tag characters (U+E0000 to U+E007F). ZWNJ and ZWJ (U+200C, U+200D) stay only right beside a non-ASCII character that is not another joiner and not general punctuation (U+2000 to U+206F); between ASCII characters they are removed. Tag characters stay only after the subdivision-flag emoji U+1F3F4. Every constructor that routes text through `sanitize` (transcript messages, tool-call and hint text, exec ledger, identity strip, elicitation form, cell text) gets this.
- **`render::allow_rule` offers fewer "always allow" prefixes.** The never-prefix list gains `busybox`, `toybox`, `stdbuf`, `setsid`, `chroot`, `strace`, `ltrace`, `wsl`, `pkexec`, `runuser`, `unshare`, `nsenter`, `ionice` and `taskset`. The check also covers Windows spellings (`.exe`, `.cmd`, `.bat`, `.com`) and versioned names (`python3.12`, `node18`), and the subcommand tools (`git.exe status`) are matched without the extension. The host's own command (`app_slug()`) still takes `command subcommand` prefixes.
- **`render::exec`: `ExecCall.permission` and `ExecCell::set_permission`.** A call can carry how its permission settled; the ledger row shows it as a dim field before the result and time (red for `denied`, and a denied call no longer also says `failed`). `ExecCall` already had a private field, so adding a public one breaks no struct literal.
- **`render::diff::ledger_diff_row` draws `−` (U+2212) for a removal and a 3-wide line number**, so the row body starts at column 4 instead of 6.
- **`terminal::capability`:** new `clipboard_osc52_forced` (`<PREFIX>_CLIPBOARD_OSC52`, taken through the naming hook) and `osc52_screen_sequence`; `clipboard_strategy` treats the forced flag like an SSH session; `clipboard_osc52_for_env` wraps for GNU screen with its own DCS rather than tmux's; `detect_image_protocol` also accepts `TERM=*kitty*`; `rgb_to_ansi16` maps neutrals by lightness and other colours by nearest hue (the old bit-threshold mapping chose other colours on 16-colour terminals).
- **Synchronized output (DEC mode 2026).** `terminal::custom_terminal::Terminal::draw` holds each non-empty frame, and `terminal::history::insert` each scrollback insert, between `ESC [ ? 2026 h` and `ESC [ ? 2026 l`. A terminal that does not know the mode ignores both.
- **`pty_attach`:** Ctrl+5 detaches like Ctrl+], because a terminal without the keyboard-enhancement protocol reports the 0x1d byte as Ctrl+5.
- **`rightkit-theme` dependency** (0.1.1, serde and serde_json only, both already in this crate's tree): `transcript::color::perceptual_distance` and the contrast ratio in `transcript::style` use `rightkit_theme::color::{delta_e76, contrast_ratio}` instead of local copies. Results move by a small numeric margin (the local copies used rounded matrix constants and an f32 path); the white-point, transfer curve and weights are the same.
- Not in this version, left for the later stages: `terminal::session`, `alternate_screen`, `link_pointer` and `keyboard_modes` carry only unused CodeRight code, and `rightkit-http`'s `percent_decode_strict` is not adopted (the local strict decoder in `markdown_render::local_links` does the same and rightkit-http brings an HTTP and TLS client).

## 0.1.5

Additive; no public item is removed or changed. First two stages of moving CodeRight's terminal UI crate onto this one (bogusyogi/rightkit#1781).

- **Naming hook.** The environment variables and file names the crate used to hard-code now take the host's prefix: `terminal::notify::set_env_prefix` (call once at startup, before the first read), `env_prefix`, `env_name` and `app_slug`, next to `set_app_name`. Same shape as `rightkit_agent_config::env_name`, which this crate does not depend on (it would bring rightkit-agent-policy, rightkit-http, toml and serde into a UI crate); a host sets the same prefix on both. Routed through it: `<PREFIX>_NOTIFY`, `<PREFIX>_TERMINAL_TITLE`, `<PREFIX>_ASCII`, `<PREFIX>_UNICODE`, `<PREFIX>_TUI_DISABLE_KEYBOARD_ENHANCEMENT`, the external-editor temp file (`<slug>-prompt-<pid>-<ns>.md`) and its shell `$0` (`<slug>-editor`), and the host's own command in the allow-rule subcommand list (`<slug> <subcommand>`; `rightkit` stays in the list). With nothing set every name is what it was.
- **Added modules.** `render::cast` (the cast tree of the main agent and its sub-agents with their models), `transcript::pacer` (adaptive line pacing of a streamed answer), `terminal::kitty_image` (Kitty graphics output for a PNG), mermaid `pie` charts (a ` ```mermaid ` block starting `pie` now renders as bars, where it fell back to source), and the crate-private `composer::clipboard_copy` result types.

## 0.1.3 (2026-11-16)

- Fix: a long answer written into the terminal's scrollback now wraps every row to the terminal width. A link longer than the terminal (a bare URL that carries an OSC 8 link, or a linked label) was written as one over-wide row that the terminal soft-wrapped on its own, so the row count the scrollback insert had counted was wrong and lines were pushed out of place. A list nested so deep that its continuation indent took half the terminal or more left a column or two for text and put one character on each row; such a line now continues from the left margin. Plain bare URLs without a link still stay whole so the terminal can match them as one link. Ported from the product TUI (CodeRight, Wave 25) where the fix was made first.
- Removed dead source files that no module declared and nothing read: `src/composer/wrapping.rs`, `src/composer/line_truncation.rs` and `src/composer/line_utils.rs` (the composer re-exports the transcript's wrapping and truncation and the terminal's line helpers), and the 97 `.snap` snapshot files under `src/` (there is no snapshot test target). In the transcript wrapping helpers, `adaptive_wrap_line_to_width` replaces the now unused crate-internal `adaptive_wrap_line`. No other behaviour changes.
