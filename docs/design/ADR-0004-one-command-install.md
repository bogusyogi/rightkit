# ADR-0004: One-command install for every app

Status: approved with conditions by Sage, 2026-10-25 (see "Sage conditions"); D-A/D-B/D-C pending Adrian (rightkit#1191, pulse#493). Owner: `@rightkit/release` (right-release).

## Request

Adrian (2026-10-25): "is there an easy, single command way to install pulse? there should be. like pnpm or
something. even brew on mac and whatever equivalent on windows ... do it across every app".

## Charter

- **Significance:** significant. A trust and supply-chain boundary: a script fetched over the network
  installs signed binaries. A durable public contract: install URLs, a tap and cask names.
- **Depth:** D2, because the change is platform-wide.
- **Rigor:** standard.
- **Objective:** sufficient.

## Current state (survey 2026-10-25)

- **Installer locations.** R2 apps (ViewRight, MailRight, and the other `r2-rightapps` apps) publish installers to
  the PUBLIC bucket `rightapps-downloads`, at `<app>/installers/<mac|windows>/current/<file>`, with a
  `versions/<ver>/` copy. The licence-gate worker guards updates only; installers are already anonymous downloads.
- **Pulse.** Pulse uses `github-releases` on a PRIVATE repo (`bogusyogi/pulse`), so anonymous `curl` cannot fetch
  its assets. `publishBlocked` is set on both installers, and there is no Linux target.
- **Platform-native verification a plain script can run with no extra tools:**
  - Windows: Authenticode, through `Get-AuthenticodeSignature`. The signer is "Damned Ventures LLC".
  - macOS: Developer ID plus notarization, through `codesign --verify --deep --strict`,
    `spctl -a -t install` and `xcrun stapler validate`. The team is 6KLGD3LLKF.
  - Linux: nothing comparable. minisign and Ed25519 need a tool the script would have to bring. The Azure
    catalog (`release-manifest.cat`) verifies on Windows only.
- **Prior art:**
  - `direct-bootstrap.mjs` covers portable zips with a Windows-only catalog.
  - `infrastructure/branded-installs/worker.mjs` serves `legion.`/`membrane.orthiclabs.com/install.ps1`
    from `rightapps-downloads`.
  - The hand-written `bootstraps/legion/install.ps1` pins version, url, sha256 and signer. It is the
    pattern this ADR generalises.
  - `@rightkit/ci` `publish-package-managers.yml` targets GitHub Actions on public repos only. It does not
    fit apps that are built and signed locally in private repos.
- **No Orthic brew tap, winget manifest or install.sh exists.**

## Drivers (quality scenarios)

- **Q1, one command.** On a clean machine, each of these installs the current release at the same path and
  identity right-release uses, and running it again upgrades:
  - Mac: `brew install orthic-labs/tap/<app>` or `curl -fsSL https://get.orthiclabs.com/<app>/install.sh | sh`;
  - Windows: `irm https://get.orthiclabs.com/<app>/install.ps1 | iex`;
  - Linux: `curl ... | sh`.
- **Q2, integrity.** A tampered or replaced installer at the CDN is refused before anything runs:
  - every channel checks a sha256 pinned at publish time;
  - Windows and Mac also check the platform signature and the expected signer (subject or Team ID).
- **Q3, no drift.** Every channel is generated by right-release from the release it just verified and
  uploaded. No per-app files are written by hand. A channel never points at a build older than `current/`.
- **Q4, no new secrets in CI.** Signing and publishing stay on the local release host, as they work today.

## Decision

1. **One generator in right-release, one data source.** After a successful `publish-update` (R2) upload, a
   new module `install-channels.mjs` takes the facts right-release already verified and renders all
   channels from them. Its input per target is: app, version, installer URL (the `versions/<ver>/` key, which
   never changes), sha256, size, signer, Apple Team ID, install destination and bundle id. Those facts come
   from config `development.targets.*.install`, `tauri.conf.json` and the upload receipt. The channels are:
   - `install.sh`: macOS and Linux. It refuses unsupported OS/arch pairs with a plain-words message.
   - `install.ps1`: Windows.
   - `Casks/<app>.rb`: Homebrew.
   - A winget manifest set. It is generated and validated, but submitted only for public apps, on request.

   Each script pins the exact version, URL and sha256. Rerunning a script fetches the regenerated script,
   so it moves to whatever `current` is. This is the Legion bootstrap pattern, generated rather than
   hand-written.
2. **Install semantics match right-release dev installs.**
   - Mac: copy the `.app` out of the DMG into `/Applications/<App>.app`, replacing it in place, using
     `in-place-install.mjs`'s transient `.previous` and rolling back on failure.
   - Windows: `<Setup>.exe /S` per-user into the configured destination. Before it runs, the script checks
     Authenticode Valid and that the subject matches the configured signer.
   - Linux: extract the declared `linux-*` tarball into `~/.local/share/<app>`, with a symlink in
     `~/.local/bin`. This runs only when an app declares a linux installer artifact; Pulse adds its payload
     under pulse#493.
3. **Host.**
   - Extend the existing `rightapps-branded-installs` worker, not a new service, with a host
     `get.orthiclabs.com` that maps `/<app>/install.{sh,ps1}` to `rightapps-downloads/<app>/install.{sh,ps1}`.
   - The app name is checked against a fixed allowlist that right-release regenerates.
   - `legion.` and `membrane.` keep their current routes.
4. **Homebrew.**
   - One tap repo `Orthic-Labs/homebrew-tap`. It must be public for anonymous `brew tap`.
   - The cask carries only the public R2 URL and sha256, so publishing it exposes nothing new.
   - right-release commits the regenerated cask and pushes it from the release host after the upload is
     verified. No CI token is involved.
5. **winget.** The public `microsoft/winget-pkgs` route needs a human-reviewed PR and suits public apps
   only. The manifest is generated and validated with each release. Submission is a separate, explicit step.
   The Windows one-command form is `irm | iex` for every app.
6. **Private-repo GitHub apps (Pulse).** An installer that cannot be fetched anonymously cannot be installed
   with one command. Pulse moves its installer delivery to the R2 public installer lane (`r2-rightapps`)
   that every other app already uses, inside its own `publishBlocked` work. This is Pulse's change, not
   RightKit's, and is tracked on pulse#493.
7. **Uninstall.**
   - `install.sh --uninstall` and `install.ps1 -Uninstall`. On Windows this runs the NSIS uninstaller.
   - `brew uninstall`.
   - Documented in docs/RELEASE-EXPORTS.md.

## Rejected candidates

- **One generic script that resolves "latest" at run time from a signed manifest.** POSIX sh cannot verify
  Ed25519, minisign or the Azure catalog without extra tools, so on Mac and Linux it would trust HTTPS alone
  for an unpinned artifact. Pinning at publish time gives the same one command with an integrity check.
- **Generalising `direct-bootstrap.mjs`.** It is built for portable zips with a CLI activate/status
  contract, and its verification is Windows-only. It stays as it is for Membrane and Legion.
- **The `@rightkit/ci` package-manager lane.** It is restricted to public repos and needs long-lived tokens
  in Actions, which breaks Q4.
- **A public winget submission per release for private apps.** It is not possible without publishing the
  app publicly.

## Invariants

- I1: A script never runs an installer before the sha256 matches. On Windows and Mac the platform signature
  and expected signer must also match.
- I2: Scripts are generated, then read back from R2 and compared byte-for-byte before the worker allowlist
  or cask moves. They follow the same publish-and-verify order as `direct-bootstrap.mjs`.
- I3: The pinned URL is the immutable `versions/<ver>/` object, never `current/`.
- I4: The install path and identity are the ones right-release's dev install already uses.

## Rollout

1. RightKit work:
   - `install-channels.mjs` with tests: rendering, refusal on hash mismatch using a fake tampered file, and a
     byte-compare on read-back;
   - the worker route `get.orthiclabs.com` with tests;
   - the tap repo;
   - a docs entry;
   - publication of `@rightkit/release` 0.7.0.
2. First app: ViewRight, already on public R2 installers. Verify with real installs on both hosts:
   - Mac: `brew install` and `curl | sh`;
   - Windows: `irm | iex`.
3. Every other `r2-rightapps` app gets the channels on its next release with no app change: its config
   already holds every field.
4. Pulse follows its move to R2 and its Linux payload (pulse#493).

## Decisions needed from Adrian

- D-A: Create the public repo `Orthic-Labs/homebrew-tap`. It holds only casks with public URLs and hashes.
- D-B: Use the host name `get.orthiclabs.com` (a new custom domain on the existing worker).

- D-C: The download host pinned into public casks and scripts. The choice is between Cloudflare's development
  endpoint `pub-…r2.dev`, which is rate-limited, and a custom domain on `rightapps-downloads`, such as
  `downloads.orthiclabs.com`. For D-B, the alternative to `get.` is one host per product, `<app>.orthiclabs.com`,
  which follows the existing `legion.` and `membrane.` convention.

## Sage conditions (2026-10-25, all binding)

1. **Immutable URL.** Every app declares `versionedKey` for its installers, and the generator hard-fails without
   one. ViewRight declares only `current/` keys today, so an app config change IS required. This supersedes
   Rollout step 3's "no app change".
2. **Retention.** `retainPreviousVersions` is 1, so a `versions/<ver>/` URL lives for the current and previous
   release only. That is enough for latest-only install; I3 means immutable within that window.
3. **Windows signer.** Match the Authenticode signer by exact parsed CN or thumbprint, after Status == Valid,
   and before running anything. Never `StartsWith`.
4. **Mac checks.** Before replacing `/Applications/<App>.app`, verify the `.app` inside the DMG with `codesign`
   and its Team ID, `spctl`, and stapler (tolerate a missing stapler, as `install-app.mjs` does), then roll back on
   failure. `install.sh` reimplements a small mount, verify, swap and roll back sequence. It cannot call the Node
   modules.
5. **Truncation safety.** `install.sh` is one function called on its last line, so a truncated `curl | sh`
   runs nothing. Windows uninstall uses `& ([scriptblock]::Create((irm <url>))) -Uninstall`.
6. **No worker allowlist.** The app segment is strict `^[a-z0-9-]+$` and the filename set is fixed, so a
   missing object returns 404. Ordering: upload the script, read it back and compare byte-for-byte, then push
   the cask. Apps on `direct-bootstrap` (Legion, Membrane) are excluded.
7. **Deferred.** winget generation and Linux generation are deferred. Linux stays off until an app declares a
   linux artifact AND a signature scheme (minisign or openssl Ed25519) is chosen: with the script and the
   installer in one bucket, sha256 alone detects only corruption.
8. **Tap credential.** The tap push uses a repo-scoped deploy key on the release host. The credential is
   documented in docs/PUBLISHING-CREDENTIALS.md.
9. **D-C first.** Resolve D-C before the first public cask.
10. **Per-platform channels.** Each `publish-update --platform` run emits only its own platform's channel:
    `install.ps1` from the win run, and `install.sh` plus the cask from the mac run.
