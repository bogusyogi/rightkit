# Architecture & decomposition review

Date: 2026-10-11. Scope: current source under `packages/` & `crates/`; 25 npm manifests, 57 top-level Rust manifests, & 2 nested example manifests. Evidence was read from manifests, public exports, implementation bodies, & in-repo callers. `rightkit owns --compact` was used as capability ownership context; declaration-only ownership was not treated as integration evidence. No tests, builds, installs, network calls, or product changes were made.

RightKit's contract is one canonical source home with published npm/crates consumption ([README.md:3-9](../../../../README.md)); shared-package boundaries are registry-facing ([RIGHTKIT-SHARED-PACKAGES.md:5-25](../../../../../docs/RIGHTKIT-SHARED-PACKAGES.md)). Verdicts below preserve public facades unless source shows duplicate responsibility or state authority. Size, module count, or multiple adapters alone is not a decomposition finding.

## Findings requiring action

1. QA ownership is documented as split, but Rust source claims replacement: `@rightkit/qa` is assigned Node/browser tooling with “Rust pair | None declared” ([packages/qa/README.md:3-8](../../../../packages/qa/README.md)), while current ownership rows assign `@rightkit/qa` to `qa-evidence` and `rightkit-qa` to `desktop-qa` ([INDEX.md:55](../../../../INDEX.md), [INDEX.md:97-98](../../../../INDEX.md)); `rightkit-qa` says it “Replaces `@rightkit/qa`” ([crates/rightkit-qa/src/lib.rs:1-5](../../../../crates/rightkit-qa/src/lib.rs)). Source shows concept overlap, but not equivalent APIs/platforms: Node exports browser/CDP page, loopback, process, storage, evidence, and guards ([packages/qa/src/index.ts:1-12](../../../../packages/qa/src/index.ts)), while Rust documents native app/control scenarios and optional Chrome ([crates/rightkit-qa/src/lib.rs:7-21](../../../../crates/rightkit-qa/src/lib.rs)). Keep both boundaries pending reconciliation; acceptance is one current ownership statement plus an API/platform matrix and concrete same-host consumer evidence before any migration. A versioned evidence/receipt contract may be shared without merging runners.
2. `rightkit-qts-ggml` is a direct deprecated wrapper over `rightkit-qts-ggml-sys` ([crates/rightkit-qts-ggml/Cargo.toml:8](../../../../crates/rightkit-qts-ggml/Cargo.toml), [crates/rightkit-qts-ggml/src/lib.rs:1-7](../../../../crates/rightkit-qts-ggml/src/lib.rs)). Keep only as a no-new-API compatibility package; acceptance is zero in-tree dependants (current `rightkit-qts` depends on `rightkit-qts-ggml-sys`), then deprecate/remove on next breaking release.
3. `rightkit-send` has private `write_atomic` code beside `rightkit-fs`'s shared atomic writer ([crates/rightkit-send/src/lib.rs:213-237](../../../../crates/rightkit-send/src/lib.rs), [crates/rightkit-fs/src/atomic.rs:1-14](../../../../crates/rightkit-fs/src/atomic.rs)). Its current caller persists host trust records ([crates/rightkit-send/src/trust.rs:244-255](../../../../crates/rightkit-send/src/trust.rs)). Semantics overlap but are not identical: send creates parent dirs, writes `0600` on Unix, `sync_all`s the file, renames, and cleans a failed temp ([crates/rightkit-send/src/lib.rs:215-237](../../../../crates/rightkit-send/src/lib.rs)); `rightkit-fs` additionally supports owner-only/private-dir policy, no-follow temp creation, existing-mode handling, configurable replacement/retry, and directory `fsync` ([crates/rightkit-fs/src/atomic.rs:21-29](../../../../crates/rightkit-fs/src/atomic.rs), [crates/rightkit-fs/src/atomic.rs:175-237](../../../../crates/rightkit-fs/src/atomic.rs), [crates/rightkit-fs/src/atomic.rs:260-287](../../../../crates/rightkit-fs/src/atomic.rs)). Treat as shared-contract candidate, not proven removable duplicate: acceptance is trust-store persistence review covering directory durability, owner-only result, Windows behavior, symlink/mode handling, and failure cleanup, then either delegate with matching options or document protocol-specific exception.

The apparent overlaps below are deliberate layers: `@rightkit/update` is repo dependency mutation ([packages/update/package.json:2-4](../../../../packages/update/package.json)) while `@rightkit/updates` is runtime install policy ([packages/updates/src/index.ts:1-17](../../../../packages/updates/src/index.ts)); `@rightkit/shell` is a renderer bridge ([packages/shell/src/index.ts:1-8](../../../../packages/shell/src/index.ts)) while `@rightkit/app-shell` is a React frame and structural bridge ([packages/app-shell/src/bridge.ts:1-14](../../../../packages/app-shell/src/bridge.ts)); JS/native `license`, `logs`, `tauri`, and QA layers have explicit language/runtime seams.
