# Astra adversarial read: rightkit-http 0.2.6 (2026-10-11)

Model gpt-6-astra, high reasoning, read-only through `codex exec`, against commit 67c7d4ce. No P0. 6 P1, 14 P2, 1 P3. Publication of this version is held until the P1 and P2 items are fixed and re-read. Finding 5 (Retry-After overflow panic, retry.rs) is also present in the published 0.2.5.

Read-only review of **0.2.6** completed. Read requested files, supporting retry/cancellation code & all integration tests; checked relevant dependency behavior against upstream sources. **No tests or exploits executed, no files changed.** Network-dependent scenarios below require stated proxy, NAT64 or cloud setup. No P0 found.

1. **P1 — Alternate IPv4 spellings bypass blocking proxy policy.** [netpolicy.rs:461](/Volumes/D/claude/rightkit/crates/rightkit-http/src/netpolicy.rs:461), [netpolicy.rs:518](/Volumes/D/claude/rightkit/crates/rightkit-http/src/netpolicy.rs:518). Strict `IpAddr` parsing rejects `127.1`, `0177.0.0.1`, `0x7f.0.0.1` & `0251.0376.0251.0376`; dotted-name checks then permit them. With proxy mode enabled, these reach proxies that interpret legacy IPv4 syntax, including metadata at `169.254.169.254`. Redirects have same bypass. Async canonicalizes these forms before checking.

2. **P1 — Proxy endpoint exemption also exempts direct destinations.** [netpolicy.rs:700](/Volumes/D/claude/rightkit/crates/rightkit-http/src/netpolicy.rs:700), [client.rs:1073](/Volumes/D/claude/rightkit/crates/rightkit-http/src/client.rs:1073), [async_client.rs:449](/Volumes/D/claude/rightkit/crates/rightkit-http/src/async_client.rs:449). Set `ALL_PROXY=http://proxy.example:3128`, `NO_PROXY=*`, with `proxy.example → 10.0.0.5`. Blocking requests to `http://proxy.example:3128/` skip both first-party admission & address classification—even with first-party hosts restricted elsewhere. Async retains host admission but exempts DNS addresses for `proxy.example` on **any port**, permitting direct access to other private services on that machine.

3. **P1 — Local-use NAT64 addresses classify as public.** [netpolicy.rs:104](/Volumes/D/claude/rightkit/crates/rightkit-http/src/netpolicy.rs:104), [netpolicy.rs:130](/Volumes/D/claude/rightkit/crates/rightkit-http/src/netpolicy.rs:130). With NAT64 configured for `64:ff9b:1::/96`, requesting `http://[64:ff9b:1::a00:1]/` passes both clients & translates to `10.0.0.1`. Only well-known `64:ff9b::/96` gets embedded-address inspection; local-use translation space is defined separately by [RFC 8215](https://www.rfc-editor.org/rfc/rfc8215.html).

4. **P1 — IPv6 metadata protection can be overridden.** [netpolicy.rs:128](/Volumes/D/claude/rightkit/crates/rightkit-http/src/netpolicy.rs:128), [netpolicy.rs:585](/Volumes/D/claude/rightkit/crates/rightkit-http/src/netpolicy.rs:585), [netpolicy.rs:614](/Volumes/D/claude/rightkit/crates/rightkit-http/src/netpolicy.rs:614). `fd00:ec2::254` receives ordinary `Private` classification; only `LinkLocal` is unconditionally denied. An allowed local-service hostname resolving there passes `.allow_if(..., |_| true)`, allowing HTTP requests to [AWS’s IPv6 metadata endpoint](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/instancedata-data-retrieval.html). This violates documented “metadata cannot be allowed by any hook” guarantee.

5. **P1 — Remote `Retry-After` causes panic before capping.** [retry.rs:77](/Volumes/D/claude/rightkit/crates/rightkit-http/src/retry.rs:77), [client.rs:878](/Volumes/D/claude/rightkit/crates/rightkit-http/src/client.rs:878), [async_client.rs:233](/Volumes/D/claude/rightkit/crates/rightkit-http/src/async_client.rs:233). Return `503` with `Retry-After: 18446744073709551616`. Finite positive parsing succeeds, then `Duration::from_secs_f64` panics on overflow; `max_retry_after` never runs. Both clients are affected; blocking parsing happens even before deciding whether retries are enabled. [Rust documents this panic](https://doc.rust-lang.org/std/time/struct.Duration.html#method.from_secs_f64).

6. **P1 — Predictable `.part` symlink permits arbitrary-file truncation.** [download.rs:154](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:154), [download.rs:169](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:169). Local attacker able to create entries in destination directory places `out.part → victim`. Default download opens through symlink & truncates victim **before URL policy runs**, even when URL is subsequently denied. Closing file before reopening its pathname for hashing & renaming also permits replacement races ([download.rs:173](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:173)).

7. **P2 — Async ignores cancellation & overall deadline entirely.** [async_client.rs:208](/Volumes/D/claude/rightkit/crates/rightkit-http/src/async_client.rs:208), [async_client.rs:262](/Volumes/D/claude/rightkit/crates/rightkit-http/src/async_client.rs:262), [async_client.rs:534](/Volumes/D/claude/rightkit/crates/rightkit-http/src/async_client.rs:534). Pre-cancelled `Request::cancel(token)` still sends. `.deadline(100ms)` does not constrain attempts, sleeps or streams; an endless response stream continues indefinitely despite deadline expiry & cancellation when stream/body timeouts retain defaults.

8. **P2 — Async ignores per-request body limit & headers-only flag.** [async_client.rs:122](/Volumes/D/claude/rightkit/crates/rightkit-http/src/async_client.rs:122). Serve 100 bytes to `.max_response_bytes(10)`: async succeeds under default configuration. `.headers_only()` still reads & buffers body. Config-wide limit remains effective, but callers’ narrower resource limits are silently bypassed.

9. **P2 — HTTPS redirects can downgrade to plaintext.** [redirect.rs:117](/Volumes/D/claude/rightkit/crates/rightkit-http/src/redirect.rs:117), [client.rs:998](/Volumes/D/claude/rightkit/crates/rightkit-http/src/client.rs:998), [async_client.rs:334](/Volumes/D/claude/rightkit/crates/rightkit-http/src/async_client.rs:334). Enable redirects; HTTPS endpoint returns `Location: http://public.example/file?signature=SECRET`. Both public-web clients follow, exposing signed query & accepting unauthenticated response content. Credential-header stripping does not protect this URL. First-party mode rejects downgrade.

10. **P2 — Bearer tokens leak through `Request::Debug`.** [client.rs:324](/Volumes/D/claude/rightkit/crates/rightkit-http/src/client.rs:324), [client.rs:412](/Volumes/D/claude/rightkit/crates/rightkit-http/src/client.rs:412). `format!("{:?}", Request::get("https://example.com").bearer("SECRET"))` prints `Bearer SECRET`: recorded secret is `SECRET`, while Debug compares equality against whole header value. Embedded recorded secrets in other headers leak similarly.

11. **P2 — Response Debug exposes signed URLs & cookies.** [client.rs:528](/Volumes/D/claude/rightkit/crates/rightkit-http/src/client.rs:528), [client.rs:575](/Volumes/D/claude/rightkit/crates/rightkit-http/src/client.rs:575). Return `302 Location: https://example.com/?token=SECRET` with default redirects disabled; formatting `send_any` response or `send_headers` result prints query verbatim. `Set-Cookie` values likewise print; redacting `final_url` does not redact headers.

12. **P2 — Download errors bypass configured redaction.** [download.rs:249](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:249), [download.rs:303](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:303). These errors are constructed after `execute`’s scrub boundary.

13. **P2 — JSON decoding errors bypass configured redaction.** [client.rs:544](/Volumes/D/claude/rightkit/crates/rightkit-http/src/client.rs:544), [client.rs:819](/Volumes/D/claude/rightkit/crates/rightkit-http/src/client.rs:819), [async_client.rs:185](/Volumes/D/claude/rightkit/crates/rightkit-http/src/async_client.rs:185). Configure `redact_values(["SECRET"])`, serve JSON `"SECRET"`, call `get_json::<u64>()`. Serde’s invalid-type error contains `SECRET`; both clients return it without scrubbing.

14. **P2 — Transport tracing bypasses URL redaction.** [client.rs:1042](/Volumes/D/claude/rightkit/crates/rightkit-http/src/client.rs:1042). Enable `ureq` TRACE logging & request `https://example.com/?key=SECRET`. Raw URL reaches transport logging before wrapper error/event scrubbing. Upstream explicitly documents TRACE as [unredacted wire-level logging](https://docs.rs/ureq/3.4.2/ureq/#log-levels).

15. **P2 — Resume validator is reused across different redirect targets.** [download.rs:221](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:221), [download.rs:234](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:234), [download.rs:239](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:239). First fetch redirects to resource A, receives four bytes `AAAA` with ETag `"v1"`, then disconnects. Reconnect restarts original URL, now redirecting to resource B, whose independent ETag is also `"v1"`; valid `206` contributes `BBBB`. Without expected hash, download successfully publishes `AAAABBBB`. Final resource URL is discarded, so `If-Range` is never bound to resource supplying saved prefix.

16. **P2 — Malformed or incomplete `Content-Range` can finalize partial files.** [download.rs:255](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:255), [download.rs:376](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:376). Start with 80-byte partial; return `206`, `Content-Range: bytes 80-199/*`, `Content-Length: 20`, then 20 bytes. Parser ignores range end; unknown total disables final length comparison, so 100-byte file is published successfully. `80-garbage/*` also passes parser.

17. **P2 — Automatic gzip decoding defeats download encoding check.** [download.rs:247](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:247), [download.rs:275](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:275). With default gzip feature, respond to identity request using `Content-Encoding: gzip`. Ureq removes encoding & length headers before returning response, so download accepts decoded bytes instead of rejecting encoding; resume offsets subsequently describe decoded bytes rather than encoded representation. Verified in [ureq 3.4.2 response construction](https://raw.githubusercontent.com/algesten/ureq/3.4.2/src/run.rs).

18. **P2 — Download writes exceed declared expected size without stopping.** [download.rs:315](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:315), [download.rs:176](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:176). Set `expected_bytes: Some(1)` & serve endless chunked data. Writes continue until disk exhaustion; expected length is checked only after EOF, & `max_response_bytes` is never applied. Download’s own chunk buffer remains bounded.

19. **P2 — Blocking stream/download DNS lacks configured deadline.** [client.rs:656](/Volumes/D/claude/rightkit/crates/rightkit-http/src/client.rs:656), [netpolicy.rs:713](/Volumes/D/claude/rightkit/crates/rightkit-http/src/netpolicy.rs:713), [netpolicy.rs:545](/Volumes/D/claude/rightkit/crates/rightkit-http/src/netpolicy.rs:545). Default streaming call has no global timeout & installs no resolver timeout. Stalled system lookup therefore executes synchronously without limit; neither 10-second connect timeout nor 60-second response timeout applies to DNS. Verified against [ureq’s separate phase budgets](https://raw.githubusercontent.com/algesten/ureq/3.4.2/src/timings.rs).

20. **P2 — Blocking retry/error-body drains ignore cancellation.** [client.rs:893](/Volumes/D/claude/rightkit/crates/rightkit-http/src/client.rs:893), [download.rs:347](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:347). Return `503` with unterminated chunked body during `stream` or download, then cancel. Internal drain uses unchecked reader; default stream/body budgets permit indefinite blocking before retry or error return. Cancellation remains ignored even between drain reads.

21. **P3 — Successful download never performs promised fsync.** [download.rs:173](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:173), [download.rs:197](/Volumes/D/claude/rightkit/crates/rightkit-http/src/download.rs:197). File is closed, hashed & renamed without `sync_all`/`sync_data`. Power loss after reported success can leave incomplete destination data despite README’s fsync guarantee.
