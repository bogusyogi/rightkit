# RightKit consumer impact: per-app table for every unit with a pending change

Date: 2026-10-22. Author: `legion:alchemist-specialist` (read-only audit; reason: a wrong row misleads every app's adoption). Nothing was built, compiled, run or committed; every statement is a static read of source, manifests, CHANGELOGs, registry JSON and the RK Fable file. Output file is this one only.

Counts: Table A 34 rows, Table B 234 rows (plus one appendix grid). Scan covers 785 pins across 15 checkouts.

## 1 Method and sources

### 1.1 Request and tier rule

Adrian, 2026-10-22: "build the per-app consumer-impact table for every crate in this lane ... Not just this lane, it should be across RightKit." Tier rule (Adrian): "mandatory packages address all apps, if it's add on, it affects 2 or more apps so not relevant for every apps." Applied here: a mandatory unit gets one Table B row per app (an app that does not pin it is a finding, unless it declared the row not-applicable); an add-on gets rows only for the apps that pin it. Tier is read from the catalog, never judged: see 1.2.

Oracle review 2026-10-22: NOT FIT -> fit after row corrections (models HR/CU/SC release decision, browser coupling, MailRight onnx, docs conditional, overlay-win refresh). Corrections applied below.

### 1.3 What reuses the cutover matrix and what is new

The request said the matrix HTML already has this table for the mandatory units. What is in `docs/audits/cutover-matrix-2026-10-11/matrix.html` (data in `matrix.json`, `catalog.json`, `matrix.csv`): 97 component rows (57 crates, 25 npm packages, 15 RightKitSwift products) by 29 app/tool columns, each cell `Y`, `N`, `M` or `NA` with rationale, evidence paths, delivery flags and confidence. It has no M1-M25 rows and no tier field: a grep of `matrix.json` and `README.md` finds no mandatory-set row ids. So the mandatory units appear there as ordinary component rows. This document therefore follows the structure and vocabulary that exist:

- Reused: the component-by-app layout (Table B is one row per component and app); component ids (`cargo:<crate>`, `npm:<package>`) and app names as the matrix writes them; the `Y/N/M/NA` vocabulary and its definitions (README.md: Y = uses RightKit with no competing local mechanism, N = locally implemented, M = shared and local both active, NA = irrelevant); the matrix's separation of source status from delivery status. Table B carries the matrix cell for the same component and app in the column `matrix 10-11` (value read from `matrix.json`; `no row` where the component has no matrix row; `n/a` for the RightKitSwift umbrella, which the matrix splits into 15 product rows).
- New in this document: tier and M-row ids from the mandatory set; RK Fable class letters; live and tree versions; per-app pins with file:line; pin status vs live and vs the set minimum; the per-app change and required action; blockers and daemon-0.4.0 coupling. The matrix is dated 2026-10-11 and has no row for 16 of the 34 Table A units (job-queue, child-process, tauri-shell, credentials, device, issues-tracker, onnx (the matrix still names it `rightkit-ort`), ffmpeg, overlay-win, docs, qa-driver, spend, android, google-identity, vault, motion), so those cells read `no row`.
- Vocabulary collisions to keep apart: matrix `M` (shared and local overlap) vs mandatory-set rows `M1`-`M25` vs RK Fable class `M` (mandatory) vs class `A(n)` (add-on serving n apps) vs `S` (app-specific). In this file a row id is always written `M6`, a matrix cell is only in the `matrix 10-11` column, and an RK Fable class is always written `RKF ...`.
