# RightKit dependency audit, batch 1 (12 crates)

Date: 2026-10-08. Read-only audit. No source, manifest, or lockfile was edited and nothing was committed.

Crates: `agent-room-core`, `rightkit-agent-tools`, `rightkit-asr`, `rightkit-audio`, `rightkit-automation`, `rightkit-browser`, `rightkit-cache`, `rightkit-computer`, `rightkit-control`, `rightkit-crash`, `rightkit-db`, `rightkit-embed`.

## Method and caveats

- **Tree measurement.** `rightkit cargo tree` ran against a scratch copy of the workspace manifest in the session scratchpad. The repo workspace could not load because `crates/rightkit-align/` is an empty directory with no `Cargo.toml`, which another worker is creating. The scratch copy lists only members that have a manifest, symlinks `crates/`, and copies `Cargo.lock`. Nothing in the repo was touched. The scratch lock differs from the repo lock only in packages outside these 12 trees (`dirs-sys`, `allocator-api2`, `bytecount`, `email_address`, `borrow-or-share`). None of those appear in any of the 12 trees, so the numbers below are unaffected.
- **Measured.** "Crates added" is the number of unique registry crates that become unreachable from the crate's normal+build graph when the direct edge is removed. Computed by graph reachability over `cargo tree -e normal,build --prefix depth` output, default features, host target (macOS). Every number in a "measured" column comes from this method or from a direct `cargo tree` count. Local path crates are excluded from counts.
- **Estimated.** Windows-only dependencies cannot be measured here. The broker rejects `--target x86_64-pc-windows-msvc` ("managed Rust target must be registered by broker"). Windows figures come from the `Cargo.lock` dependency lists and Cargo.toml, and are marked estimated. Effects of feature changes that have not been built are also estimated.
- **Not checked.** RustSec advisories were not queried (no network advisory access in this session). Unmaintained status is therefore not assessed. Crate versions were not checked against upstream.
- **Use sites.** Each use site was found by grepping the crate's `src/` and `build.rs` (tests and examples excluded for runtime deps). Cited lines come from those greps. No build.rs exists in any of the 12 crates.
- **Versions.** Published/staged state comes from `packages/release/rightkit-versions.json`. Its `cargo` key lists the published version and `stagedCargo` lists the staged version. `legacyCargo` lists earlier published versions.

## 1. agent-room-core

### A. Identity
- Path: `crates/agent-room-core`. Version 0.3.0 (source). Edition 2021, rust-version 1.98.0.
- Publish state: manifest says `publish = false`. Release manifest lists `0.3.0` under `stagedCargo`, which conflicts with `publish = false`. Treat as **staged-but-unpublishable** until reconciled.
- Platforms: macOS, Windows, and Linux. Runtime shell-outs cover `open` (room.rs:771), `xdg-open` (room.rs:776), `explorer.exe` (room.rs:763), `taskkill.exe` (room.rs:1008), `powershell.exe` (room.rs:1565), and `icacls.exe` (runtime.rs:57, 82).

### B. Responsibility
Shared agent-room state: append-only room store with SHA-256 receipts, protocol turns and events, runtime file, auth tokens, and a local axum HTTP and SSE host. One sentence: it owns the shared "agent room" state machine and its local HTTP server.

Public API (lib.rs:3-7): `pub mod auth`, `protocol`, `runtime`, `server`, `store`. Key items: `server::serve` (server.rs:681), `store` (SQLite via rusqlite), `protocol` (event and turn types, canonical JSON hashing at protocol.rs:437-451), `auth` (token hashing at auth.rs:197). Binary: `room` (src/bin/room.rs).

### C. Consumers
- RightKit crates depending on it: none (no Cargo.toml in `rightkit` names it as a dependency).
- Apps: none found in any app manifest.
- Mentions only: `crates/rightkit-oauth/examples/server_axum.rs:1` says the Axum adapter is "already used by RightKit's agent-room-core". That is a comment, not a dependency.

- Default features (none on the crate itself): **80** unique external crates (measured).

### F. Problems
- Two unrelated jobs in one crate: a pure room-state library (store, protocol, auth) and an HTTP host with a CLI binary. This forces axum and tokio-stream onto every consumer.
- Windows ACL is done by shelling out to `icacls.exe` (runtime.rs:57-60, :82). `rightkit-fs::restrict_owner_only` already provides native owner-only DACLs with an icacls fallback (`rightkit-fs/src/private.rs:5`, :16). This is a duplicate and should call rightkit-fs (which would add a dependency; see Recommendations).
- Atomic writes use bare `std::fs::rename` (store.rs:234, :316, :386), not `rightkit_fs::atomic_write`.
- `rightkit-ownership.json` declares "declaration-only detection", so this crate has no implementation fingerprint.
- Process spawns in `bin/room.rs` (lines 186, 763-776, 1008-1019, 1110, 1300, 1565) duplicate what `rightkit-process` does. The binary is not a library concern.
- `rusqlite` `bundled` pulls vendored SQLite C into every consumer.
- `crates/agent-room-core/artifacts/council-room` is in the crate directory; not inspected further.

### Verdict
Split `http` (axum, tokio-stream, tokio `net`) behind a default-off feature. Replace `rand` with `getrandom`. Route the Windows ACL through `rightkit-fs`. Decide whether `publish = false` or the staged 0.3.0 entry is correct.

### F. Problems
- **Build-time network fetch on by default.** `ort-defaults` includes `ort/download-binaries` (Cargo.toml:56). The download is SHA-256-verified (`build/download/verify.rs`). Removing it saves 27 crates (measured). `rightkit-vad`'s default feature is the path that turns it on for this crate, and this crate's own `ort-defaults` repeats it.
- **Pinned pre-release.** `ort =2.0.0-rc.13` is an exact pin on a release candidate. Consumers that also use `rightkit-ort`, `rightkit-embed`, `rightkit-ocr`, `rightkit-qts`, or `rightkit-vad` must match this exact version (lock shows one ort copy, so no duplicate today).
- **Unused dependency:** `eyre` (2 crates measured).

- **Runtime library loading:** whisper.cpp is loaded via `libloading` (cpp.rs:253-271). The loaded library path and any ABI assumptions are unverified here.
- **Two ONNX Runtime loading strategies in the tree.** This crate uses static/download (`download-binaries`); `rightkit-embed` uses `load-dynamic` (embed Cargo.toml). Both can exist in one app.
- **Derivative source.** Local patches are listed in `PATCHES.md`. Upstream drift is not measured here.
- No `cfg(windows)` deps. `libloading` Windows branch at cpp.rs:254 uses `libloading::os::windows`, which is feature-free.

### Verdict
Set `rightkit-vad` to `default-features = false` and drop `download-binaries` from `ort-defaults` (or make it an explicit opt-in feature). Remove `eyre`. Put `tokenizers` behind a Parakeet feature if any consumer runs only Whisper.

Dev-dependencies: `rusqlite 0.40.1` **with `bundled`** and `tempfile 3` (tests only). The dev `bundled` feature does not carry to consumers, so consumers must enable SQLite themselves. Correct for dev-only, but it means a consumer's tests may pass while their production build links system SQLite.

### E. Totals
- Default: **90** unique external crates (measured).
- Minimal: **90** (the crate has no features; `rusqlite` is already at default-features off). Consumers that want the vector store only and no embedder cannot drop `ort` or `tokenizers` without a feature split (estimated: 58 + 4 + 2).

### F. Problems
- **No feature passthrough for `rusqlite` bundled.** A consumer building `rightkit-embed` on a host without a system SQLite fails. Add a `bundled` feature that forwards to `rusqlite/bundled` (or depend on `rightkit-db`, which already has it).
- **Duplicate responsibility:** the vector store opens its own SQLite connection (`vector.rs:1`) instead of using `rightkit-db`, so WAL, busy timeout and durability profile are not applied to embeddings. Route through `rightkit-db`.
- `ort` pinned `=2.0.0-rc.13` exact (matches `rightkit-asr`, `rightkit-ort`, `rightkit-ocr`, `rightkit-qts`, `rightkit-vad`). Good for avoiding duplicates; a pre-release pin.
- `sha2` 0.10.9 is the workspace majority, but 0.11.0 is used by `rightkit-cache`, `rightkit-models`, `rightkit-pdf`, and `lopdf`.
- Feature split candidate: `tokenizers` (58 crates) is needed for `Embedder` only. A `vector-only` build (VectorStore + cosine) would save 58 + 4 + 2 crates (estimated) if `ort` and `tokenizers` move behind an `embedder` feature.
- Apps (CodeRight, MailRight) still on `fastembed` (drafts). Adoption gap.

### Verdict
Add a `bundled` passthrough. Put `ort`, `tokenizers`, `serde_json`, `sha2` behind an `embedder` feature so the vector store alone is cheap (estimated 60+ crates). Route the vector store through `rightkit-db`.

## Security-relevant items

- **rightkit-asr: build-time network fetch enabled by default.** `ort` `download-binaries` (via `ort-defaults` and `rightkit-vad` default) downloads ONNX Runtime binaries during build (ort-sys `build/download/`, `dist.tsv` with SHA-256, verified in `verify.rs`). Brings ureq, native-tls, security-framework, socks, lzma-rust2 (27 crates, measured).
- **Pre-release pin:** `ort =2.0.0-rc.13` exact (asr, embed, ort-based crates).
- **Vendored C:** SQLite (`libsqlite3-sys` via rusqlite `bundled`: rightkit-db default, agent-room-core, rightkit-embed dev); Oniguruma (`onig_sys` via tokenizers `onig`: rightkit-asr, rightkit-embed); OpenSSL only when `rightkit-db/sqlcipher` is selected.
- **Runtime dynamic library loading:** `rightkit-asr` loads whisper.cpp via `libloading` (whisper/cpp.rs:253-271). `rightkit-embed` loads ONNX Runtime via `load-dynamic`. Path and ABI trust not verified.
- **Process spawning outside `rightkit-process`:** agent-room-core (`icacls.exe`, `open`, `xdg-open`, `explorer.exe`, `taskkill.exe`, `powershell.exe`), rightkit-control (`lsappinfo`, `pgrep`, `open`, `screencapture`; mac.rs:162-533), rightkit-automation (`/usr/bin/open`, `/usr/bin/plutil`, `/usr/sbin/screencapture`), rightkit-crash (`/usr/bin/sample`, native.rs:52). Review argument construction for user-controlled values.
- **Shell watchdog:** rightkit-browser runs `/bin/sh -c` with a fixed script (proc.rs:125) to kill a Chrome process group. Fixed string; no injection path found in read-only inspection.
- **Git dependencies:** none in these 12 manifests.
