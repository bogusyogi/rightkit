# RightKit npm package dependency audit and inventory (2026-10-08)

Scope: the 22 non-private packages under `rightkit/packages/`: app-shell, ax, doc-render, git, hooks, i18n, legal-ui, legal, license, logs, media-ui, onboarding, pdf-ui, platform-ui, qa-chrome, qa, release, settings-ui, shell, tauri, theme, updates. Private packages (agent-room-mcp, build-control-*) are out of scope.

Method and measurement labels:
- **Closure** = unique `name@version` packages in the production tree (`dependencies` + `optionalDependencies`, peers excluded, dev excluded), computed by walking `pnpm-lock.yaml` `importers` and `snapshots` (script run against the lockfile, lockfileVersion 9). Labelled **measured (lockfile)**.
- **Exclusive** = packages reachable only through that direct dependency, i.e. the count removed if it were dropped. **Measured (lockfile set difference)**.
- **Published** = `pnpm view <name>@<src version> dependencies peerDependencies optionalDependencies` against the registry. Labelled **measured (registry)**.
- **Consumer versions** = `package.json` grep across the app repos under `/Volumes/D/claude/` (section not separated in that pass). **Measured (grep)**.
- **Consumer duplicates** = `grep @rightkit/...@` in each app `pnpm-lock.yaml`. **Measured (lockfile)**.
- Use sites are `file:line`, max 5. "UNUSED" means no reference in src, test, dist, README, or styles after grepping the whole package excluding `node_modules`.
- Feature sets: npm packages have no feature flags, so the "minimal feature set" total equals the default total.
- Rust, Swift, and the cross-cutting sections G–K are out of this npm lane.

## Cross-package findings

1. **tauri forces a second `updates` copy into consumers (measured).** `@rightkit/tauri@0.1.1` declares `"@rightkit/updates": "0.2.4"` (exact, registry). Its only use of updates is `import type { AutoUpdateClient }` at `packages/tauri/src/index.ts:1`, so it should be a peer. Current `updates` is 0.2.5. Consumer lockfiles show two `@rightkit/updates` copies (0.2.4 and 0.2.5) in mailright, viewright, heardright/tauri-app-next, and coderight-tauri, and 0.2.3 and 0.2.5 in scraperight (its `tauri@0.1.0` pins `updates@0.2.3`). Measured (lockfile). The in-repo lockfile instead links `packages/tauri` to `link:../updates` at 0.2.5, so the workspace build and published consumers resolve different copies. Measured (`pnpm-lock.yaml:487-493`).
2. **doc-render ships mermaid and katex, neither used (measured).** Zero references to `mermaid` or `katex` in doc-render src, test, dist, README, or styles. Math is rendered as raw text in `packages/doc-render/src/renderers.tsx:71-72` (`<pre class="rk-doc-math">` and `<code>`), so KaTeX was never wired. Mermaid is 109 exclusive packages. Consumer viewright lockfile carries `katex@0.16.47`, `0.16.8`, `0.18.7` and `mermaid@11.17.2` (measured).
3. **Exact pins published to consumers.** `@rightkit/tauri` (updates `0.2.4`), `@rightkit/qa` (qa-chrome `0.1.3`, from `workspace:*`), and `@rightkit/release` (smol-toml `1.7.0`). The first is the only one that produces a measured duplicate.
4. **Peer/dependency ranges.** Peer React ranges are inconsistent: `<20` in app-shell, legal-ui, platform-ui, settings-ui, onboarding; `<21` in doc-render, i18n, media-ui, pdf-ui, release peers. Several settings-ui peers have no upper bound (`@rightkit/license >=0.1.0`, `@rightkit/logs >=0.1.0`, `@rightkit/updates >=0.2.0`).
5. **Registry vs `packages/release/rightkit-versions.json`.** All 22 packages' registry `latest` equals source version (measured). The manifest's `npm` section is stale (e.g. `@rightkit/doc-render` is absent from `npm` and listed only as `stagedNpm`, yet is published at 0.1.3). Treat the manifest as stale.

## Verdict and recommended changes (ordered by packages saved)

1. **doc-render**: remove `mermaid` and `katex` (UNUSED). Saves 111 packages and removes all eight duplicate-version cases in consumers. Decide `remark-math`: either wire KaTeX rendering or drop the plugin. Risk: low (no references), but confirm no consumer relies on the `katex` peer side effect; none found.
2. **tauri**: move `@rightkit/updates` from `dependencies` to `peerDependencies` (type-only use). Republish. Removes a second updates copy from every consumer (measured in 5 apps). Risk: medium; consumers must install updates directly (all six consumers already do).

4. **updates**: remove or relocate `UPDATE_HOST_CONTRACT_VECTORS` out of the runtime entry (test-only). Risk: low; check the two test consumers.
5. **logs / tauri**: have tauri import `RIGHTKIT_LOGS_*_COMMAND` from `@rightkit/logs` instead of repeating the literals. Risk: low.
6. **Peer ranges**: align peer React to `<21` (or `>=18 <21` everywhere) and add upper bounds to settings-ui peers `license`, `logs`, `updates`. Risk: low.
7. **Stale manifest**: update `packages/release/rightkit-versions.json` (`npm` section lags the registry; all 22 are published at source version). Risk: none.
8. **Consumer drift**: bump consumers to current versions (updates 0.2.5, logs 0.1.4, license 0.1.8, onboarding 0.2.3, theme 0.2.1, release 0.2.135). Risk: low, but each bump is a change in consumer repos and needs the owning app's approval.
