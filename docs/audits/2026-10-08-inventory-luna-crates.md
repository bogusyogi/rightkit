# RightKit Rust inventory

**Scope & evidence.** Read-only inventory of current checkout under `/Volumes/D/claude/tools/rightkit`; `docs/audits/` was not read. I observed **50 crate manifests**, although request specified 49; extra/currently present crate is `rightkit-contracts`. Source versions, descriptions, features & direct dependencies come from each `crates/<crate>/Cargo.toml`; public API evidence comes from `src/lib.rs` or cited modules. `packages/release/rightkit-versions.json` distinguishes published registry versions from staged source versions.

**Dependency-count limitation.** I could not measure default or minimal-feature transitive counts: `rightkit cargo tree ... --locked` refused because it would need to update `Cargo.lock`. I did not retry without `--locked`, because that could write the lockfile. Counts below are therefore **unmeasured**, not estimated. The required docs paths `tools/rightkit/README.md`, `docs/rules/README.md` & `docs/rules/rightkit.md` do not exist in this checkout; root `README.md` & `AGENTS.md` were present. `rightkit cargo metadata --no-deps` returned manifests but no resolved graph. No build or test was run.

**Status terms.** *Published* means source version matches `registry.cargo`; *staged* means source version is newer than registry; *unpublished* means `publish = false` or no registry entry. All dependency names below are direct dependencies from manifests; code references were searched, but no-use conclusions are made only where noted.

## G–I. Crate cross-cutting findings

- **Atomic writes overlap:** `rightkit-fs` owns atomic writes (`src/atomic.rs`), `rightkit-settings` exposes atomic writes (`src/atomic.rs`, re-exported in `src/lib.rs:7`), and `rightkit-cache` has temp-file/rename cache writes (`src/disk.rs:252`). Keep filesystem atomicity/permissions in `rightkit-fs`; have settings/cache call it or document why their stronger domain semantics differ.
- **Process ownership overlaps by layer:** `rightkit-process` owns child lifecycle; `rightkit-sandbox` owns sandbox/PTY/process-tree policy; `rightkit-browser` starts browser processes through `OwnedCommand` (`src/proc.rs:60`); `rightkit-computer` uses raw `std::process::Command` (`src/macos.rs:373`). Keep low-level ownership in process, policy/sandbox in sandbox, and route computer prototype through process if retained.
- **HTTP clients overlap:** `rightkit-http` owns `ureq` (`src/client.rs:261`); `rightkit-mcp` directly uses both `ureq` (`src/client.rs:251`) & `reqwest` (`src/advanced_http.rs:8`). Assess whether MCP’s advanced async HTTP can be an adapter over one shared transport contract; do not collapse until async streaming requirements are checked.
- **ONNX Runtime setup is fragmented:** `rightkit-ort` owns runtime setup; `rightkit-embed` directly imports `ort::session::Session` while also depending on `rightkit-ort` (`src/embedder.rs:4–5`). `rightkit-vad` declares direct `ort` plus a `rightkit-ort` dev dependency. Route runtime setup through `rightkit-ort`; avoid duplicate ORT ownership.
- **Settings/secret boundaries:** `rightkit-settings` offers a `SecretProbe` abstraction; `rightkit-secrets` optionally implements it (`Cargo.toml` feature + `src/store.rs:309`). This is a sensible optional adapter boundary; avoid folding credential persistence into settings.
- **Duplicate hashing:** crates use SHA-2 for distinct purposes (`rightkit-cache/src/key.rs:5`, `rightkit-embed/src/embedder.rs:9`, `agent-room-core/src/auth.rs:4`). Keep domain-level hashes local unless one shared API can preserve each crate’s canonicalization contracts.
- **Removal/merge candidates:** `rightkit-computer` is explicitly a macOS prototype with no declared dependencies/consumers (`Cargo.toml:2–8`); remove or graduate only after app-use check. `rightkit-align`, `rightkit-compose`, `rightkit-transcript`, `rightkit-asr`, `rightkit-tts`, & `rightkit-vad` are unpublished internal crates; their role split is coherent around transcript, alignment, composition, ASR, TTS & VAD, so no evidence supports merging them wholesale. `rightkit-qts-ggml` is intentionally thin over `-sys`; retain if it provides the safe boundary, otherwise merge wrapper into `rightkit-qts` and keep `-sys` internal. |
