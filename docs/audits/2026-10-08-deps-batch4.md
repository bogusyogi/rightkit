# RightKit dependency and inventory audit, batch 4 (2026-10-08)

Scope: crates rightkit-secrets, rightkit-service, rightkit-settings, rightkit-shell, rightkit-speech-client, rightkit-sync, rightkit-tauri, rightkit-transcript, rightkit-tts, rightkit-vad, rightkit-watch (sections A to F, plus the dependency tables from the original brief), and the workspace section J. Cross-cutting sections G to I and K belong to other batches and are not covered here.

## Method and limits

- **Measured.** Transitive counts come from `rightkit cargo tree -p <crate> -e normal,build --prefix depth --no-dedupe`, run with the `--offline` flag. "Crates added" for a direct dependency is measured as its subtree minus the subtrees of its sibling direct dependencies (exclusive). That is a subtree-set difference, so feature unification effects are ignored. Dev-only extra is the count from `-e normal,build,dev` minus the normal and build count.
- **Workspace in scratch.** At audit start `crates/rightkit-align` had no `Cargo.toml` (empty directories, untracked), so `rightkit cargo` refused to load the workspace. I did not edit the repo. I built a scratch workspace in the session scratchpad with symlinks to each crate directory and a copy of `Cargo.lock`, excluding align, and ran `cargo tree --offline` there. The scratch lock differed from the repo lock only by adding the `rightkit-compose 0.0.0` entry, with no new external packages. The graphs for these 11 crates do not depend on align, so the counts are unaffected.
- **Host-only.** `x86_64-pc-windows-msvc` is not registered with the RightKit broker (`managed Rust target must be registered by broker`). Windows-only dependencies (windows, windows-sys, webview2-com, tauri-winrt-notification) are therefore **not measured**; they are named but not counted. Host counts are for the default target as resolved on this Mac.
- **Broker instability.** Partway through the session `rightkit` returned `EXTERNAL_ROOT_UNREADABLE ... (timeout)` for every command. Measurements taken before that point are the ones reported. The one measurement that was pending at the time of writing is marked as such.
- **Not verified from source.** The ort-sys build-script network download and the TLS stack behind `download-binaries` and `tls-native` are described from the feature names. The crate sources are not in the local cargo registry cache, so the build script was not read.
- **Use sites.** Each use site was found with `grep -rn` over `src/`, `build.rs`, `tests/`, `examples/`, and `benches/` of the crate. Max five per dependency. "UNUSED" means no reference was found in the whole crate, excluding tests for runtime dependencies.
- **Lock snapshot.** `Cargo.lock` changed during the session (other workers added `rightkit-align` and `rightkit-compose`). Its count moved from 789 to 815 packages. Section J uses the current file.

## Release status source

`packages/release/rightkit-versions.json` has two cargo maps. The `registry.cargo` map gives the published version and the top-level `cargo` key gives an older list. Where they disagree, both are shown. `stagedCargo` gives the staged version.
