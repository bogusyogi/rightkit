1. **P1 — Cross-process clock commits still roll trusted time backwards.** [clock.rs:300](/Volumes/D/claude/rightkit/crates/rightkit-license/src/clock.rs:300). Default `compare_and_save` separates load from save; `LEDGER_LOCK` protects only one process. A checks ledger `900`, B saves `1100`, A saves `1000`; restart at `1001` can accept previously expired tokens. **Fix:** require atomic compare-and-save implementations; remove unsafe default or require cross-process serialization. Existing race tests override this default, so cannot validate it.

2. **P1 — macOS fallback still exposes secrets outside requested keychain.** [macos.rs:287](/Volumes/D/claude/rightkit/crates/rightkit-secrets/src/macos.rs:287), [macos.rs:310](/Volumes/D/claude/rightkit/crates/rightkit-secrets/src/macos.rs:310). Native add remains unchanged; destination checking happens afterward. If explicit keychain disappears & native fallback writes elsewhere, process termination before cleanup—or cleanup failure—leaves secret there permanently. **Fix:** use creation API whose explicit destination fails closed, such as appropriately configured `SecItemAdd`; post-write deletion cannot enforce isolation. Test at [macos.rs:792](/Volumes/D/claude/rightkit/crates/rightkit-secrets/src/macos.rs:792) checks ownership comparison, never fallback or cleanup failure.

3. **P1 — Windows add-if-absent can overwrite concurrent writes.** [windows.rs:188](/Volumes/D/claude/rightkit/crates/rightkit-secrets/src/windows.rs:188), [windows.rs:154](/Volumes/D/claude/rightkit/crates/rightkit-secrets/src/windows.rs:154). Only add-if-absent acquires `AccountLock`. A observes absence; B successfully sets credential; A calls unconditional `CredWriteW`, replacing B & returning `true`. Distinct services sharing one Windows prefix also acquire different locks for identical targets. **Fix:** lock every mutator using actual normalized credential target; factor unlocked internal write for lock-holding callers.

4. **P1 — Windows compatibility codec corrupts valid Unicode secrets.** [keyring_compat.rs:30](/Volumes/D/claude/rightkit/crates/rightkit-secrets/src/keyring_compat.rs:30). Writing text `"\u{4142}"` produces UTF-16LE bytes `[0x42, 0x41]`; reading classifies those bytes as legacy UTF-8 & returns `"BA"`. macOS returns original text. Existing Unicode tests miss this ambiguity. **Fix:** select encoding explicitly through namespace/version metadata; use UTF-16LE consistently for KeyringCompat & separate legacy UTF-8 migration.

5. **P1 — Migration deletes concurrently replaced source credentials.** [migrate.rs:35](/Volumes/D/claude/rightkit/crates/rightkit-secrets/src/migrate.rs:35), [migrate.rs:49](/Volumes/D/claude/rightkit/crates/rightkit-secrets/src/migrate.rs:49). Migration reads source A; another writer replaces source with B; migration verifies destination A & unconditionally deletes source B. Length-check repair does not prevent this loss. **Fix:** retain source until conditional deletion or cross-process migration/write serialization exists; copy-only migration is smallest safe change.

6. **P1 — Timed-out mutations remain live & can overwrite successful retries.** [store.rs:255](/Volumes/D/claude/rightkit/crates/rightkit-secrets/src/store.rs:255). `run` abandons worker without cancellation. Write A stalls, returns timeout; retry B completes successfully; A resumes & overwrites B. Public `Backend` permits this directly; Windows writes have no serialization preventing it. **Fix:** wait for mutation completion, or introduce cancellable serialized operations whose completion remains observable before permitting retries.

7. **P1 — Windows target prefix bypasses account isolation.** [namespace.rs:67](/Volumes/D/claude/rightkit/crates/rightkit-secrets/src/namespace.rs:67), [windows.rs:197](/Volumes/D/claude/rightkit/crates/rightkit-secrets/src/windows.rs:197). `Slash { prefix: Some("victim\0ignored") }` passes validation. Any account produces native target `"victim"` because Windows stops at NUL; delete can remove unrelated credential. **Fix:** validate prefix at construction & backend boundary, rejecting NUL/control characters & invalid target lengths.

8. **P2 — Helper secret copies still escape zeroization.** [apple_helper.rs:198](/Volumes/D/claude/rightkit/crates/rightkit-secrets/src/apple_helper.rs:198). Typed visitor removes `Value::String`, but escaped response `{"ok":true,"value":"secret\nvalue"}` decodes through serde_json’s ordinary scratch `Vec<u8>` before entering `WipedString`. That allocation remains unwiped; confirmed in locally available [serde_json source:1538](/Users/adrdsouza/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/serde_json-1.0.150/src/de.rs:1538). **Fix:** decode secret fields through zeroizing scratch storage, including error paths & reallocations.

9. **P2 — Helper timeout excludes blocking write & final wait.** [apple_helper.rs:149](/Volumes/D/claude/rightkit/crates/rightkit-secrets/src/apple_helper.rs:149), [apple_helper.rs:178](/Volumes/D/claude/rightkit/crates/rightkit-secrets/src/apple_helper.rs:178). Helper that never reads stdin can block sufficiently large requests forever; helper that closes stdout but stays alive blocks final `wait()` forever. **Fix:** apply one deadline across stdin, stdout & process exit; kill & reap on every failure.
