**BLOCKING**

**7 — P1, continuing: private PDFs remain exposed during or after saving.** Windows writes bytes at [commit.rs:84](/Volumes/D/claude/rightkit/crates/rightkit-pdf/src/commit.rs:84) into ordinary inherited-ACL temporary files; `ReplaceFileW` applies original DACL only afterward. On macOS, `0600` does not neutralize inherited ACL grants, & copying mode bits drops original explicit ACL restrictions. These contradict [Windows creation security](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights) & [macOS ACL precedence](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/FileSystemProgrammingGuide/FileSystemDetails/FileSystemDetails.html). **Fix:** establish restrictive ACL/DACL before writing, preserve original security metadata through handles, & fail closed on preservation failure; cover explicit restrictions & inherited grants on both platforms.

**13 — P1, NEW: Windows replacement failure deletes both versions.** [commit.rs:156](/Volumes/D/claude/rightkit/crates/rightkit-pdf/src/commit.rs:156) calls `ReplaceFileW` without backup; every error triggers temporary-file deletion [commit.rs:92](/Volumes/D/claude/rightkit/crates/rightkit-pdf/src/commit.rs:92). Microsoft explicitly documents `ERROR_UNABLE_TO_MOVE_REPLACEMENT` (1176): without backup, original no longer exists & replacement survives under its temporary name. Cleanup deletes that surviving copy. **This mechanism is wrong against [ReplaceFileW’s failure contract](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew). Fix:** preserve recoverable files, use protected backup storage, & implement explicit recovery states with separate cases for success, 1175, 1176, 1177 & ordinary failures.

**14 — P1, NEW guard defect: token “upper bound” permits multi-gigabyte parser allocation.** [inspect.rs:204](/Volumes/D/claude/rightkit/crates/rightkit-pdf/src/inspect.rs:204) counts `0q0q…` as one regular-character run. Pinned [lopdf 0.44 parser](https://raw.githubusercontent.com/J-F-Liu/lopdf/v0.44.0/src/parser/mod.rs) accepts each `0` operand followed by `q`, requiring no intervening whitespace. Thus 32 MiB of repeated `0q` passes preflight while creating roughly 16 million operations plus operand allocations, before walker limits run. Both platforms can exhaust memory. **Fix:** enforce allocation/token limits inside parsing, or use parser-equivalent bounded lexical validation; add adjacent-number/operator, signed-number & nested-container cases.

**15 — P1, newly identified class bypass: inherited-resource budget counts shallow entries but clones recursively.** [merge.rs:76](/Volumes/D/claude/rightkit/crates/rightkit-pdf/src/merge.rs:76) charges `/Resources << /XObject << … >> >>` as one entry, then clones its entire nested dictionary at line 85 onto every page. Ten thousand pages inheriting twenty thousand resource names produce 200 million copied entries while charging only ten thousand. `select_pages` materializes even unselected pages [merge.rs:131](/Volumes/D/claude/rightkit/crates/rightkit-pdf/src/merge.rs:131). Underlying amplification predates this fix; added guard leaves it exploitable on both platforms. **Fix:** share materialized resources indirectly, or charge recursive objects, names & bytes before cloning; cover nested resources & selecting one page from large inputs.
