# Astra read of rightkit-process 0.3.4 (working tree), 2026-10-11

Read-only review before a planned safety release. Verdict: do not publish. Findings verbatim:

1. **P1 — Recycled PGIDs remain signalable.** [process_handle.rs:134](/Volumes/D/claude/rightkit/crates/rightkit-process/src/process_handle.rs:134) reaps before checking membership; scheduling can pause between those operations long enough for reuse. [owned.rs:419](/Volumes/D/claude/rightkit/crates/rightkit-process/src/owned.rs:419) exposes `child().wait()/try_wait()`, allowing an arbitrarily long unsealed interval. Concrete scenario: reap through accessor, retain owner, PID recycles into unrelated group, drop owner: delayed seal sees that group & kills it. Likewise, seal with surviving grandchild, let grandchild die, recycle PGID, then drop: membership check accepts unrelated group. Even observing absence later does not permanently retire this seal. README/CHANGELOG do **not** document residual recycling risk; comments incorrectly claim safety.

2. **P1 — Check-then-signal & clone races remain.** [process_handle.rs:161](/Volumes/D/claude/rightkit/crates/rightkit-process/src/process_handle.rs:161), [owned.rs:524](/Volumes/D/claude/rightkit/crates/rightkit-process/src/owned.rs:524): `kill(-pgid, 0)` cannot establish identity for subsequent SIGTERM/SIGKILL. Last member can disappear & PGID recycle between syscalls; window is normally short but unbounded under descheduling. Even “leader still running” can become stale when another `ProcessHandle` clone reaps before signal; detached direct-PID termination has equivalent race. Additionally, `sealed.swap(true)` publishes completion before `empty.store(...)`. `wait_timeout`, bounded termination & `wait_or_kill` all reach these paths.

3. **P1 — Descriptor bound can deadlock pipe consumers.** [process_unix.rs:124](/Volumes/D/claude/rightkit/crates/rightkit-process/src/process_unix.rs:124), [process_unix.rs:456](/Volumes/D/claude/rightkit/crates/rightkit-process/src/process_unix.rs:456): another thread can `dup2` a pipe writer above scanned highest+1024 before fork; lowest-first allocation does not constrain explicit duplication. Helper retains writer even with CLOEXEC because helper never execs. Engine waiting for stdin EOF then waits forever while helper waits for engine exit. Enough concurrent opens can also place std’s exec-error writer above bound, blocking `spawn()` after successful arming. Rust waits for that pipe’s EOF on successful exec. [Rust spawn implementation](https://raw.githubusercontent.com/rust-lang/rust/master/library/std/src/sys/process/unix/unix.rs)

4. **P1 — Parent-death protection disappears before descendants exit.** [process_unix.rs:543](/Volumes/D/claude/rightkit/crates/rightkit-process/src/process_unix.rs:543): launch `sh -c 'sleep 600 &'`, retain `OwnedChild`, then SIGKILL supervisor after shell exits. Helper already exited on engine NOTE_EXIT, so grandchild survives. Comment claiming descendants exist only when supervisor also died is false. README describes helper’s early exit but still promises group cleanup.

5. **P1 — Nested `fork()` can deadlock before timeout starts.** [process_unix.rs:229](/Volumes/D/claude/rightkit/crates/rightkit-process/src/process_unix.rs:229) invokes libc `fork` from `pre_exec`, re-running registered atfork callbacks. Concrete embedding: prepare callback locks mutex, parent callback unlocks, child callback absent because children normally immediately exec. First fork leaves mutex locked in engine; second fork re-enters prepare & deadlocks. No ack timeout has started. No explicit allocation/env access appears in helper body, but its blanket async-signal-safety claim ignores these callbacks. [Apple pthread_atfork documentation](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/pthread_atfork.3.html)

6. **P2 — Windows spawn semantics change incompatibly.** [owned.rs:120](/Volumes/D/claude/rightkit/crates/rightkit-process/src/owned.rs:120): `from_command` now supplies default config for allowlisted spawns. Wrap `Command` configured with `env_clear()` & piped stdout, then call `inherit_handles_only`: previously rejected without explicit config; now silently inherits parent environment/stdout, potentially exposing environment secrets & losing expected pipe. No public signature removal found; this behavioral regression is unsuitable for safety patch.

7. **P2 — “Other Unix” sampling assumes Linux procfs.** [usage.rs:213](/Volumes/D/claude/rightkit/crates/rightkit-process/src/usage.rs:213): FreeBSD/macOS-adjacent Unix targets without `/proc/self/statm` always return error. Typical macOS/Windows/Linux byte & CPU conversions are correct; macOS offsets match [Apple’s structure](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/sys/resource.h). Sampling performs synchronous calls; failures propagate as `io::Error`. Arithmetic is unchecked: particularly signed block-counter addition at line 236 can overflow on 32-bit Unix. `observe_idle` deliberately blocks.

Complete identity protection requires retaining ownership until final signal. `waitid(WNOWAIT)` can retain leader without reaping, but **every** reap path must cooperate, including public accessor & clones; current `wait()` immediately follows WNOWAIT with reaping. Thus no isolated seal tweak completely fixes this API.

Other checks: detached reaper, post-drop clones & stderr thread send no signals themselves. Windows job/process termination remains handle-based. Helper-only SIGPIPE/SIGTERM changes do not affect engine; directory scans happen before fork. Ack timeout returns ETIMEDOUT, kills/reaps helper, then std exits/reaps failed engine; exec failure triggers helper’s engine-exit watch. Normal helper exit is orphan-reaped; no normal persistent zombie demonstrated. Actual PID-1 parent passes equality check.

Tests: with identical signal instrumentation, first two new seal tests reject old unconditional kills; survivor test already passes old behavior. Missing: accessor reap, forced reuse, clone interleavings, late-grandchild death, high-FD EOF, TERM-resistant escalation & descendant survival after engine exit. Read-only review; tests not executed. Requested HEAD already labels manifest 0.3.4.

**Verdict: do not publish.**
