# Astra adversarial review of the rightkit-fsindex spec (2026-10-10)

Model: gpt-6-astra, reasoning high, read-only sandbox via Codex CLI 0.161.0; inputs: the spec, crates/rightkit-fsindex at 0.1.1, Pulse, CodeRight/Membrane sources. Untrusted advice until each adopted claim is verified against source (see the spec v2 changelog).

1. **P2 — Current API inventory is inaccurate (§4).** `Item.ext` does not exist; `Item.kind` does. Search returns `Result<Vec<Hit>>`, defaults to 100 results, coerces zero limit to one, & searches basenames. `SortKey::Name` actually sorts allocation before name. Config defaults, error variants, bounded-16 subscription, size fields & feature-gated content method otherwise match. **Fix:** publish exact signatures, defaults & ordering; distinguish existing API from additions. Evidence: [index.rs:44](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/index.rs:44), [index.rs:572](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/index.rs:572), [index.rs:663](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/index.rs:663).

2. **P2 — Search semantics need qualification (§8).** Token AND, operators, score caching, heap & typo cost match source. However, matching folds ASCII bytes; “≥5 letters” means ≥5 bytes, first-character typos fail, empty/negative-only queries fail, & tokens exceed 128 bytes only by error. **Fix:** specify these restrictions & decide Unicode behavior explicitly. Evidence: [query.rs:39](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/query.rs:39), [query.rs:288](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/query.rs:288).

3. **P1 — Rollups do not implement implied folder-local uniqueness (§8).** Hard links have one global owner; sibling folders containing secondary links receive zero bytes **& zero files**. Clone groups use global maximum shared size in every containing folder, even where that folder’s member is smaller; clone keys omit device identity. Single-file unique=allocated & package-extension behavior match. **Fix:** choose global attribution versus per-folder distinct accounting, define file counts, namespace clone keys by volume, & label clone estimates. Evidence: [store.rs:778](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/store.rs:778), [store.rs:835](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/store.rs:835), [store.rs:899](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/store.rs:899).

4. **P2 — Store description hides important limits (§5).** RKFSIX02, 76-byte entry columns, 36-byte directory columns, 16-MiB name segments, fingerprint & reopen predicates match. Free-list reconstruction scans **all slots**; only link/clone reconstruction filters SPECIAL. Compaction additionally requires >50,000 slots. More than 64 roots are silently omitted from committed header. **Fix:** document linear reopen work, reject excess roots, distinguish measured footprint from format size. Evidence: [store.rs:333](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/store.rs:333), [store.rs:469](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/store.rs:469), [index.rs:1064](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/index.rs:1064).

5. **P1 — “Crash safety” lacks corruption/concurrency guarantees (§5).** Dirty-flush failures can be ignored; clean stores lack structural validation before following indexes. No exclusive store lock prevents concurrent mutable mappings or destructive rebuilds. Swap removes current directory before rename & ignores failures. **Fix:** exclusive ownership, validated columns/links, durable replacement protocol, explicit write-failure state & rebuild-on-corruption. Evidence: [store.rs:410](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/store.rs:410), [store.rs:263](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/store.rs:263), [index.rs:1416](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/index.rs:1416).

6. **P1 — Windows schema cannot represent proposed metadata (§§5–6).** Current `dev:u32`/`fileid:u64` cannot represent [64-bit volume serial + 128-bit identity](https://learn.microsoft.com/en-us/windows/desktop/api/winbase/ns-winbase-file_id_info). Attributes & reparse tag are separate ULONGs, not one u32. RKFSIX03 conflicts with “02 reopens unchanged” unless dual-format handling exists. **Fix:** version complete schema, separate fields, explicit migration/rebuild rules & volume incarnation tracking. Coordinate `rightkit-fs::FileKey`, also currently 64-bit-index based. Evidence: [backend/mod.rs:37](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/backend/mod.rs:37), [identity.rs:38](/Volumes/D/claude/rightkit/crates/rightkit-fs/src/identity.rs:38).

7. **P1 — Enumeration fallback loses identity (§6.2).** FileIdExtdDirectoryInfo is unavailable before Windows 8/Server 2012; filesystem/redirector support also needs probing. FileFullDirectoryInfo lacks file ID & reparse tag; FileIndex is not stable identity. **Fix:** qualify supported OS/filesystems, prefer FileIdBothDirectoryInfo where suitable, define missing-metadata states & narrowly scoped metadata queries. Restart enumeration safely after class fallback. Sources: [information classes](https://learn.microsoft.com/en-us/windows/win32/api/minwinbase/ne-minwinbase-file_info_by_handle_class), [fallback structure](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_full_dir_info).

8. **P1 — Lazy hard-link discovery cannot use existing core (§6.2).** `attach()` & reopen reconstruction only group entries when `nlink>1`. Detecting second occurrence without nlink requires indexing identities for first occurrences too. **Fix:** specify identity map, promotion/ownership rules, persistence, deletion/replacement handling & memory budget; never invent identity when fallback lacks it. Evidence: [store.rs:355](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/store.rs:355), [store.rs:904](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/store.rs:904).

9. **P1 — `\\?\` does not make shared core Windows-ready (§6.2).** Core splits paths exclusively on `/`, compares byte-exact components, & converts Windows paths through lossy UTF-8. This breaks native separators, unpaired UTF-16, aliases & case-insensitive lookup. **Fix:** lossless platform path representation; separate canonical identity, display spelling & search normalization; define UNC/verbatim paths, per-directory case sensitivity & macOS normalization. Evidence: [index.rs:175](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/index.rs:175), [store.rs:1039](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/store.rs:1039).

10. **P1 — “Never hydrate” is unproven (§§3,6).** `OPEN_REPARSE_POINT` does not secure every ancestor against replacement; blanket non-descent also omits locally available cloud-directory children. Recall-on-open needs handling alongside offline/data-access states. Content indexing later performs ordinary reads without placeholder checks. **Fix:** explicit reparse/recall capability matrix, pinned traversal, incomplete-subtree reporting & hydration-safe content eligibility. Sources: [default-stream EOF](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_full_dir_info), [compressed/sparse storage API](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getcompressedfilesizew).

Optional ENUM_USN_DATA returns records without size/allocation, so cannot alone replace crawl. Sources: [journal access](https://learn.microsoft.com/en-us/windows/win32/fileio/using-the-change-journal-identifier), [USN fields](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/d2a2b53e-bf78-4ef3-90c7-21b918fab304), [index.rs:444](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/index.rs:444).

**Five highest-value changes, ranked:**

1. Specify freshness, completeness, cursor epochs, replay & fallible barriers.
2. Redesign Windows identity/path/store schema before backend implementation.
3. Replace consumer “delete/feed” promises with explicit parity contracts.
4. Define accounting accuracy, unavailable metadata & privacy boundaries.
5. Make adversarial platform/consumer qualification measurable release gates.

**Verdict: do not ship as written.** Architecture direction is viable, but normative claims currently permit false freshness, incorrect accounting, incomplete reconciliation & privacy regressions. Rewrite these contracts first, then qualify Windows enumeration independently before authorizing scanner retirement or workspace adoption.

New defects introduced by v2:

- **P1 — Lock ownership breaks during replacement.** Renaming `index` moves its locked `index/lock` into `index.old`; replacement `index/lock` is another file. Another process can acquire it while original owner remains active. Put lock outside swapped directories, acquire before recovery/creation, & retain throughout migration. [v2 §5](/Volumes/D/claude/rightkit/docs/plans/2026-10-10-rightkit-fsindex-spec.md:81)

- **P1 — Privacy default can weaken Pulse protection.** `home_dirs` discovers exclusion locations, not indexed roots: [source](/Volumes/D/claude/rightkit/crates/rightkit-fsindex/src/index.rs:403). Pulse explicitly indexes mount roots & relies on those exclusions: [caller](/Volumes/D/claude/pulse/hub/src-tauri/src/disk_index.rs:198). Simply disabling discovery leaves other users’ homes inside indexed volumes while removing protected-folder exclusions. Define home authorization separately from exclusion discovery. [v2 §10](/Volumes/D/claude/rightkit/docs/plans/2026-10-10-rightkit-fsindex-spec.md:154)

- **P1 — Revocation purge misses actual access boundaries.** Losing access to `/Users/me/Library/Mail` does not make root `/` unreadable. Root-only purge therefore preserves sensitive entries; deleting live entries also says nothing about names arenas, retained batches, or `index.old`. Specify subtree access revalidation & deletion across every retained representation. [v2 §10](/Volumes/D/claude/rightkit/docs/plans/2026-10-10-rightkit-fsindex-spec.md:156)

- **P1 — Cloud-directory exception defeats “never hydrate.”** “Directories are not placeholders” is false: Windows explicitly documents recall attributes for directories; enumeration itself can fetch remote contents. Successful handle opening does not establish safe enumeration. Require provider-aware no-recall traversal or report incomplete coverage. [v2 §6.2](/Volumes/D/claude/rightkit/docs/plans/2026-10-10-rightkit-fsindex-spec.md:104), [Microsoft attribute contract](https://learn.microsoft.com/en-us/windows/win32/fileio/file-attribute-constants).

- **P1 — Replay-before-open has no bounded completion contract.** “To completion” lacks captured upper USN, cancellation, notification-buffer limits, & overflow recovery during replay. Continuous churn can extend startup indefinitely; 0.2.0 offers no observable catching-up handle, despite Pulse’s 200-ms cancellation gate. “Zero-length read” also needs correction: distinguish `BytesToWaitFor=0` from zero-sized buffers; successful output still contains next USN. Specify valid probe, bounded replay frontier, atomic checkpoint publication, & cancellation. [v2 §6.2](/Volumes/D/claude/rightkit/docs/plans/2026-10-10-rightkit-fsindex-spec.md:107), [Microsoft USN contract](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-read_usn_journal_data_v0).

- **P1 — Retention is a minimum, not a memory bound.** “4096 batches or 15 minutes, whichever is larger” retains every burst inside 15 minutes & potentially ancient batches when idle. At 1024 paths/batch, 4096 full batches with 100-byte paths consume roughly **400 MiB in path bytes alone**. Add byte ceiling, eviction semantics, & explicit `NeedsRelist` boundaries. [v2 §7](/Volumes/D/claude/rightkit/docs/plans/2026-10-10-rightkit-fsindex-spec.md:126)

- **P2 — Identity-map budget excludes its value.** Full `(u64,u128)` key already occupies 24 packed bytes; slot adds four before alignment, occupancy, or allocator overhead. A compact indirect representation could meet budget, but none is specified. Budget actual representation, rehash peak, reopen reconstruction, & simultaneous old/new stores. [v2 §6.2](/Volumes/D/claude/rightkit/docs/plans/2026-10-10-rightkit-fsindex-spec.md:103)

- **P1 — Adapter digests do not establish consistent views.** Only `list()` accepts per-call adapter; search/subscription/replay lack equivalent selection despite “one index serves all three.” Digests cover files already read, without rules for newly created policies, external global ignores, or policy changes between pages.
