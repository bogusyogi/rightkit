# RightKit foundation work items (2026-10-24)

Source: `docs/research/2026-10-24-rightkit-vs-fastframe-matrix.md` (30-row comparison against Fastframe, ZapFast and Spotifast) and the RightPass and PlayRight design reviews of the same day. Each item below is one GitHub issue. Ranked by payoff. Evidence paths are relative to the repositories as checked out on 2026-10-24.

| # | Item | Why | Acceptance |
|---|---|---|---|
| 1 | Measure idle RSS and cold start of every hub on macOS and Windows | No Right Suite hub has a number; MailRight's homepage figure is marked unverified. ZapFast's method (process-tree PSS, first window, usable UI, medians of paired runs) is the template | A `docs/measurements/` table per app and OS; method documented; numbers in each shell README budget rows |
| 2 | WebView2 environment teardown for tray-resident apps | HeardRight measured 504 MB working set for a hidden hub (8 WebView2 processes, 72% per-environment overhead) against 47.6 MB for the Rust host; `TrySuspend` leaves about 458 MB (`heardright/docs/plans/2026-07-21-windows-slint-resource-correction.md`) | Experiment: do the `msedgewebview2` processes exit when the last Tauri window closes? If yes: shell option "destroy webview on hide, recreate on show". If no: a documented resident-host plus on-demand-hub-process pattern with a template |
| 3 | Split `rightkit-tauri-shell` into runtime-neutral crates plus a Tauri adapter | autostart, single instance, clipboard, presence, OS settings panes and deep links have zero Tauri references but ship inside the Tauri crate; Ember's egui host, SwiftRight (C ABI), the HeardRight menu-bar helper and overlay apps cannot use them. The shell pulls 191 crates | New crates (names to ratify) for autostart, instance, clipboard, presence, deep-link; `rightkit-tauri-shell` depends on them; dependency count recorded before and after |
| 4 | `rightkit-power`: sleep, resume, session lock and unlock, battery and saver, metered network, keep-awake | RightKit has no macOS sleep or session listener; the only suspend hook is Windows-only in `rightkit-audio::lifecycle`. RightPass "lock on sleep" and HeardRight reconnect-after-wake need it. Design after `fastframe-power`, add the macOS resume event it lacks | Crate with injected-data tests; HeardRight adopts for reconnect; RightPass design consumes it |
| 5 | Neutral notifications owner (actions, replace and withdraw by key, permission state) and dock or taskbar badges | `notify.rs` is usable only inside the Tauri crate; Linux unsupported; no actions or replace keys. `fastframe-notifications` is the reference API | Crate usable without Tauri; the shell delegates to it; fake-backend tests |
| 6 | Now-playing and media keys owner | None exists (only an untested `send_media_key`). Needed by `@rightkit/media-ui`, CutRight, ViewRight, PlayRight's native player | Crate over `souvlaki` (SMTC, MPNowPlayingInfoCenter) and `mpris-server`; one-owner rule documented |
| 7 | Rust localisation owner and resolved theme tokens for non-web UIs | `@rightkit/i18n` is React-only (237 lines, one adopter); the audit records "no Rust i18n owner"; Ember carries its own. `@rightkit/theme`'s resolver exists only in TypeScript | One catalog source (PO or Fluent) generated to TS, Rust and Swift; `rightkit-theme generate --json` emits resolved tokens; Ember and overlay-win consume them |
| 8 | Updater: reinstate rollback and add publisher-key rotation | Decision D01 (#771) removed the retained previous copy; boot probation answers "reinstall". A password manager and any tray-resident app need a failed update to leave the previous build working. `fastframe-update` rolls back when the new build does not report started within a minute and carries additional publisher keys | Rollback restored in `@rightkit/release`, `@rightkit/app-update` and `RightKitUpdate`, or an explicit per-app rule that MSIX or App Store distribution provides it; key rotation (`kid` or additional keys) in the updater contract |
| 9 | Three-OS continuous integration for RightKit | RightKit has no CI; `rightkit-tauri-shell` 0.5.0 shipped Windows code "not compiled or exercised". Fastframe compiles every PR on ubuntu, macos and windows | A matrix (private runners acceptable) that compiles and tests every crate on all three OSes on every push |
| 10 | `ContentWebviewSpec`: remote-origin content webview with a profile slot | `WindowSpec` opens app-relative paths only ("never an absolute or remote URL"). Tauri 2.12 already has `data_directory` (Windows) and `data_store_identifier` (macOS 14+), `on_navigation`, `on_new_window`. Consumers: PlayRight service windows, ViewRight's html-content-webviews plan, ScrapeRight's sign-in window | Spec with origin allowlist, profile slot, popup allowlist, no IPC capability, `DevToolsPolicy::ContentOnly`, `register_user_data_dir` for the tripwire, destroy on close; adopted by at least one app |
| 11 | `rightkit-credentials` `protected-key`: OS-bound key release | `os_auth` proves a prompt, not a release (README). RightPass needs: Secure Enclave P-256 with `biometryCurrentSet` wrapping a key slot (Apple); Windows Hello `KeyCredentialManager` signature over a per-vault challenge, HKDF to the slot key (Windows) | Feature with typed unsupported, denied and cancelled outcomes; Swift counterpart in `RightKitCredentials`; hardware-verified on both OSes |
| 12 | One pairing owner | Three short-authenticated-string implementations: `rightkit-daemon` `rk-pair/1`, `rightkit-identity::pairing`, and the copy in `rightkit-sync-keys/src/pairing_sas.rs` that its header says should be shared | `rightkit-identity::pairing` is the owner; daemon and sync-keys consume it; the copy is deleted |
| 13 | `rightkit-sync`: conditional-object adapter and conflict-preserving policy | Vault data cannot use the LWW engine or the plaintext `pending_apply` ledger; the Drive backend documents no compare-and-swap. R2 documents atomic `If-Match` / `If-None-Match` on `PutObject` | New module: immutable objects plus a single authenticated head updated conditionally, three-way merge policy hook, encrypted ledger; Drive excluded for vault use |
| 14 | Resolve the `http` feature contradiction | `rightkit-sync` marks `http` "parked; do not enable it in apps" while `@rightkit/sync-worker` names HeardRight as first consumer | One ruling recorded in both READMEs |
| 15 | Passkey authenticator adapter and the Apple credential-provider product | Proposed `rightkit-passkeys` over `passkey-rs` with a vault-backed `CredentialStore`; proposed `RightKitCredentialProvider` wrapping `ASCredentialProviderViewController` | Both exist with synthetic-store tests; RightPass Gate 1 builds on them |
| 16 | Swift package public or vendorable for open-source consumers | `RightKitSwift` is consumed by exact tag from the private repository; an open-source RightPass iOS build cannot resolve it | Decision: publish the Swift package publicly or document a vendoring procedure under its licence |
| 17 | Small borrows from the Fastframe family | `fastframe-file`'s debug panic when the UI thread writes; Spotifast's DPAPI sealed credential fallback and revocation markers; Spotifast's CI gate on new settings; `fastframe-audio` pause-when-idle output and allocation-free callback test; package-manager-installed detection in the updater; system proxy and SOCKS in `rightkit-http`; Sigstore or GitHub artifact attestations | Each landed in its owner with a test, or declined with a line here |

Not doing (recorded so it is not re-litigated): migrating the hubs to egui; git-tag dependencies on fastframe (release checks refuse them; fork and publish as `rightkit-*` if a piece is taken); copying their assets (ZapFast ships GPL-2.0 sounds); Zig.
