This file is maintained by the RightKit lead in the same change as any row it describes: a change to a crate, package or Swift product lands together with its row, its totals and, where it opens or closes a gap, its entry in section 4. It is hand-written evidence, not generated. The working tree moves while lanes land, so a row describes the tree at the Last reconciled line; re-derive from the cited `path:line` before relying on it, and refresh the line when you do.

### How to update a row

1. **Versions.** Copy registry, staged and tree versions from [`packages/release/rightkit-versions.json`](../packages/release/rightkit-versions.json) and the manifest (`Cargo.toml`, `package.json`, `swift/RightKitSwift/VERSION`). Say "publishing" for a staged version the file does not yet record as registry; say "published" only when the file records it or the lead states it (then name the source).
2. **Support level with citation.** Re-read the `cfg`, `[target.*]`, runtime-platform branches and stubs; set macOS and Windows to Full, Partial or None with a fresh `path:line` that you opened. Re-check every cite in the row, because line numbers drift.
3. **Verification state.** Tag what changed with exactly one of: *verified on macOS*, *verified on Windows (Dell)*, *written, unverified*, *unverified*. Use a verified tag only when the gap ledger rows or a crate CHANGELOG say so (or the lead states it, then name the source); name the host in parentheses (`verified on Windows (CI runner)` for Pulse's runner, `verified on Windows` plus a build number when the source names no host).
4. **Consumers.** Re-run the grep described under "How to read it" for that crate or package.
5. **Gaps.** Add, change or close the matching row in section 4 (with its ledger or audit id) and fix the totals line and the headline counts.

## How to read it

- **Support levels.** *Full*: a real implementation of the crate's public surface exists for that OS (behind that OS's `cfg`/feature, or platform-neutral code with no OS `cfg` and no OS-specific dependency). *Partial*: part of the surface works, the rest is a stub, returns `Unsupported`, is behind a non-default feature, or is `cfg`'d out; the cell says which. *None*: `compile_error!`, whole crate `cfg`'d out, or every public entry returns `Unsupported`. *(untested)*: the README or a code comment says that path has not been compiled or run on that OS (the sentence is cited). Support is read from code; no build or test was run to produce this matrix. *Verification state* tags (below) are quoted from the gap ledger, crate CHANGELOGs or the RightKit lead, never inferred: **verified on macOS**, **verified on Windows (Dell)**, **written, unverified**, **unverified**. A host in parentheses names where the evidence was gathered (`CI runner` is Pulse's `windows-2025` runner; "host not named" means the source says Windows but not which machine). A cell without a tag describes code read at the Last reconciled line, with no host verification claimed.
- **Citations** are `path:line` relative to the item's own directory (`crates/<name>/`, `packages/<name>/`, `swift/RightKitSwift/`) unless they start with `crates/` or `packages/`. Each cited file and line was checked to exist when written, and the quoted text behind each support claim was matched against that line mechanically; a few cites are line ranges or file-level.
- **Published / tree.** *registry* is the latest version recorded under `registry` in [`packages/release/rightkit-versions.json`](../packages/release/rightkit-versions.json); *staged* is `stagedCargo` / `stagedNpm`; *tree* is the version in the manifest now. "tree newer" means the working tree is ahead of what is published, so a README or row may describe unpublished behavior. *private* means `publish = false` / `"private": true`; *never published* means a public crate with no registry record. *staged ... (publishing)* is a staged version the file does not yet record as registry; *published ... per the RightKit lead* is a version the lead states is live although the feed has not caught up.
- **Linux** is listed only as a claim: a cell is filled when the item's README mentions Linux; otherwise it reads "not claimed" with what the code does in parentheses.
- **Consuming apps** come from grepping `/Volumes/D/claude/{genright,cutright,heardright,viewright,mailright,coderight,scraperight,postright,pulse}` (excluding `target/`, `node_modules/`, `dist/`, `.git/`, `rk-snapshot/`, `.cache/`, `.legion-cache/`, `.claude/`; re-run 2026-10-11) for `rightkit_<crate>` in `*.rs`, `rightkit-<crate>` in `Cargo.toml`, `@rightkit/<pkg>` in `package.json` and TS/JS, and `import RightKit<Product>` in Swift. *both* means a plain dependency with no `cfg` at the dependency or (for the files sampled) the use site; *Windows only* / *macOS only* means a `[target.'cfg(windows)']` / `[target.'cfg(target_os = "macos")']` dependency; Brackets after *both* add detail: `win target dep` / `mac target dep` (an extra `[target.*]` dependency entry besides the plain one), `cfg(windows) uses` / `cfg(macos) uses` (at least one using file has that guard within four lines of the use), `tests` (also a dev-dependency). A `[patch.crates-io]` entry is not a consumer. Use-site gating is a line-window heuristic, not a module-level proof. npm packages run in the Tauri webview on every desktop OS, so they are listed by app only.
- **Docs vs code** lists README sentences that contradicted the code. "Fixed in tree" means another lane has since corrected the code or README sentence and the cited line shows it. "Fixed" means a reconciliation pass corrected the README sentence in place (minimal edit, with a code citation in the sentence). "Open" means a contradiction left in place, with the reason. "none found" means the README was read against the code and nothing was found; it is not a proof.

## Headline findings

- **Windows is the weaker desktop OS.** Backends that are stubs, `None`, or self-described as never compiled or run on Windows: `rightkit-fsindex` (stub), `rightkit-hotkeys` (README and `src/windows/mod.rs:3-5` say never built), `rightkit-automation` (e2e fails), `rightkit-ownership`, `rightkit-child-process`, `rightkit-sandbox`, `rightkit-shell` (parts), `rightkit-service` (`connect_expecting` and `Suite::per_user_default` fail closed), `rightkit-tts-qwen` family (bindings pending regeneration). `rightkit-qa-driver` and `rightkit-qa` now run a real Tauri app on a Windows CI runner (Pulse), but ViewRight's document-open scenario on the Dell is blocked by a `devtools call timed out` defect (ledger #92). See section 4.
- **macOS has one missing backend:** `rightkit-overlay` has no macOS implementation (stubs return `false`). Its other gaps are narrower (macOS-only features documented as such; `rightkit-child-process` refuses `kill_on_parent_exit` on macOS).
- **Verification is thin outside macOS.** Today's second-wave work is mostly *written, unverified* on Windows; the Windows host evidence the ledger and CHANGELOGs record is: `rightkit-db` 0.3.2 and `rightkit-credentials` 0.1.3 inside HeardRight and the ffmpeg `decode` catalog row (verified on Windows (Dell)), the `rightkit-fs` DACL measurement (Windows build 10.0.26300.9550, taken before the 5c6fe134 reduction), and, per the lead, `rightkit-app-settings` (before 5c6fe134) and `rightkit-sidecar` test runs. Ledger #79 (managed-target MAX_PATH) is closed on the Dell.
- **`rightkit-qa` is no longer macOS-only**: it documents Windows real-app driving (README:20, :89-131), which Pulse, GenRight, CutRight and ViewRight use through the app's embedded `rightkit-qa-driver` server, which exists only in a `qa-control` (app `qa-native`) build and never ships (`crates/rightkit-qa-driver/README.md`, "QA control never ships"). The code is Partial on Windows (installed-package lane absent, ledger #56).
- **Swift audit items S02 to S06 are fixed in the tree (uncommitted)**; S01 is open for `WhisperEngine`. The `RightKitLicense` platform label now sends `macos` on macOS, a licensing wire value change committed 2026-10-11 as a bug fix (Macs were labelled `ios` and counted against the mobile seat pool; they now send `macos` and use the computer pool).
- **Trees ahead of the registry.** 38 of 56 crates and 3 of 24 npm packages carry a tree version newer than the recorded registry version, and `RightKitSwift` is 0.6.0 in tree (untagged) against 0.4.0 in the feed. Rows describe the tree.
