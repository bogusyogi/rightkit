# RightKit platform matrix

Per-platform support for every crate, npm package and Swift product in this repository, read from the source as it stands in the working tree at `6c466d53` plus uncommitted edits from other lanes (snapshot 2026-10-11). It complements, and does not repeat, [CAPABILITY-MAP.md](CAPABILITY-MAP.md) (who owns a capability), [ADOPTION.md](ADOPTION.md) (how apps adopt it), [INVENTORY-STATUS.md](INVENTORY-STATUS.md) (registry and account parity) and the generated [INDEX.md](../INDEX.md).

This file is hand-written evidence, not generated. Re-derive a row from the cited `path:line` before relying on it; many crates have in-progress edits, so a line number can drift.

## How to read it

- **Support levels.** *Full*: a real implementation of the crate's public surface exists for that OS (behind that OS's `cfg`/feature, or platform-neutral code with no OS `cfg` and no OS-specific dependency). *Partial*: part of the surface works, the rest is a stub, returns `Unsupported`, is behind a non-default feature, or is `cfg`'d out; the cell says which. *None*: `compile_error!`, whole crate `cfg`'d out, or every public entry returns `Unsupported`. *(untested)*: the README or a code comment says that path has not been compiled or run on that OS (the sentence is cited). Support is read from code; no build or test was run for this matrix.
- **Citations** are `path:line` relative to the item's own directory (`crates/<name>/`, `packages/<name>/`, `swift/RightKitSwift/`) unless they start with `crates/` or `packages/`. Each cited file and line was checked to exist when written, and the quoted text behind each support claim was matched against that line mechanically; a few cites are line ranges or file-level.
- **Published / tree.** *registry* is the latest version recorded under `registry` in [`packages/release/rightkit-versions.json`](../packages/release/rightkit-versions.json); *staged* is `stagedCargo` / `stagedNpm`; *tree* is the version in the manifest now. "tree newer" means the working tree is ahead of what is published, so a README or row may describe unpublished behavior. *private* means `publish = false` / `"private": true`; *never published* means a public crate with no registry record.
- **Linux** is listed only as a claim: a cell is filled when the item's README mentions Linux; otherwise it reads "not claimed" with what the code does in parentheses.
- **Consuming apps** come from grepping `/Volumes/D/claude/{genright,cutright,heardright,viewright,mailright,coderight,scraperight,postright,pulse}` (excluding `target/`, `node_modules/`, `dist/`, `.git/`) for `rightkit_<crate>` in `*.rs`, `rightkit-<crate>` in `Cargo.toml`, `@rightkit/<pkg>` in `package.json` and TS/JS, and `import RightKit<Product>` in Swift. *both* means a plain dependency with no `cfg` at the dependency or (for the files sampled) the use site; *Windows only* / *macOS only* means a `[target.'cfg(windows)']` / `[target.'cfg(target_os = "macos")']` dependency; Brackets after *both* add detail: `win target dep` / `mac target dep` (an extra `[target.*]` dependency entry besides the plain one), `cfg(windows) uses` / `cfg(macos) uses` (at least one using file has that guard within four lines of the use), `tests` (also a dev-dependency). A `[patch.crates-io]` entry is not a consumer. Use-site gating is a line-window heuristic, not a module-level proof. npm packages run in the Tauri webview on every desktop OS, so they are listed by app only.
- **Docs vs code** lists README sentences that contradicted the code. "Fixed" means this pass corrected the README sentence in place (minimal edit, with a code citation in the sentence). "Open" means a contradiction left in place, with the reason. "none found" means the README was read against the code and nothing was found; it is not a proof.

## Headline findings

- **Windows is the weaker desktop OS.** Backends that are stubs, `None`, or self-described as never compiled or run on Windows: `rightkit-fsindex` (stub), `rightkit-hotkeys` (README and `src/windows/mod.rs:3-5` say never built), `rightkit-automation` (e2e fails), `rightkit-control` (WebView2 path marked UNVERIFIED), `rightkit-ownership`, `rightkit-process`, `rightkit-sandbox`, `rightkit-shell` (parts), `rightkit-qts` family (bindings pending regeneration). See section 4.
- **macOS has one missing backend:** `rightkit-overlay` has no macOS implementation (stubs return `false`). Its other gaps are narrower (macOS-only features documented as such).
- **The committed `rightkit-qa` README is no longer macOS-only**: it documents Windows real-app driving (README:20, :72-113), which Pulse, GenRight, CutRight and ViewRight use through the app's embedded `rightkit-control` server. The code is Partial on Windows (row below); another lane owns that README.
- **Trees ahead of the registry.** 37 of 57 crates and 9 of 25 npm packages carry a tree version newer than the recorded registry version, and `RightKitSwift` is 0.5.0 in tree against 0.4.0 in the feed. Rows describe the tree.
