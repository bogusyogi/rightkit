# RightKit connection map

Generated by `scripts/map/extract.py` (three passes over the source) and `scripts/map/render.py`. The interactive view of the same data is [`rightkit-map.html`](rightkit-map.html); the raw data is [`rightkit-map.json`](rightkit-map.json). Regenerate both after any change: `python3 -I scripts/map/extract.py && python3 -I scripts/map/render.py`.

## How it was traced

- **Pass 1, declared:** every `crates/*/Cargo.toml` and `packages/*/package.json`: version, publish, features, every RightKit dependency (normal, dev, build, peer, target-specific), modules, binaries, size, test count.
- **Pass 2, used:** every source file, comments and string literals removed, scanned for real uses of each RightKit crate (by its library name and by renamed dependencies) and package (imports, requires, and packages run by name), outside and inside tests (`tests/`, `#[cfg(test)] mod` blocks). Compared with pass 1.
- **Pass 3, runtime contracts:** environment variables read and set (literal names and names held in constants, resolved across the repository), files, sockets and pipes named in code, programs spawned; then the local product apps, for their RightKit pins and the RightKit variables they read.

Each pass was re-run after its false positives were traced to their cause in the source (comments, Rust char and raw strings, library names, renamed dependencies, nested example projects, `#[cfg(test)]` spans, one-argument `.env(NAME)` reads, error-code tables shaped like environment objects). Pass 3 role detection is pattern-based: a variable passed through a helper the patterns cannot see shows up as *mentioned*, not as read or set.
