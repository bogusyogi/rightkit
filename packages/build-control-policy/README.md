# Agent ownership policy hooks

`ownership-write-hook-cli.mjs` adds secondary feedback for Claude `Write`/`Edit`/`MultiEdit` and shell (`Bash`) calls, and for Codex `apply_patch` and shell (`exec_command`) calls. Both adapters deny writes targeting ownership exception or platform trust records. `ownership-session-hook-cli.mjs` adds the current RightKit ownership index at session start. Hook feedback is fail-open for ambiguous edits; build admission remains authoritative.

Install the fifteen runtime assets (`src/install-policy-assets.mjs:9-25`) & append the hook records to both host configs:

```sh
node rightkit/packages/build-control-policy/src/install-agent-policy.mjs
```

The installer writes verified assets into a content-addressed `content-<sha256>` directory under `D:\.rightkit-managed\agent-policy` on Windows or `~/Library/Application Support/RightKit/build-control/agent-policy` on Mac (`RIGHTKIT_CONTROL_ROOT` overrides; `packages/release/managed-roots.mjs:10-11`). Hook commands never name a `content-*` directory. They name a fixed launcher under the same root, so the registered command text does not change across policy activations. Never register source checkout paths or `content-*` paths.

### Heavy-write guard (macOS, `src/agent-heavy-write-guard.mjs`)

Orthic-Labs/rightkit#800. Host policy from the storage lead: `/Volumes/D` is the only agent volume; `/Volumes/E` is Adrian's personal volume and agent writes there are denied; agents create no simulators (use the shared iPhone 18 Pro); DerivedData lives at `/Volumes/D/.xcode/DerivedData`; run outputs go in `/Volumes/D/scratch`. The agent volume list is host configuration: `RIGHTKIT_AGENT_VOLUMES` (`:`-delimited), else `/Volumes/D`, the volume that `packages/release/disk-policy.json` names for the mac scratch and workspace roots. `ownershipWriteDecision` calls the guard first, for every shell tool and for `Write`/`Edit`/`MultiEdit`/`apply_patch`. It does nothing unless `input.platform ?? process.platform` is `darwin`. A denial carries `[HOOK:rightkit-heavy-write:block]`, the rule id and the agent-volume alternative.

There is no full shell emulator and no textual prefilter: every command is parsed and every write destination and working directory is resolved (cwd, `realpath` of every existing ancestor) before the decision. A construct is resolved exactly or refused with a rewrite hint ("split into separate commands", "use an absolute path"). Refusal is always acceptable; a false allow never is.

| Rule id | Denied |
| --- | --- |
| `simctl-no-simulators` | `simctl create` and `clone`, with or without `--set`. Other simctl subcommands pass, unless `--set` names a protected location. |
| `xcodebuild-derived-data` | `xcodebuild` build, test, archive, analyze or default action without `-derivedDataPath` on a verified agent volume. `-help`, `-usage`, `-version`, `-list`, `-showsdks`, `-showBuildSettings`, `-showdestinations`, `-showTestPlans` and `clean` alone pass. |
| `xcodebuild-output` | `archive` without `-archivePath`; `-exportArchive` without `-exportPath`; any `-archivePath`, `-resultBundlePath`, `-exportPath`, `-clonedSourcePackagesDirPath`, `-packageCachePath` or `SYMROOT`/`OBJROOT`/`DSTROOT`/`CONFIGURATION_BUILD_DIR`/`BUILD_DIR` style override that is present but not on an agent volume. |
| `internal-heavy-path` | Writes into `~/Library/Developer/CoreSimulator/Devices`, `~/Library/Caches/<known app owner>` or `~/Library/Application Support/Orthic Labs/shared/models`. App owners are the repository names in `ownership-repositories.json` plus `rightkit`, `rustright`, `swiftrightfactory`, `app.orthiclabs.*` and `com.orthiclabs.*` bundle ids. A path that really resolves outside (a symlinked cache that points at `/Volumes/D`) passes. |
| `non-agent-volume` | Writes to any `/Volumes/<name>` that is not an agent volume (`/Volumes/E`, `/Volumes/D-evil`, disk images). Reads pass. |
| `undeterminable-destination` | A construct whose destination cannot be resolved exactly: shell expansion of an unset variable, `$(...)`, backticks, glob or brace expansion, a missing flag value, a relative destination with an unknown working directory, an unparseable command, `sh -c "$VAR"`, a wrapper option the guard does not model, an ambiguous `tar` mode, or inline `python -c`/`node -e` code that runs `xcodebuild`/`simctl`. A word that starts with an unevaluated expansion (`cp "$X" dst`) could be an option, and an option whose arity is not in the guard's table could swallow the destination, so both are refused: an unknown expression or option is never accepted as a known-safe prefix. |
| `repo-create-outside-run-root` | `git clone` (also with no directory, which lands in the working directory) and `git worktree add` write outside a leased run root. `git worktree move` and `repair` keep only the agent-volume check. See "Run roots" below. |
| `download-outside-run-root` | A curl or wget file output, or the `--local-dir` and `--cache-dir` of `hf download` and `huggingface-cli download`, outside a leased run root. `hf download` without `--local-dir` writes the shared Hugging Face cache and is refused. |
| `run-lease-forgery` | Any write destination named `.rightkit-run.json`, however spelled (case, `.`, `..`, a symlink to it): redirects, `tee`, `cp`/`mv`/`install`/`rsync`/`ditto`, `tar -f`, `sed -i` and `w`, `dd of=`, `truncate`, `touch`, `ln`, `mkdir`, `Write`/`Edit`/`MultiEdit`/`apply_patch` paths, and a `curl -O` or `wget` of a URL whose file name is that. The lease is created only by `right-release disk run-root <name>`. |

Covered writers: redirects, `tee`, `cp`, `mv`, `ln`, `install`, `ditto`, `rsync` (`--temp-dir`, `--backup-dir`, `--log-file`), `scp`, `mkdir`, `touch`, `truncate`, `dd of=`, `unzip` (`-d` or the working directory), `curl` (`-o`, `-D`, `-c`, `--output-dir`, `-O`), `wget` (`-O`, `-P`, the working directory), `find -fprint*`/`-exec`, `time -o`, and `tar`. Short options parse with attached values (`-o"$HOME/x"`, `-sSLo path`, `-C/dir`), long options with `=` or a separate value and with unique-prefix abbreviations. `tar` create/append/update writes `-f` (and `-C` is a read directory); extract writes every `-C` (or the working directory); an undeterminable mode is refused.

Round 3 rules. Every unresolved destination is refused, including a safe-looking prefix followed by an unresolved part (`/Volumes/D/${REL}`); a protected static head is denied with its own rule first. Composed `functions.exec` code accepts only direct `exec_command({...})` calls whose `cmd`/`command`/`workdir`/`cwd` are single inline string literals: a variable argument, an earlier object, an alias, spread, or `.cmd =`/`["cmd"] =` mutation is refused. An unknown option is refused even as `--name=value` (`--no-X` only when `X` is known). `tar -h` is `--dereference` (help is `--help`/`-?`), and `--index-file`/`--listed-incremental` outputs are checked in every mode. `install -d` checks every operand; `ln` checks `<cwd>/<basename>` for one operand, the last operand for two or more, and `-t DIR`. `curl` checks every file-writing option (`-o`, `--etag-save`, `-D`, `-c`, `--trace`, `--trace-ascii`, `--stderr`, `--libcurl`, `--hsts`, `--alt-svc`, `--output-dir`), the implicit output of `-O`/`--remote-name`/`--remote-name-all`/`-J`, and refuses `-K`/`--config` and a `--write-out` with `%output{}`. `rsync` checks `--write-batch`/`--only-write-batch` (and the `.sh` companion), `--log-file`, `--temp-dir`/`-T`, and resolves a relative `--backup-dir`/`--partial-dir` against the destination root. `find` refuses `-execdir`/`-okdir`, treats `{}` as always unresolved (so a nested writer destination containing it is refused even under an agent start root or with `-L`), and checks `-delete` start paths and `-fprint*`/`-fls` files. `sed` is modelled: `-i` edits each file operand (BSD `-i ''`/`-i EXT`, GNU `-i`/`-iSUFFIX`/`--in-place`), a literal script is read (every `w`/`W FILE` and `s///w FILE` is a destination), while a script that is not literal (any expansion), `-f`, the `e` command and `s///e`, an unreadable script, an ambiguous suffix word or a missing file operand are refused, with or without `-i`. `git clone` (explicit DIR, or `<cwd>/<repository name>`) and `git worktree add PATH` (the first operand, never the trailing commit-ish) / `move` are destinations, with ordered `git -C` options resolved physically. `xargs` is refused whenever it wraps a command the guard tracks, because stdin controls its final argv. Attached option values (`-oVAL`, `--opt=VAL`, `dd of=VAL`) are sliced from the already expanded word and keep its dynamic status; a literal `$` in them is never expanded a second time. A short-option cluster that contains an unresolved expansion outside a valued option's attached value is refused.

Shell semantics modeled exactly or refused: prefix assignments reach only the child environment, so a command whose words use a variable assigned in the same simple command is refused (`DD=/x xcodebuild -derivedDataPath "$DD"`), while `env VAR=value cmd` keeps the shell's value in argv; a `cd` counts only inside its own `&&` chain (`;`, newline and `||` leave the working directory unknown, so a following relative destination is refused); `functions.exec` code is read call by call with each nested `exec_command`'s own `workdir`, and a non-literal `cmd` or `workdir` is refused; wrapper options (`sudo`, `env`, `nice`, `time`, `timeout`, `xcrun`, `xargs`, `arch`, `caffeinate`, ...) are parsed with their real arity, long and short, with and without `=`, and an unknown one is refused.

"On an agent volume" is proven, not assumed. The destination must contain no `..`; every existing ancestor is resolved with `realpath` (a dangling symlink is refused); the result must be `/Volumes/<name>/...` with `/Volumes/<name>` an agent volume; and that mount and the nearest existing ancestor must be on a device (`st_dev`) other than `/`, `/System/Volumes/Data` and the home volume. `/Volumes/D-evil`, `/Volumes/D/../../Users`, a symlink to an internal directory and `/Volumes/Macintosh HD` (a symlink to `/`) all fail.

Run roots (`repo-create-outside-run-root`, `download-outside-run-root`). A clone, a worktree or a download is admitted only below a leased run root: a real directory directly under a run-root parent (`/Volumes/D/scratch`, or the `:`-delimited `RIGHTKIT_SCRATCH_ROOTS`) that holds a regular `.rightkit-run.json` file, `{"schema":1,"name","createdAt","leaseUntil"}`, whose `leaseUntil` is still in the future, whose `name` is that directory's name, and that lasts at most 30 days from its `createdAt` (one day of tolerance; a `createdAt` more than a day ahead of the clock is not a lease either). `right-release disk run-root <name> [--days N]` writes that lease (N at most 30; `MAX_LEASE_DAYS` in `packages/release/disk-policy.mjs` and in the guard) (see the disk hygiene section of `packages/release/README.md`). The sweep skips a leased unit, so what an agent fetches there is not deleted under it. The destination must lie strictly below the run root, except for a directory the tool fills (`--output-dir`, `wget -P`, the working directory, `--local-dir`, `--cache-dir`), where the run root itself is allowed. Refused: a run root or a lease that is a symlink, missing, expired, unreadable, malformed, copied from another run root or longer than 30 days; any write to the lease file (`run-lease-forgery`); `..`; a run root off the agent volume; and any destination that cannot be resolved. `/dev/null`, `/dev/stdout` and `/dev/stderr` are not files for curl or wget, and `-` is stdout. Refusals name the run root, the lease and the command that creates one. The guard reads the lease through its file seam and never writes it. `RIGHTKIT_WORKSPACE_ROOTS` changes only the workspace named in the refusal hint; it admits nothing. Installed hosts pick these rules up after `node packages/build-control-policy/src/install-agent-policy.mjs`. curl is read one operation at a time (`--next` or `-:` starts a new one, each with its own `--output-dir`, `-O` and `-o`; a relative `-o` lands in that operation's `--output-dir`), `wget --spider` without `-r`, `-m`, `-p` or `-b` writes nothing and passes, and program names are matched case-insensitively (APFS runs `Git`, `CURL` and `/usr/bin/Curl`). Known limits, because the guard is feedback and not confinement: `gh repo clone`, `git init` followed by `git fetch`, scripts and heredocs that clone or download, a shell redirect of curl's stdout to a workspace file, `WGETRC`, a server-chosen file name (`curl -J`, `wget --content-disposition`) and archive members or cloned files that carry a lease file. Not done: a Windows port of the run-root rules, and branch-creation and install refusals.

The guard tokenizer keeps what the dependency tokenizer in `ownership-write-hook.mjs` discards: redirect targets, variables, substitutions and the operator around every command. A redirect is never read as a `-derivedDataPath`: `xcodebuild build > /Volumes/D/x` has no destination and is denied. `agent-heavy-write-guard.test.mjs` asserts deny-on-unknown.

Round 4 git and find. `git` is modelled explicitly. (a) Pure object readers (`log`, `show`, `rev-parse`, `cat-file`, `ls-tree`, `ls-files` without `-m`/`-d`, `diff --no-index`, listing forms of `branch`/`tag`, `remote -v`/`show`/`get-url`, `config --get`, `worktree list`, `reflog` listing and the like) are allowed and never spawn git. `status`, `diff`, `diff-files`, `diff-index`, `describe`, `ls-files -m|-d` and `reflog expire|delete` are NOT write-free (they refresh `.git/index` and take `index.lock`, or rewrite logs), so they are repo-local writers needing the closure check below, unless `--no-optional-locks` or `GIT_OPTIONAL_LOCKS=0` (value 0 only) is given. The `GIT_*` and `-c`/`--config-env`/`--git-dir`/`--work-tree`/`--namespace`/`--exec-path=` refusals apply to every git invocation, read-only forms included. (b) Repo-local writers (`add`, `commit`, `checkout`, `switch`, `restore`, `reset`, `merge`, `rebase`, `stash`, `fetch`, `pull`, `push`, `gc`, create/delete forms of `branch`/`tag`, `remote add`, `config` writes ...) are admitted only on git's own resolution of the repository: the repository directory (cwd, or the ordered `-C`, resolved physically) must be on an agent volume, and then `git -c core.fsmonitor=false -c core.untrackedCache=false rev-parse --path-format=absolute --show-toplevel --absolute-git-dir --git-common-dir` is run read-only in that directory (one 5 s budget per hook call, environment scrubbed to PATH and HOME so no `GIT_*` reaches it). Git itself applies global and included configuration, `gitdir:` files, `commondir` and `core.worktree`; each of the three printed paths, resolved physically, must be on an agent volume. A failure, timeout, no time left, or output that is not three absolute paths refuses; the runner is an injectable seam (`gitRunner`, `clock`) and the tests fake it. Any `GIT_*` variable (hook process env, prefix assignment, `export`, `env`) other than `GIT_TERMINAL_PROMPT`, `GIT_PAGER`, `GIT_EDITOR=true|:`, `GIT_OPTIONAL_LOCKS=0` and `GIT_AUTHOR_*`/`GIT_COMMITTER_*` name/email/date refuses the command; `-c`, `--config-env`, `--git-dir`, `--work-tree`, `--namespace` and `--exec-path=` refuse any git command. `push`/`fetch`/`pull` resolve the remote (a direct path or `file://` URL, or a remote name through `git remote -v` in the same bounded seam): a local remote must resolve physically onto an agent volume, network URLs are fine, remote helpers (`ext::`) are refused. (c) Every output option is a destination on every subcommand: `--output FILE` (and abbreviations) on `log`/`diff`/`show`, `archive -o/--output`, `bundle create FILE`, `format-patch -o/--output-directory` (or the cwd), `init [DIR]`, `clone`, `worktree add PATH`/`move`, `config --file`. Round 5: the probe runs with the EFFECTIVE `HOME` and `XDG_CONFIG_HOME` for the command (inherited, or the value the command sets by prefix, `export` or `env`); a value set by the command that is not a resolvable literal refuses and git is not spawned. `git worktree add|move|remove|prune|lock|unlock|repair` require physical closure of the SOURCE repository (`.git/worktrees/<name>` is written there) and of each affected worktree root (add: the new PATH; move: the new PATH and the old root; remove/lock/unlock: the target's root as `git worktree list --porcelain` reports it, matched by exact physical path or git's unique suffix; repair: every listed root and each operand); any other worktree action is refused. `git config` parses `-f`/`--file` in every form (`-f FILE`, `-fFILE`, `-lf FILE`, `--file FILE`, `--file=FILE`, `--fil=FILE`) as a destination that must be on D, refuses `--global`/`--system` writes and `--edit`, allows their reads, and treats `--blob` as read-only; an option built from an expansion is refused. `git init` on an existing target (a `.git` dir or `gitdir:` file, or inside a repository) resolves git's own gitdir/commondir/work tree and requires them on D (a broken or redirected reinit is refused); a target with no `.git` where git answers 'not a repository' (exit 128) is a fresh init that checks only the target; `--separate-git-dir` is a destination. (d) Any other subcommand or unparsed form is refused. `find` with `-L`, `-H` (when last) or `-follow` refuses `-delete`; nested `-exec`/`-ok` commands are analysed in a forked scope so an `env -C` or variable inside one cannot move a sibling or a following command.

Limits. This is bounded PreToolUse feedback, not a sandbox or confinement, and it does not change SDK defaults or move, delete, reset or symlink anything. Scripts (`make`, `npm run`, `fastlane`, shell files), services, IDEs and child processes choose their own locations and escape every visible argument; functions, aliases, sourced files, `su -c` and tools not listed above are not followed. Native write-location proof (the process and filesystem evidence of where bytes landed) is still required for any claim that nothing was written to the internal drive. Git hooks, clean/smudge filters, core.hooksPath set in global or system configuration, aliases defined there and any program git is told to run are opaque code execution that the guard does not model (the guard is not a sandbox); a repository whose own configuration redirects them is covered only as far as the paths git resolves above.

### Stable launchers & the active pointer

```text
agent-policy/
  active.json          {"schemaVersion": 1, "digest": "<sha256>"}, replaced atomically (temp file, flush, rename)
  launch/
    hook-launcher.mjs  shared core, a byte copy of src/hook-launcher.mjs
    write-hook.mjs     registered for the write/Bash hook
    session-hook.mjs   registered for SessionStart
  content-<sha256>/    verified assets, unchanged; superseded directories are kept
```

Install order is content directory, verified; launchers; then `active.json`. Launchers are written only when their bytes differ, and their bytes depend on neither a digest nor the root, so a re-install touches nothing it does not need to.

At run time the launcher reads `active.json`, requires a 64-character lowercase hex digest, resolves `content-<digest>/src/<fixed hook script>`, refuses any path whose real path leaves the root, and imports that script in the same node process (no child process). stdin, argv (`argv[1]` becomes the script, as for a direct run), stdout, stderr & the exit code reach the agent exactly as before.

A missing, unreadable or malformed pointer, an invalid digest, an absent or non-file target, or a path outside the root is refused with one `[HOOK:rightkit-policy-launcher:unavailable] <code>: ...` line on stderr, nothing on stdout, and exit 1. That is what `node <missing script>` already did. How a host treats exit 1 from a hook is host behavior that this repository does not verify. These hooks are advisory feedback & broker/build admission stays authoritative. The launcher never exits 0 on a failure and never exits 2, so a broken install cannot look like an allow decision or block every tool call. Denials (exit 2) come from the hook script and pass through unchanged; an error thrown by the script propagates unchanged.

### Registration & migration

Registration updates in place any existing RightKit command for the same hook that points into a `content-<sha256>` directory of this root (or of the legacy managed root's `agent-policy`), or at the launcher with a different node path. Its position, group matcher & other fields stay; duplicate RightKit entries for that hook are dropped; a new group is appended only when none exists. A RightKit registration in a group with another matcher is dropped, and the group for the wanted matcher is appended. Hooks that are not RightKit's, and every other field & group, are untouched. A config that already holds the launcher commands is not rewritten.

When this change is first activated, the command changes from a content-addressed path to the launcher path, and a host may ask you to review the hooks once more for that change. Later policy activations leave the command unchanged. The command also embeds the installing node's absolute path, so installing with a different node binary (for example after a Node upgrade moves it) changes the command.

Old `content-*` directories are left in place.

### Manual registration

Append these groups to existing host hook arrays. Preserve all existing groups & commands. Substitute `<write-launcher>` & `<session-launcher>` with the installer's `writeLauncher` & `sessionLauncher` output paths, escaping backslashes for JSON.

Claude `settings.json` additions:

```json
{
  "PreToolUse": [{
    "matcher": "Write|Edit|MultiEdit|Bash",
    "hooks": [{ "type": "command", "command": "node <write-launcher>" }]
  }],
  "SessionStart": [{
    "hooks": [{ "type": "command", "command": "node <session-launcher>" }]
  }]
}
```

Codex `hooks.json` additions:

```json
{
  "PreToolUse": [{
    "matcher": "Bash|apply_patch|exec_command|functions\\.exec",
    "hooks": [{ "type": "command", "command": "node <write-launcher>" }]
  }],
  "SessionStart": [{
    "hooks": [{ "type": "command", "command": "node <session-launcher>" }]
  }]
}
```
