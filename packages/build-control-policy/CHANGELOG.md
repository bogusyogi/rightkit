# Changelog

## 0.1.4-phase1 (2026-10-19)

- Heavy-write guard for agent actions on macOS (Orthic-Labs/rightkit#800): `src/agent-heavy-write-guard.mjs`, called first by `ownershipWriteDecision` and shipped as the fifteenth policy asset. Host policy: `/Volumes/D` is the only agent volume (configurable through `RIGHTKIT_AGENT_VOLUMES`), writes to `/Volumes/E` and any other mount are denied, `simctl create|clone` is always denied (use the shared iPhone 18 Pro), DerivedData belongs at `/Volumes/D/.xcode/DerivedData`. Also denies `xcodebuild` build/test/archive without `-derivedDataPath` on the agent volume (and non-agent `-archivePath`, `-resultBundlePath`, `-exportPath`, `-clonedSourcePackagesDirPath`, SYMROOT-style overrides) and writes into the internal CoreSimulator Devices directory, known app caches under `~/Library/Caches` and the RightKit `shared/models` path. Read-only queries pass. The agent volume is proven by realpath of every ancestor and `st_dev` against `/`, the Data volume and the home volume; `..`, `/Volumes/D-evil`, symlinks to internal paths and dangling symlinks are refused. No effect off macOS. Feedback only: scripts, services and child processes still need native write-location proof. Not built, installed or activated here; activation is the protected route.
- Review round on the candidate (seven false allows/denies): no textual prefilter (every command and destination is resolved); attached short options (`curl -o"$HOME/x"`, `-sSLo`, `cp -t`, `unzip -d`, `wget -O/-P`, `tar -C`) and unique-prefix long options; prefix assignments reach only the child environment (a command word that uses a variable assigned in the same command is refused, `env VAR=x cmd` keeps the shell value); a `cd` counts only inside its `&&` chain, otherwise the working directory is unknown and relative destinations are refused; `functions.exec` keeps each nested call's own `workdir` and refuses non-literal `cmd`/`workdir`; wrapper options (`sudo`, `env`, `nice`, `time`, `timeout`, `xcrun`, `xargs`, `arch`, `caffeinate`, ...) are parsed with real arity or refused; `tar -c` writes `-f` and reads `-C`, `tar -x` writes `-C`, an unknown mode is refused.

- Round 2 (five more false allows): every writer table (cp, mv, ln, install, ditto, scp, rsync, mkdir, touch, tee, truncate, unzip, curl, wget) lists the real arity of each option, so `rsync -az src /Volumes/E/x` no longer lets `-z` swallow `src`; an unknown option, or a word that starts with an unevaluated expansion, is refused. An assignment that may not run (after `&&`/`||`, in `if`/`for`/`while`/`case`, a function body, a pipeline or background job) makes the variable unknown instead of updating it; `eval`, `source`, `read`, `unset`, `let` and similar forget every tracked value. `env -C`, `sudo -D`, tool workdirs, `tar -C` and relative destinations resolve symlinks of each existing prefix before applying `..`; a `cd` whose logical and physical targets differ leaves the cwd unknown. Composed `functions.exec` code is tokenized: `cmd` and `workdir` must each be ONE complete string literal (concatenation, calls, parentheses, spread, computed keys, comments and duplicate keys refuse the code), and string literals are decoded exactly as JavaScript does (`\xHH`, `\uHHHH`, `\u{...}`, line continuations, identity escapes) or the code is refused.

- Round 3 (Fable verdict 800-r3-agreed.md, Astra packet c4a2002b): every unresolved destination is refused (G1); composed `functions.exec` code accepts only direct `exec_command` calls with inline literals (G2); unknown `--name=value` options are refused; `tar -h` is `--dereference`, tar `--index-file`/`--listed-incremental` outputs are checked; `install -d` and `ln` implicit destinations; curl implicit output and every file-writing option; rsync batch/backup/partial/temp/log destinations; `find` refuses `-execdir`/`-okdir` and never resolves `{}`; `sed -i` (BSD and GNU forms) and `w`/`W` scripts; `git clone`/`worktree add|move` with ordered `-C`; `xargs` refused when it wraps a tracked command; attached option values keep their dynamic status; option clusters with an unresolved expansion are refused.

- Round 4 (three source gaps): `git` modelled explicitly: read-only forms allowed; repo-local writers admitted only on git's own bounded `git rev-parse` resolution (work tree, git dir and common dir on the agent volume, 5 s budget, scrubbed env, injectable seam), no `GIT_*` overrides outside a harmless list, `-c`/`--config-env`/`--git-dir`/`--work-tree`/`--namespace`/`--exec-path=` refused, `push`/`fetch`/`pull` local or `file://` remotes (direct or by name) must be on the agent volume, every output option (`--output`, `archive -o`, `bundle create`, `format-patch -o`, `init`, `clone`, `worktree add`, `config --file`) is a destination, other subcommands refused; status/diff/describe/diff-files/diff-index/ls-files -m|-d/reflog expire|delete are index- or log-writing, so they need the closure check unless `--no-optional-locks` or `GIT_OPTIONAL_LOCKS=0`; the GIT_* and -c/--config-env refusals apply to every git invocation; `find -L/-H/-follow` with `-delete` refused; nested `find -exec/-ok` analysed in a forked scope.

- Round 5 (Astra BLOCK on 196c514f): `git worktree add|move|remove|prune|lock|unlock|repair` need closure of the source repository and of every affected worktree root (listed by git, resolved physically), other worktree actions refused; `git config` parses -f/--file in every attached and clustered form as a destination, refuses --global/--system writes and --edit, allows reads, --blob read-only; the rev-parse/remote/worktree probe uses the effective HOME and XDG_CONFIG_HOME (unresolvable values refuse, never dropped); `git init` on an existing repository requires its resolved gitdir/commondir/work tree on D (fresh init checks the target only), `--separate-git-dir` is a destination.

- Round 6 (leased run roots, storage hardening; `src/agent-heavy-write-guard.mjs`, an installed asset): two new rules, `repo-create-outside-run-root` (`git clone`, `git worktree add`) and `download-outside-run-root` (curl and wget file outputs, `hf` and `huggingface-cli download`), admit a destination only below a run root: a real directory directly under `/Volumes/D/scratch` (`RIGHTKIT_SCRATCH_ROOTS` overrides the parent) holding a regular `.rightkit-run.json` lease (`{"schema":1,"name","createdAt","leaseUntil"}`) whose `leaseUntil` is still in the future. `right-release disk run-root <name>` writes the lease. A symlinked run directory or lease, the run root itself (except a directory the tool fills: `--output-dir`, `wget -P`, the working directory, `--local-dir`), the lease file, `..`, an expired, unreadable or malformed lease, and a run root off the agent volume are refused; refusals name the run root, the lease and the command. `git worktree move` and `repair` keep the agent-volume check. `/dev/null`, stdout and `-` are not files. The guard reads the lease through its fs seam and never writes it. `RIGHTKIT_WORKSPACE_ROOTS` changes only the workspace named in the hint. Installed copies change only after the reinstall, `node packages/build-control-policy/src/install-agent-policy.mjs`. The guard is outside the `POLICY_BUNDLE_ENTRYPOINTS` import closure (checked by walking the static imports of the eight entrypoints), so no trust-sync is needed. Package version unchanged. Not done: the Windows port of the run-root rules (hook tool names and path forms on the Dell are unproven) and branch-creation and install refusals. Not installed or activated here; native write-location proof on the Mac is still required.

- Round 7 (review of the run-root rules; `src/agent-heavy-write-guard.mjs`, an installed asset): a new rule, `run-lease-forgery`, denies every write destination named `.rightkit-run.json` (redirects, `tee`, `cp`, `mv`, `install`, `rsync`, `ditto`, `tar -f`, `sed -i`, `dd of=`, `Write`, `Edit`, `MultiEdit`, `apply_patch` paths, and a `curl -O` or `wget` of a URL with that file name), whatever the spelling (case, `.`, `..`, a symlink to it); the lease is created only by `right-release disk run-root <name>`. A lease must carry the name of its own directory and may last at most 30 days from its `createdAt` (plus one day of tolerance; a `createdAt` over a day in the future is refused), the same `MAX_LEASE_DAYS` that `disk run-root --days` enforces. curl is checked one operation at a time (`--next`, `-:`): `curl --output-dir R -O U --next -O U` no longer writes its second file into the working directory unseen, and a relative `-o` resolves against that operation's `--output-dir`. `wget --spider` (without `-r`, `-m`, `-p`, `-b`) is no longer refused. Program names are matched case-insensitively (`Git clone`, `Curl -o`, `/usr/bin/CURL`). The guard header lists the known limits (`gh repo clone`, `git init` plus `git fetch`, scripts and heredocs, curl stdout redirected to a workspace file, `WGETRC`, server-chosen file names, archive members and cloned files that carry a lease file). Installed copies change only after the reinstall, `node packages/build-control-policy/src/install-agent-policy.mjs`. Package version unchanged.

## 0.1.2-phase1

- The cargo, rustc, rustdoc and rustup PreToolUse guard now fires only when the tool would run locally on the Mac or Dell (RustRight managed hosts). Hosts that are neither (Linux, cloud sessions, CI) pass every command; the host test is the same win32/darwin platform test `packages/release/managed-roots.mjs` uses. Hook input may carry `platform` to override `process.platform`.
- Commands run through `ssh` or `plink` are remote: the argument string after the host is not an invocation here. Local parts are still inspected: other segments (`ssh h true; cargo build`), `$(...)` and backticks, `env X=1 cargo`, and `ProxyCommand`/`LocalCommand` options.
- Denial text says RustRight.
