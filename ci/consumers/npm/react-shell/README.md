# @rightkit/react-shell npm consumer (npm.@rightkit/react-shell)

Packed-archive consumer for `@rightkit/react-shell` 0.7.2 (the workspace version). The unit is installed only from the sealed `file:` archive. The reviewed closure pins `@rightkit/platform-ui` 0.4.0, the required peer, `react` 19.3.1 and `react-dom` 19.3.1 (server rendering only). The optional peer `@tauri-apps/plugin-os` is declared-only and not installed; the consumer asserts that it does not resolve, so platform detection takes the documented host-injected path.

Surface (exact `exports` keys): `.`, `./headless`, `./react`, `./shell.css`, `./shell.layered.css`, `./shell.structure.css`, `./shell.visual.css` and `./suite-aliases.css`. The consumer asserts the sorted export names of the three code entries (32 in the root entry, 106 in `./react`, 2 in `./headless`) and reads the five stylesheets through archive-bound export URLs. It also asserts that the helpers the shell re-exports are the same functions as in the installed `@rightkit/platform-ui`, so the peer is shared and not duplicated.

Scenarios (13): export surface and shared peer; navigation, selection and ranking helpers and `anchorPoint`; the theme store (persistence, OS changes without React, QA override, blocked storage, `alwaysPaintDataTheme`, `darkRemovesAttribute`, `applyStoredThemeSync`, `themeBootScript` in a `node:vm` context); the shortcut registry (dispatch, sequences, typing guard, overrides, conflicts, suspend, per-shortcut options); chord vocabulary, `createKeymapStore` and the prefix helpers; the command and toast registries; `ShellProvider` context, keybindings and hooks rendered on the server; the fused `AppShell` layout in nine configurations; the titlebar, caption controls, frame, navigation and page primitives; the UI primitives; dialogs, command palette, shortcut help, toast viewport, table and shortcut recorder; the headless toggle and segmented-control props; the hover guard and the stylesheet files.

What it proves: the registries behave as documented without a DOM, the markup for the shell, its primitives and its closed overlays has the documented roles, labels and classes, the provider passes injected stores through, `shell.css` is exactly the structure file plus the visual file, the structure file carries no colour, the layered file imports both into the `rk` layer, and `suite-aliases.css` maps each unprefixed name to its `--rk-` token. Windows renders caption buttons from the window adapter and macOS reserves space for the native traffic lights. The only bridge fake is a window adapter whose calls are recorded.

What it does not prove: anything that needs a mounted tree or a browser. Effects, state changes after the first render, key handling through real events, focus trapping and restoration, palette keyboard navigation, toast timers and stacking, the sidebar resize drag, the `ErrorBoundary` fallback after a render error and the `useCommands` and `useShortcuts` registrations are not run. The portal-based `ContextMenu` and `Popover` need `document.body`, so only their export names are asserted; `anchorPoint`, their placement function, is tested. `useContextMenu`, `useLatest`, `useModalDismiss` and `CaptionControls` are asserted by export name only (the caption buttons render through `Titlebar` and `AppShell`, and `useModalDismiss` runs inside the dialogs, but their effects do not run). Native bridge members (`openExternal`, `onMenuAction`, `setNativeTheme`) are not called. Stylesheets are checked as text, so cascade, layout, motion and `prefers-reduced-motion` behaviour stay with the package's browser end-to-end tests. The optional OS plugin path is not run.

Required environment: `RIGHTKIT_CONSUMER_ARTIFACT`, `RIGHTKIT_CONSUMER_ARTIFACT_SHA256`, `RIGHTKIT_CONSUMER_EXPECTED_VERSION` and `RIGHTKIT_CONSUMER_RESOLUTION` (`packed` or `fetched`). The runner provides them. `provenance.mjs` is the shared byte-identical helper that binds every installed file to the supplied archive.

The consumer sets `globalThis.__RIGHTKIT_PLATFORM__` to `macos` before importing the shell so no step depends on the host, and deletes it at the end. No network, no credentials, no user data. Output is one JSON line; exit 0 only when all thirteen scenarios pass. `nativeHostQualified` is always false.
