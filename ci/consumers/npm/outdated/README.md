# @rightkit/outdated npm consumer (draft, npm.@rightkit/outdated)

Packed-archive consumer for `@rightkit/outdated` 0.2.0 (workspace version). Recipe ID: `outdated-check-apply-gate-land-consumer`. The unit is installed only from the sealed `file:` archive. The reviewed closure is two published packages, pinned exactly: `@rightkit/ci` 0.3.0 (the package imports `driftCommand` from `@rightkit/ci/drift.mjs`) and `smol-toml` 1.9.1 (the TOML parser). The workspace declares `@rightkit/ci` as `workspace:^`, which packs as `^0.3.1`; the install override pins the published 0.3.0, whose `drift.mjs` is byte-identical to the 0.3.1 source. When `@rightkit/ci` 0.3.1 is published, move the pin in the registry closure and in this recipe's `package.json` together.

Surface (exact `exports` keys): `.`, which resolves to `dist/index.js`. The package also ships the `right-update` bin at `dist/bin.js`. The consumer runs the installed bin file with Node (`process.execPath`) and never uses a `.bin` shim, so it behaves the same under pnpm on Windows and macOS.

Test doubles: the registries (`fetch`), `pnpm outdated` (`exec`), `rustright cargo update` and `pnpm add` (`run`), and the platform and process runner for the schedule are injected through the package's own dependency options. Temporary repositories live under the OS temp directory and are removed at the end. No network, no credentials, no user data, and nothing is installed into the host (no launchd job, no scheduled task). The longest wait is a 3 s gate deadline.

Not covered: the real registries (crates.io, npm, GitHub) and `pnpm outdated`, `rustright cargo update` and `pnpm add` themselves; archive extraction for a tool delivered as a zip or tar (needs `unzip` or `tar` on the host); a real `launchctl` or `schtasks`; and `right-update` used through a package-manager `.bin` shim. Apply, land and discard are exercised where each file is touched by one row. An apply whose rows share a file (every cargo row shares `Cargo.lock`, and two bumps in one `Cargo.toml` share it too) records each row's digests against the file as that row left it, so `land` refuses with "changed since apply" and `discard` fails its digest check; the recipe lands and discards single-row applies only and does not assert the multi-row case.
