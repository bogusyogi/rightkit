# @rightkit/media-ui npm consumer (npm.@rightkit/media-ui)

Packed-archive consumer for `@rightkit/media-ui` 0.3.4 (the workspace version). The unit is installed only from the sealed `file:` archive. The reviewed closure pins `react` 19.3.1 and `react-dom` 19.3.1, the required peers (`react-dom` is used for `renderToStaticMarkup`). The unit's optional peers `fabric` and `react-image-crop` are declared-only and deliberately not installed; the consumer asserts that neither resolves.

Surface (exact `exports` keys): `.`, `./image` and `./styles.css`. The consumer asserts the 47 sorted export names of the root entry and the two names of `./image` (`ImageEditor`, `ImageViewer`).

Scenarios (10): export surface and absent optional peers; `MediaPlayer` server markup for video and audio (labels, tracks, poster, speed control, icons, original link); adapters (`MediaAdaptersProvider`, `useMediaAdapters` precedence, `normalizeResourceHandle`); player labels, `mediaClock` and `mediaErrorMessage`; the image edit model and export geometry; the export pipeline driven through a fake canvas; image save names, types and `canvasToArrayBuffer`; viewer transform and crop maths and font helpers; the edit snapshot store; the `ImageViewer` and `ImageEditor` server markup.

What it proves: the player renders its documented controls in the loading state, `resolveSrc` from a provider or a prop rewrites the source and the original link, the edit model and resize maths return the documented values, `exportImageEdit` asks the canvas for the right size and draws crop, rotation, flip, filter and wrapped text in the right order and encodes with the right MIME type and quality (the pipeline runs against a recording fake canvas and a fake `Image`), oversized exports are refused before a canvas is allocated, and the image entry imports and renders its toolbar and stage without `fabric` or `react-image-crop`, which the package loads lazily. Edit-history snapshots are copied on the way in and out.

What it does not prove: playback or decoding of real media, fullscreen, captions rendering, the compatibility-copy flow behind `preparePlayback`, any pointer, wheel, keyboard or drag interaction of the viewer and editor, paging between sibling images, printing and saving through the host adapters, and the lazily loaded text overlay (`fabric`) and crop tool (`react-image-crop`). Real pixels are never produced: the fake canvas records calls only. Viewer and player effects do not run in server rendering. The stylesheet is checked as text only. The two optional peers need their own recipe closure before the editor tools can be qualified.

Required environment: `RIGHTKIT_CONSUMER_ARTIFACT`, `RIGHTKIT_CONSUMER_ARTIFACT_SHA256`, `RIGHTKIT_CONSUMER_EXPECTED_VERSION` and `RIGHTKIT_CONSUMER_RESOLUTION` (`packed` or `fetched`). The runner provides them. `provenance.mjs` is the shared byte-identical helper that binds every installed file to the supplied archive.

No network, no credentials, no user data; every URL uses the reserved `.invalid` TLD or a made-up local path and is never fetched. The consumer installs a fake `Image` and `document` only for the duration of the export scenario and restores them. Output is one JSON line; exit 0 only when all ten scenarios pass. `nativeHostQualified` is always false.
