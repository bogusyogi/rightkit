# @rightkit/pdf-ui npm consumer (npm.@rightkit/pdf-ui)

Packed-archive consumer for `@rightkit/pdf-ui` 0.2.0 (the workspace version). The unit is installed only from the sealed `file:` archive. The reviewed closure pins `pdfjs-dist` 6.4.299, the unit's runtime dependency (its range is `^6.4.299`), `react` 19.3.1, the peer, and `react-dom` 19.3.1 for `renderToStaticMarkup`. The consumer imports `pdfjs-dist` itself and asserts version 6.4.299, so the viewer and the recipe share one copy.

Surface (exact `exports` keys): `.` and `./styles.css`. The consumer asserts all 35 sorted export names of the root entry.

Scenarios (10): export surface, pinned pdf.js and shipped stylesheet; the `PdfViewer` server markup (default, find bar off, toolbar hidden with a host slot, regex option, outline and pages panels, bytes and loader sources); `usePdfSearch` outside and inside the viewer and `PdfTruncationNotice`; `pdfDocumentInit`, `configurePdfJs`, `ensurePdfWorker` and `pdfWasmUrl`; the password flow (`attachPasswordHandler`, `PdfPasswordCancelledError`, the attempt cap, `createLoadTimer` pause and resume); literal and regex find (`findLiteralMatches`, `findRegexMatches`, `regexPatternError` policies, `createRegexSearcher`); zoom, canvas DPR, rotation, page limit, thumbnail window and `withTimeout`; the link service and `isSafeExternalUrl`; `pdfTextContentSource` and `highlightSpan` on a minimal fake DOM; `acquirePdfRenderKeepalive` on a fake window.

What it proves: the viewer's initial markup is exactly what the package documents for each option, find matches are correct for case, whole words, whitespace runs, hyphenation and final-sigma folding, a refused regex matches nothing, only `http(s)` and `mailto` links ever reach the host's `openExternal` and the document-supplied URL never becomes an `href`, the password flow ends the load when declined or exhausted and pauses the load clock while the user is asked, and the render keepalive wraps the animation-frame functions only while held.

What it does not prove: pdf.js reading or drawing a real PDF. That needs the pdf.js worker, a canvas and a DOM, so document loading, page rendering, text layers (`renderPdfTextLayer`), outline and thumbnail extraction, in-viewer find, zoom and rotation behaviour, and worker and wasm hosting stay with the package's own tests and its browser end-to-end test. Viewer effects do not run in server rendering. The Worker-backed regex deadline is not run, because plain Node has no `Worker`, so the synchronous strict policy is the path under test. Loading `pdfjs-dist` in plain Node writes its legacy-build notice to stderr; stdout stays a single JSON line. The stylesheet is checked as text only.

Required environment: `RIGHTKIT_CONSUMER_ARTIFACT`, `RIGHTKIT_CONSUMER_ARTIFACT_SHA256`, `RIGHTKIT_CONSUMER_EXPECTED_VERSION` and `RIGHTKIT_CONSUMER_RESOLUTION` (`packed` or `fetched`). The runner provides them. `provenance.mjs` is the shared byte-identical helper that binds every installed file to the supplied archive.

No network, no credentials, no user data; the PDF URLs use the reserved `.invalid` TLD and are never fetched. Output is one JSON line; exit 0 only when all ten scenarios pass. `nativeHostQualified` is always false.
