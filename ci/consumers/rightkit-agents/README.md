# rightkit-agents 0.2.0 registry consumer

Standalone consumer, outside the workspace, pinning `rightkit-agents =0.2.0` exactly with default features off and the features `claude` and `codex`, the set CodeRight's driver host uses. It installs the crate from the sealed archive through the offline directory registry and runs `src/main.rs`, which exits non-zero on the first failed assertion. No vendor CLI is installed or run; the vendor side is replayed from inline transcripts, and one test copies this program under the names `claude` and `codex` to act as a stand-in CLI.

## What it proves

- The event model. `AgentEvent` serialises with a snake_case `type` tag and round-trips, `ControlOutcome` serialises with its `outcome` tag, `UnknownPolicy` defaults to lenient, `ParseError::unknown_required` and `unknown_required_method`, and `RateLimitState`: observed data replaces the earlier state, a failed probe keeps the last snapshot, and `mark_unsupported` never hides data.
- Claude Code argv. `build_args` and `build_args_with` produce the exact argument list (config mode, model, resume, tools, budget, system prompt, host approvals, settings), refuse `bypassPermissions`, an invalid mode, a malformed id or model (the message names the field, never the value), a resume option without a resume id, a fallback model equal to the model and a tool name with a comma. `PERMISSION_MODES`, `check_permission_mode` and `enable_permission_prompt` (idempotent).
- Claude Code frames. The user-turn, interrupt, permission allow and deny, `initialize`, `set_model` and `set_permission_mode` frames are single newline-terminated JSON lines of the documented shape, and `next_request_id` gives distinct `rk-<kind>-<n>` ids.
- Claude Code parsing. `StreamParser` over an inline transcript yields the exact events for init (with the full `SessionInit`), partial-message block starts and text deltas, thinking, text, tool use, a subagent that starts and finishes, tool results with their joined text, usage, compaction, rate limits, control requests and responses, a result with a permission denial and a budget failure; unknown kinds become `Unknown`, hook telemetry produces nothing, malformed JSON and a missing type are errors. Under `UnknownPolicy::FailClosed` an unknown top-level kind, a system subtype named for execution truth and a system payload carrying a required key are refused with the kind named, while telemetry and a harmless unknown subtype pass. `parse_control_response`, `parse_initialize_response`, `parse_interrupt_receipt` (only with the advertised capability), `parse_can_use_tool`, `parse_rate_limit` and `parse_result_summary`.
- Host permission answers. `PermissionDecision::from_answer` and `frame`, and `answer_can_use_tool` fails closed with `NO_ANSWER_MESSAGE` for no receiver, a timeout (a late send then fails) and a disconnect, and passes an allow or a deny through.
- Codex app-server parsing. `parse_line` classifies responses, server requests and notifications; approval requests carry their event; thread, message, command, reasoning, subagent, token-usage, compaction, server-request-resolved and turn notifications map to the expected events; bookkeeping notifications produce nothing; `turn/failed` is always a terminal failure and a usage limit adds a rejected rate limit; unknown notifications become `Unknown`. `parse_line_with` under `FailClosed` refuses unknown notifications in the `turn/`, `item/` and `serverRequest/` families and `error`, and passes others. `is_required_notification`, `PINNED_CODEX_VERSION`, `APPROVAL_REQUESTS` and `KNOWN_NOTIFICATIONS`.
- Codex frames and client. `approval_response_frame` for every `Decision`, `error_response_frame`, `build_args`, `thread_params` (the `on-request` default, options, extra params merged over, resume id) and `launch_env`. `CodexClient` drives `initialize`, `thread_start`, `turn_start`, `turn_interrupt`, `thread_resume` and `respond_approval` over in-memory streams, buffers other lines in order (`drain_pending`, `next_incoming`), counts request ids up, and reports an RPC error, a closed stream and a refused line (`ClientError`).
- Vendor discovery against the stand-in CLI. `find_binaries` and `find_binary` search `PATH` (on Unix, skipping a file without the executable bit), `probe` reads the version and, for Claude only, the sign-in, `detect` caches its snapshot while a fresh `probe` sees a new `PATH`, `RIGHTKIT_DISABLE_VENDOR_CLIS` turns every probe off (`0` and the empty value do not), `claude_auth_status` reads only the official boolean, and `run_bounded` caps output at `PROBE_OUTPUT_CAP` with both streams kept, gives up at its deadline on a hanging child, and returns `None` for a program that cannot start.

## What it deliberately does not prove

- The `session` feature (`Session::spawn`, approvals, cancel and whole-tree teardown). It needs a running vendor CLI, and no app enables it yet.
- A real Claude Code or Codex process, a signed-in account, or rate limits as a vendor really reports them. Inline transcripts follow the shapes of the crate's recorded fixtures with neutral names.
- `list_models`, which names vendor model aliases, and the drift test against the Codex schema snapshot in the source repository.

State: a per-process directory under the OS temp directory, removed at the end, and one short-lived copy of this program per probe. No network, no credentials, no real user data. The longest wait is a 400 ms deadline on the hanging stand-in.
